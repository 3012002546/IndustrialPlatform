# PF05 起派遣前详细设计与页面验收规则

版本 V1.0；2026-09-07。适用于 PF-05 及全部后续 PF/MES 新开发或实质重构；不重开历史已验收任务。本规则补充实施模板和 PF 工作包模板，执行权责以仓库 AGENTS.md 与用户当前授权为准。

## 1. 先细化，再派遣

详细规格属于总控的派遣输入，不得把“决定表字段、冻结接口、决定页面布局”留给编码任务。规格按业务场景纵向连接：需求 → 数据与状态 → API/事件 → 线框图与交互 → 内部任务 → 验收。每条需求有稳定编号，任务只引用精确章节，不再复制四份字段表。

分开记录两个维度：

| 维度 | 取值与含义 |
| --- | --- |
| 设计就绪度 | 待细化 / 待前置核验 / 已就绪；有阻塞的项目必须写缺项、责任方、补齐位置和退出条件 |
| 派遣/执行状态 | 待派遣 → 已派遣 → 开发中 → 待验收 → 已完成；实际进入谁的工作线后才能写已派遣 |

“待派遣”只表示尚未派出，不自动表示设计/依赖已通过。历史“可派遣”映射为“待派遣 + 已就绪”；历史“待细化”继续作为就绪度。正式派遣要求**本次派遣范围全部已就绪**。没有真实分派，不填写执行者ID。Todo只表达能力、契约、环境和授权前置，不登记代码分支、提交哈希或工作树版本；实际交付标识留在evidence，运行协作安排由总控维护。文档细化不等于启动实现。

如果需 PoC 才能决定引擎/硬件适配，先把 PoC 的输入、候选、测试装置、阈值、结果格式及停止条件写完整，再派遣这个明确范围。PoC 输出先由总控回写生产规格，生产部分仍不得带着待决策项启动。保留既有 PF-06 双 PoC 决策门；不把每个内部 TASK 都变成独立派遣或用户确认门。

## 3. 字段与接口编写约定

蓝图维护边界、顺序和业务含义，阶段实施方案与details维护具体字段/API/页面及任务。同一项设计调整须同步相关摘要与细化章节；发现冲突先修正，不能用“以新版为准”掩盖两套语义。Todo引用文件/章节而不固定其修订号。API/事件schemaVersion、数据修订、并发版本、迁移version/checksum、安装包/bridge兼容版本是功能契约，继续保留；它们不表示代码必须停留在某个Git状态。


- 领域 Entity 的通用生命周期集中定义一次，逐表明确“领域实体/技术记录”。当前基类 Id/ConcurrencyVersion 为 Guid，OptimisticVersion 为 long，从 0 开始；不要臆造数据库自增 Id 或初始版本 1。
- NId 是 string 稳定业务身份，API 不暴露内部 Id；TenantNId/外部用户标识来自可信上下文，不截断、不转大小写或按姓名合并。外部标识长度不够时派遣前调整契约，不能运行时截断。
- PG `snake_case`；SQLite 显式类型映射和约束验证。时间 `DateTimeOffset` / `timestamptz` / RFC3339 UTC。整数上限、decimal 精度和前端序列化要同时明确，禁止 long 被 JavaScript number 静默舍入；新增长序号 DTO 使用十进制字符串并在边界适配，不全仓库改现有契约。
- 枚举写出允许值和迁移策略；JSON 必须有 schemaVersion、字段结构、大小上限，不使用“扩展字段 json”掩盖未设计的核心字段。哈希明确算法与规范化输入，不存原始 Token。
- 同聚合普通 ParentId 外键默认 RESTRICT；没有业务依据不做级联删除、软删除复合 FK；跨模块/服务不建 FK。必要冗余 NId 由聚合写入并验证，不能形成两个可独立修改的父标识。
- 每个索引标明对应查询；不要给所有列机械建索引。唯一键是否跨软删除记录保留必须明确。API 权限之外再核验租户、成员、客户和节点范围。
- 升级采用新增可空列/兼容读取 → 受控回填 → 收紧约束；规定旧数据缺省和失败恢复。迁移、种子 id/version/checksum 需在派遣前核对现有注册格式；不给执行者“自行改已有种子重跑”。

## 4. 黄金页面与线框图

来源为用户指定的 `industrial-platform-management-page/SKILL.md`，以及其 `references/table-selection.md`、`references/local-development-acceptance.md`。仓库内本规则保留可移植的执行要求；不要求其他机器存在 `C:/Users/DONG` 路径。

黄金代码入口：`src/frontend/src/pages/pc/identity/IdentityUsersPage.vue`；复用 `AppPage`、`AppQueryPanel`、`AppDataTable`、`AppFormDrawer` 与现有权限、主题、locale。yefeng 只借鉴信息结构，不能复制其视觉、权限、路由和 API。

| 页面类别 | 布局与组件 | 选择与动作 |
| --- | --- | --- |
| 普通管理列表 | 全宽查询 + 一张表，full 工具档 | 默认 none；行操作只管本行，溢出放“更多” |
| 主从配置 | 左侧紧凑目录/树/列表，右侧上下文 + 详情/Tab/子表 | 左侧 single/compact；右侧主要业务区域，新增子项紧邻子表标题 |
| 层级权限/菜单配置 | 全宽树表；预览和发布历史经入口打开 | 不常驻第三栏；行层级动作明确 |
| 三数据集 | 主从 + Tab 或三个有名称的数据集 | 不塞入三套完整工具栏和套卡片 |
| 聊天/共享/设计器 | 专用消息区/媒体舞台/画布 | 复用壳与交互语义，不把消息或画布硬套 CRUD 表格 |

所有新增页面及结构化弹层在派遣前给线框图，至少标注 PageId、路由、终端/参考视口、主数据集、选中上下文、主要按钮、加载/保存归属和窄屏变化。相同模板页面可共用图，但每条路由必须登记差异。线框图是布局基线，不等于真实视觉验收。

```text
┌ AppPage：标题 / 说明 / 数量                     页面主操作 ┐
├ AppQueryPanel：查询控件                         查询 重置 ┤
├ 左侧 A：compact、single ┬ 右侧：当前 A 名称 / 状态 / 更多 ┤
│ 快速查找 / 刷新          │ Tab：详情 / 子项 / 历史          │
│ A 列表；保持挂载与滚动    │ B 子表名称           新增子项    │
│ A 的明确选中状态          │ B 数据 / 局部加载 / 局部错误重试 │
└────────────────────────┴─────────────────────────────────┘
抽屉：标题 → 有标签的表单字段 → 错误 → 取消 / 保存（局部 busy）
```

标题/说明/数量/页面操作只出现一次；顶部查询 placeholder 已清楚表达时省略重复可见 label，但保留本地化 aria-label。多数据集保留上下文标题；表格工具与业务按钮分区。表单/详情/分配使用 AppFormDrawer，保留居中/侧滑偏好；纯确认继续用确认框。

### 4.1 选择和异步规则

稳定业务 row-key 必填。A 清空即清 B 和 B 的选择/动作，不发无父级查询；A 切换时立即显示选中状态，仅 B loading；取消或拒绝旧请求，旧 A 的结果/错误都不能覆盖新 A。分页/筛选/租户切换后默认清选；确需保留必须列出验证策略。批量操作声明混合状态限制和部分失败语义。

2026-09-07 已读当前 `AppDataTable.vue`：存在 `row-click`、`activeRowKey`/`selectedRowKey` 和 selection-change；不能继续沿用旧技能“没有整行点击”的快照。row-click/active 与 radio/checkbox 不自动等同，业务需归一到同一个选择入口并测清空/快速切换。当前 selection-change 只取 records/row，未合并 reserves；不得许诺跨页批量写入，除非先补齐共享契约和对应测试。不以页面 DOM/VXE 私有 API hack 代替公共组件能力。

保存使用同步 submit guard + AppFormDrawer.busy；遮罩不能阻止 Teleport 弹层重复点击。失败保留输入，409 提示重载/对比，不静默覆盖。未授权按钮按 PermissionGate，后端独立拒绝。

## 5. 页面可发现性与本地验收

逐页走通：命名路由 → API bootstrap → 权限目录/策略 → 版本化 navigation seed/upsert → 旧库增量应用 → 当前用户动态菜单 → 中英标题 → 实际点击进入。已有 seed ledger 不会因源代码变更重跑；不得把路由文件或菜单常量存在写成验收通过。

优先复用当前 UnifiedHost 或 Gateway 拓扑、登录与 IDE。UnifiedHost 必须组合模块、端点、初始化与 health；独立服务同时验证 Gateway 前缀与认证。检查 Shared/PerService 的真实目标，不通过新增 Docker 库“修正”Shared；不输出私有配置。

SQLite 依 `src/开发注意事项-数据库拓扑与本地配置.md` 显式使用 `IndustrialPlatform__DevelopmentInfrastructureMode=Sqlite`，不能依赖文件缺失或关闭 RemoteDevelopment 自动切库。核对 SqlSugar 连接和 SharedSqliteFile 同一目标。测试只用隔离数据库/租户，记录创建数据的精确键与清理；不清普通调试库或重启用户 VS/VS Code。

每页至少记录：实际 Host/URL、菜单路径、测试身份/权限、各区 toolbar-profile、选择/加载/保存归属、中英/明暗主题/密度、200% 缩放/窄屏/键盘、empty/loading/error/无权限/冲突、控制台与网络、截图/测试证据。HMR 后查看真实页面，恢复临时视口。登录过期/环境未运行/仅静态阅读时对应项为待验收。

当前可复用的验证入口（未来源码实现时执行，本轮文档维护不运行）：后端先`dotnet build src/backend/IndustrialPlatform.slnx --configuration Release`，成功后`dotnet test src/backend/IndustrialPlatform.slnx --configuration Release --no-build`；前端在`src/frontend`按影响运行`pnpm typecheck`、`pnpm lint`、`pnpm exec prettier --check <本次文件>`、`pnpm test:unit <定向spec>`及`pnpm build`，实际E2E用项目现有`pnpm test:e2e <场景>`并指向隔离数据环境。具体spec由任务验收矩阵定位，不机械对每张内部卡跑全套；读取退出码/失败/跳过数量，真实页面检查不能由这些命令替代。

## 6. 协作与变更控制

总控维护设计/字段/线框图/任务/门禁；执行者只消费已冻结输入、连续实现、自测、修复、回写 evidence；现有独立验收从稳定交付复核，不与开发同时改文件。具体角色及模型沿当前任务配置，不因本文改变现有任务设置。复用原工作线，默认独立长期 worktree；PF-02 主工作区例外保持。

派遣一个PF当前批准范围的精简包，包含前置条件、文档精确章节、内部序列、允许和禁止范围、共享文件写入顺序、验收与交付。实现前核对当前公开契约是否满足前置；不以“已到某提交/分支版本”代替契约核验。内部步骤连续执行，不逐卡派遣/提交或建立额外审批层。设计变更需总控先回写受影响规格及验收映射，再通知执行者；安全的局部实现细节自行处理，结构/权限/数据权威不能临场更改。

降低返工的额外要求：提供一组成功样例和一组失败样例；优先交付一条端到端业务链；对超时区分失败与结果未知；为迁移、身份切换、重复点击、乱序事件和恢复演练单独列案例；共享组件能力缺口先修共享契约再写业务页。未验证的硬件、第三方接口与客户协议登记为显式门禁，不能用 Mock 消除。
