# 13A-Industrial Platform知识中心开发实施方案

版本：V0.12 · 开发前合同复核 · 2026-11-18。

阶段：PF-10A，设计与开发优先于PF-10；保留原编号。设计就绪度：待细化；派遣状态：未派遣。本稿已有范围、状态、契约草案和页面线框，不是可直接建表/编码的完整派遣规格。

Service Host：由PF-10A先创建`KnowledgeHub.Service`，PF-10后续扩展ServerMonitor。内部模块：KnowledgeBase、IssueTracking、KnowledgeAssistant、DataAssistant、ProjectWorkspace、ModelGateway；会话与工具执行属于助手应用能力，不增加核心Host。

## 1. 已确认方向与本稿设计取舍

### 1.1 用户已确认

- 内部实施、运维知识和问题处理优先；PF-10A开发优先级高于监控。
- 首期先接DeepSeek官方API，暂不使用本地模型。
- 助手支持知识问答、页面导航、连续上下文、MCP/HTTP读取和少量明确写动作，例如创建问题草稿。
- 项目级知识以“收资料 → 查得到、问得到”为主线，查看与维护沿用平台权限。经验整理、资料包导出和跨项目合并属于首期辅助功能。
- 全局助手按业务对象和行为扩展。后端鉴权，实际执行方提供完成凭据。前端动作由发起请求的标签页领取，SignalR 可加速提醒。
- PF-10A 与 PlatformStudio 的交付原则一致，平台原生优先，同时支持独立部署。具体装配和验收见 §3.1。
- ServerOpsCenter继续独立维护，平台监控仅作参考；平台现场部署不依赖VPN。PF-10A不等待监控、Agent或旧系统API。

### 1.2 主控据此采用的设计草案

采用“项目内知识与问题管理＋全局助手”，沿用.NET10/Vue/SqlSugar及平台公共能力。首期一套部署提供当前项目知识范围；保留可信TenantNId和ProjectNId，不要求用户先维护客户/工厂/项目层层目录。不新建跨项目知识授权、分享审批、ACL设计器或多级审核引擎。

资料上传成功且 File 确认可读后自动入库并建立索引。项目内使用查看、维护两项权限。维护人员可暂存手写稿或直接收录，版本未注明也可入库。下文 Published 与发布指针为内部有效修订标识。

比较后保留的路线：

| 路线 | 取舍 |
| --- | --- |
| 项目内知识/问题＋有限工具调用 | 本稿采用：符合项目级MES和内部实施优先场景，复用现有权限与业务能力 |
| 多项目共享知识与逐篇ACL/多级审批 | 当前无必要，不纳入首期，避免增加发布与维护成本 |
| 通用Agent/工作流编排平台 | 超出已确认目标，首期用有限调用及执行记录满足连续操作 |

## 2. 用户路径与范围

| 编号 | 首期路径 | 用户可见结果 |
| --- | --- | --- |
| KH-01 | 选取资料上传→自动入库→解析索引 | 原件可按文件名查找，各项入库结果与索引进度分别显示 |
| KH-02 | 查某版本的故障→打开引用→查看原文 | 答案有当前可读修订与适用版本，资料不足时明确说明 |
| KH-03 | 登记问题→分派/处理→补充→验证→关闭 | 处理人、当前状态和历史清楚，“我负责/待我验证”可直接进入 |

| KH-06 | 调用已登记MCP/HTTP读取→继续追问→查看结果/导出 | 参数及来源可查看，失败/超时与已完成明确区分 |

| KH-07 | 修订/停用知识→再次提问/恢复会话 | 不继续把失效修订当作当前依据，不重放历史操作 |

保留JSON、二维码/条形码、人工HTTP调试辅助工具；其码制、预算、目标限制在派遣前细化，优先验收 KH-01/02 的入库、查找与带引用问答。真实生产统计需要生产源及指标定义，当前未提供，不用模拟数据宣称接通生产。MCP读取不要求ServerOpsCenter提供服务。

首期不包含OCR、Office协同编辑、跨项目共享治理、长期个性化记忆、自由SQL、MES提交/审批、远程Shell、自动修复服务器或助手自行决定收录知识。

### 3.1 平台原生优先，同一核心支持独立部署

原生模式哪些组件直接消费、哪些需要开发适配，以及独立实例的最小物料和逐项验收，见双模式装配与助手行为接入。

PF-10A 首期交付平台原生、独立安装两种装配。先在 Industrial Platform 打通知识与助手主线，再在无主平台运行的环境冷安装验收。两种装配共用 KnowledgeHub 应用服务、数据模型、权限语义、行为注册和资料包格式。部署时选择身份与公共能力适配器，前端入口提供对应外壳。设计依据见PlatformStudio 双模式合同。

| 边界 | 平台原生（优先） | 独立安装 |
| --- | --- | --- |
| 入口与身份 | 由平台菜单、会话、角色权限和当前项目进入 | 独立 Web 入口、登录及默认项目。无 MES 时采用最小本地身份装配，提供管理员初始化和受限用户验证。接已有 MES 时显式配置受信身份、租户与角色映射 |
| 持久化与任务 | 复用平台 File、Audit 和作业公开契约 | 安装清单包含 KnowledgeHub 宿主、静态前端、业务数据库、文件存储、审计和导入/索引/导出任务执行器。优先复用 RuntimeSupport 的中立实现，在本地持久化任务、意图与审计。安装器负责初始化、升级及存储路径配置 |
| 独立可用的主线 | 上传、原文检索、带引用问答、问题处理与资料包导出合并 | 同一套流程。独立实例之间可以传递资料包。问答使用本实例服务端配置的 DeepSeek API；无法出站时仍能上传、搜索和阅读原文 |
| 助手入口与行为 | 平台外壳按平台权限、平台业务数据和平台菜单装配并执行动作 | 独立外壳负责本应用页面；存量 MES 项目按 §9.2.1 重定义业务行为并由目标服务或 MES 页面执行。MES 用户导出须绑定该项目授权的目录及导出接口；无业务源时仍可使用知识检索及问题草稿 |
| 通知与运维 | 可复用平台站内消息和实时刷新 | 问题待办按本地状态计算，执行状态可主动领取。外部通知和实时提醒按安装配置启用。独立安装时初始化、登录、文件读取、任务运行均在本部署完成 |

独立安装允许只启动 KnowledgeHub 及其自带依赖，运行时无需连接 Industrial Platform 的网关、Identity、SystemData、ReferenceData、PlatformStudio 或 ServerMonitor。最小登录、文件、审计和作业的组件选择属于工程装配设计。真实 MES 的 SSO、外部菜单与数据接入按目标系统分别验证，独立安装本身可以先验收。DeepSeek 作为外部模型服务，连通性与独立部署分别记录。

**验收顺序。** ① 平台内沿实际菜单、登录和权限跑通上传、查原文、问答与页面动作。② 在空环境禁用主平台地址，只凭独立发行清单初始化，用本地用户完成资料和问题主线、带引用问答及本标签页导航，验证重启后原件、索引任务和审计可恢复。③ 在原生和独立实例间双向导入资料包，核对附件、版本和冲突处理。现场 MES 身份或工单数据源缺席时单列待测。

服务初始化沿平台Inspect/Plan/Apply/Verify与服务自有账本；设计统一使用小写 `knowledgehub` 作为模块、初始化与受信生产者的 ServiceKey，InitializationUnitKey 同名，一个持久化生命周期，不按六个模块拆六套初始化设施。Shared/PerService及PG/SQLite/SQL Server沿平台兼容要求；各入口注册一致性、DDL映射、种子和迁移在D02/D06补齐，不执行EnsureCreated或把SQL交给SystemData。

## 4. 架构与数据所有权

```text
平台知识中心页面 / 全局助手面板
  → 可信身份 + 平台权限 + 当前项目范围
  → KnowledgeBase（正文、修订、发布、索引任务）
  → IssueTracking（问题、处理记录、知识来源关联）
  → Assistant（会话、任务条件、工具执行、结果引用）
      → ModelGateway → DeepSeek API
      → 授权检索 / Dataset公开端口
      → 已登记MCP/HTTP操作
      → 前端页面动作 → 实际执行回执
```

同宿主模块调用公开应用契约，不跨Repository/表查询，不为每次内部调用增加HTTP。File仅保存公开文件标识与所属业务关联。知识正文/发布指针是权威数据；全文/向量索引可重建。助手不复制知识主档，页面上下文不是授权依据。

## 5. 范围与权限

ProjectWorkspace首期只保存项目名称、适用系统版本、必要配置及数据源引用；单项目安装初始化默认项目。用户不必先创建项目才能使用；多项目接口预留不等于首期交付跨项目工作台。

拟定权限键由现有平台角色配置：`knowledgehub.knowledge.read/manage`、`knowledgehub.issue.read/create/manage`、`knowledgehub.assistant.use`、`knowledgehub.settings.manage`；具体键须在权限目录核验后冻结。首期不另建知识角色管理器、不逐篇维护ACL。服务端每次检查可信租户/项目和权限，配置管理不自动拥有资料阅读权。

`issue.create`允许创建/编辑/删除/提交本人草稿，并保留提交后本人创建问题的读取权，不授予分派或修改他人问题的权限；助手创建也要求该权限。当前可读问题的提交人可补充本人问题，被指定补充人/验证人可执行对应动作，服务端同时检查状态和对象关系。受理、分派、编辑他人问题、取消已提交问题、代验及重开归`issue.manage`；代验须写原因。`assistant.use`不能替代业务权限。

普通阅读与助手仅看已发布有效修订；维护人员在管理页可看草稿/历史。问题草稿默认仅创建人及具有项目问题管理权限的人可见，提交后本人凭create仍可读取，项目内其他人按问题read/manage权限可见；助手列举/查询也遵守该规则。维护权限撤销后，即使旧页面按钮仍显示也拒绝服务端发布。

## 6. 知识生命周期

### 6.1 文档与修订分别管理

文档稳定标识不随修订变化；`CurrentPublishedRevisionNId`指向唯一有效发布修订。已发布修订不可改写，修改产生新草稿；首期每份文档只保留一个活动草稿，冲突以并发版本阻止覆盖。

适用系统版本与内容修订分别管理：一份文档对应一种适用范围，修订用于该范围内纠错更新。需要旧系统与新系统方案同时可检索时，建立两份文档并分别标明适用版本，不以新修订覆盖仍需使用的旧版本方案，不新增发布分支。用户指定版本时匹配已登记适用版本或明确通用内容；版本不明且候选冲突时澄清，不猜测兼容。修改适用范围时提示保留仍有效旧范围的独立文档。

| 动作 | 前置 | 结果 |
| --- | --- | --- |
| 新建/编辑草稿 | 有维护权限，版本匹配 | 草稿保存，未公开、不供助手检索 |
| 手写知识收录 / 上传自动生效 | 有维护权限；标题/正文或可读附件有效；版本匹配 | 修订冻结、切换发布指针、写审计及索引任务 |
| 发布新修订 | 新草稿有效 | 旧修订保留历史，新检索只接受新指针；不得默默用旧版回答 |
| 停用 | 有维护权限 | 文档不再供普通阅读/助手使用；索引清理异步，读侧立即拦截 |
| 重发 | 有维护权限，恢复当前停用的发布修订 | 恢复有效指针并触发索引；历史修订须先复制为新草稿 |
| 回滚 | 选择历史修订 | 复制为新草稿，重新发布；不改写历史修订内容 |

发布状态（Draft/Published/Disabled）与索引状态（Pending/Processing/Ready/Failed）独立。新修订发布后可人工阅读，问答待索引完成；页面显示“已入库，索引处理中/需处理”。索引任务携带修订及索引代次，旧任务晚到不能覆盖新发布指针。

### 6.2 内容与导入

上传到原件可读、解析结果覆盖范围、分块建索引与重建、原文定位、证据不足处理，以及平台内/独立安装的同题集验收，按知识主线规格执行。

| 格式 | 首期处理深度 |
| --- | --- |
| 富文本、Markdown、TXT | 保存/安全渲染/提取/按段落引用；富文本禁止活动脚本和任意远端资源加载 |
| 文本PDF | 原文件、文本提取、页码引用；扫描页无文字时报告不可提取 |
| DOCX | 段落/标题/普通表格提取；引用段落位置，不承诺Word稳定页码 |
| XLSX | 工作表/单元格范围提取，保留表头和单位；不执行宏或外部链接、不代替统计计算 |
| 图片、其他附件 | 图片预览与人工说明；ZIP/EXE仅附件，不索引；旧DOC/XLS暂按附件处理 |

批量导入逐项记录状态，失败可重试，原文件保留。哈希完全相同可提示重复；同名文件不得自动认定新修订或覆盖。用户选择跳过/新增文档/指定文档新修订。单文件大小、批次数和解析时限采用数据规格初始预算，待真实样本核验后冻结，解析器应可取消并限制资源。

## 7. 问题与知识转换

| 状态/动作 | 规则 |
| --- | --- |
| Draft → Open（提交） | 标题、描述、项目有效；AI只能创建Draft，提交由用户完成 |
| Open → InProgress（受理） | 明确处理人；分派与受理写历史 |
| InProgress ↔ WaitingForInfo | 写明需补充内容/补充记录；保存待响应人 |
| InProgress → PendingVerification | 必须填写解决方法；默认提交人验证，管理人可指定验证人 |
| PendingVerification → Closed | 验证人确认有效；项目管理权限可代验但必须记录原因 |
| PendingVerification → InProgress | 验证退回理由必填 |
| Closed → InProgress | 人工重开并记录原因，保留历史解决方案 |
| Open/InProgress/WaitingForInfo → Cancelled | 取消原因必填；取消不等于解决 |

草稿可删除，已提交问题首期只取消/归档展示，不物理删除历史。只使用固定状态机，不新增流程设计器/SLA引擎。补充记录、附件、解决方法与状态变更共同进入问题时间线。

人工“转知识草稿”映射：标题→知识标题、问题描述→现象、根因→原因、解决方法→处理步骤、适用版本→知识适用版本。附件由用户选择并重新建立File引用，草稿内部保留来源问题/处理记录标识；普通知识读者无问题权限时不显示问题详情。只有有效解决方案才能转换；转换接口按请求幂等，超时重试不重复建草稿，主动再次转换需用户明确新操作。

问题关闭与知识发布无事务依赖。模块间转换采用持久转换操作记录＋KnowledgeBase幂等创建：先创建草稿，再回填关联；失败可核对重试，不跨模块写表、不以补偿删除已成功草稿恢复状态。

## 8. 数据模型草案与并发

以下为实体职责概览；三条核心流程的字段类型、长度、默认值、索引、保留及故障一致性见数据规格。普通导入批次见数据 §2.8；配置、外部工具及资料包合并等完整字典及三Provider实际迁移仍待补齐，D02未整体闭合。

| 实体 | 一行代表什么 | 关键数据与约束 |
| --- | --- | --- |
| ProjectWorkspace | 一个部署项目范围 | NId、Name、SystemVersion；TenantNId来自可信上下文 |
| KnowledgeDocument | 一份稳定知识 | ProjectNId、OwnerUserNId、PublishedRevisionNId、DraftRevisionNId；标题/分类取修订，Status由指针与启用标记推导 |
| KnowledgeRevision | 一份内容版本 | DocumentNId、RevisionNo、正文、适用版本、发布人/时间；文档内序号唯一，发布后内容不可变 |
| KnowledgeAttachment | 修订持有的文件关联 | RevisionNId、FileReferenceNId、说明、排序；同修订文件引用唯一 |
| KnowledgeCategory/Tag | 项目内目录/标签 | 名称、父目录/排序；禁止目录环，不借目录实现隐形权限 |
| KnowledgeIndexTask | 某修订某索引代次的处理 | RevisionNId、Generation、状态、尝试次数、错误码；代次唯一 |
| Issue / IssueActivity | 一个问题/一条处理事实 | 项目、标题、描述、状态、处理人、验证人；操作人/时间、类型、理由 |
| IssueKnowledgeConversion | 一次人工转换 | IssueNId、解决方案版本、OperationKey、TargetDocumentNId、状态 |
| AssistantConversation/Message | 一段会话/一条消息 | 租户、用户、项目、消息顺序、文本、引用；不与PF05聊天表合并 |
| AssistantTaskContext | 会话中一个业务任务的当前条件 | 类型、版本、项目、筛选、对象/结果标识、明确时间范围；结构化JSON需固定schema |
| AssistantExecution/Step | 一次用户请求/一次工具执行 | CapabilityId/Version、参数指纹、状态、幂等键、结果标识；不是任意工作流定义 |
| AssistantResult | 一份可引用结果 | 来源、权限范围、查询参数、截止时间、快照位置/失效时间 |
| ToolConnection/Operation | 一个外部连接/获准操作 | 类型、服务端目标、Secret引用、参数schema、读写分类、授权范围 |
| ModelProfile | 项目的模型配置 | Provider、ModelId、Secret引用、能力/预算、启用；不存明文密钥进业务DTO |

领域实体沿平台基类：Id/ConcurrencyVersion为Guid，OptimisticVersion从0开始；API只用稳定NId，长版本序号用十进制字符串，时间UTC RFC3339。同模块聚合关系按实际约束建索引，跨模块不建FK。拟用`knowledgehub_`表前缀，按Knowledge/Issue/Assistant明确逻辑归属，具体命名待字段字典冻结。

根资源写接口同时校验optimisticVersion字符串与concurrencyVersion GUID；冲突409且保留本地编辑内容。同一OperationKey＋规范化参数指纹重放返回原结果；同键不同参数409。幂等记录保留期必须覆盖执行与结果核对窗口，具体时限在数据字典统一定义。发布指针/修订冻结/审计或可靠审计意图/索引事件在本服务事务内落定；消费按修订和代次幂等。

## 9. 助手、DeepSeek与外部工具

### 9.1 会话与上下文

全局入口在平台外壳，PC右侧面板可展开；页面切换后会话保持。首期界面只显示当前项目与任务条件，不暴露任务编排树。会话绑定当前租户/用户/项目；显式跨项目切换打开对应会话范围，不自动携带旧项目片段。多标签页分别持有pageContextId和版本，晚到响应归原消息，不强制跳转新页面。

上下文由近期消息＋历史摘要＋明确任务状态＋本轮授权片段组成。用户明确纠正覆盖旧条件；页面变化只更新页面环境，不覆盖用户已确认查询。结果保存稳定标识及排序，“第二条”必须指向该结果记录；“今天”执行时固化实际时间范围，历史恢复不重新解释。恢复只展示，不自动重放导航/查询/导出/写入。

历史回答包含资料摘录也属于受控内容；恢复时复核当前范围/来源状态，无权内容隐藏且不再传模型。权限校验不仅作用于引用链接，也覆盖摘要、结果快照和导出。

### 9.2 有限执行机制

业务模块登记可调用行为，项目绑定具体对象，公共执行器负责工具往返与结果呈现。生产工单查询、打开页面和用户导出用于验收这套机制。首期由 DeepSeek Responses API 创建模型响应，以 DeepSeek 文档列出的参数和兼容范围为准。助手后端记录动作，前端外壳领取并交给页面执行，按实际结果回执。

```text
用户请求 → 装配当前有权能力 → 模型提出能力/参数
→ 服务端schema/范围/权限校验 → 执行 → 保存真实回执
→ 必要时有限后续调用 → 展示结果与下一步入口
```

首期内建能力：知识检索/打开引用、页面查找/导航/应用筛选、问题查询、创建问题草稿、受控Dataset查询和导出。页面和Dataset调用现有公开契约；MCP/HTTP工具按操作登记，不以模型生成URL/SQL执行。

明确只读请求直接执行；用户明确要求创建问题草稿且必需参数齐备时可直接创建，返回“草稿已创建”及编辑入口。信息不足则补问缺失字段，不自行提交、分派、关闭问题或发布知识。模型/知识/工具返回文本不能授权新增动作。

拟定默认预算：每轮最多6次工具调用、总执行120秒（长导出转后台）；参数校验失败至多一次纠正，达到预算展示当前结果及未完成项。这些数值是主控初始建议，需用真实连续请求验证后冻结。外部写动作只有登记了业务成功语义、幂等与结果查询才可启用，首期默认只读。

执行状态：Queued/Running/WaitingForInput/Succeeded/Failed/Cancelled/Unknown。外部写入超时无法确认时进入Unknown并查询状态，不盲目重发；取消不表示撤销已完成的外部动作。刷新/断线后按ExecutionNId恢复，不能重新生成幂等键再执行。

### 9.2.1 宿主行为约定与项目接入

平台内的业务操作以 Industrial Platform 的数据、权限和页面为准。独立部署接入存量 MES 时，MES 项目负责定义自己的业务对象、动作和成功条件。两者共用助手的调用过程。KnowledgeHub 自有的资料、问题草稿及其页面在两种装配中继续使用同一业务实现。

| 层次 | 两种装配如何复用 |
| --- | --- |
| 助手公共机制 | 复用会话、对象澄清、工具声明生成、参数校验、授权检查时机、执行记录、幂等、结果卡和发起标签页回执。DeepSeek 只收到当前宿主已登记且调用者可用的行为。 |
| 可共用的动作语义 | “查一组记录”“打开页面”“导出文件”可以使用相同的输入和结果结构。只有字段含义、适用范围与成功条件能一一对应时才沿用同一语义版本。 |
| 平台内行为定义 | 由平台模块登记平台资源、查询口径、平台权限键、数据服务、命名路由、前端处理器及完成凭据。请求执行时在平台身份和数据范围内办理。 |
| 独立部署的 MES 项目定义 | 按项目登记 MES 的对象名称、参数口径、主体及权限映射、接口或页面处理器、支持版本和完成凭据。可映射的语义复用公共动作；同名但含义不同的行为使用项目自己的标识、参数和回执。平台路由、用户表、角色名及状态枚举均须在目标项目重新核实。 |

**接一个项目时交付什么。** 每个项目维护一份带版本的行为清单，在现有集成配置中管理。每条记录包含宿主与项目、业务名称/别名、能力及版本、输入字段和业务口径、调用者权限映射、数据或页面执行入口、结果映射与成功条件。提供方负责用目标系统校验用户及行列范围。能力缺失、权限撤销或版本不兼容时，停止提供对应动作。执行与会话结果固定来源宿主、项目和绑定版本，切换项目时重新发现能力；历史执行不得改送另一系统。同一宿主内可以复用字段映射模板，凭据、角色和路由按项目配置。

| 同一句话 | 平台内 | 独立部署接 MES 项目 |
| --- | --- | --- |
| 列出本月生产工单 | 调用平台登记的工单查询，使用平台日期口径和数据范围 | 项目登记工单接口、默认日期、工厂范围和 MES 状态映射。若该项目按计划开工日统计，结果卡明确写“按计划开工日”；口径未确定时向用户澄清。 |
| 打开未完工工单页 | 平台发起标签页解析已注册路由，应用平台筛选并回报实际加载结果 | MES 项目登记自己的 pageId、筛选字段、未完工状态集合和页面处理器。由拥有该页的 MES 前端接收并执行，再按同一 actionId 回报到达、筛选及加载。只有入口链接的项目提供手动打开，并显示可确认的实际阶段。 |
| 导出用户 | 使用平台 Identity 的目录、字段和导出权限约定 | 由 MES 指明用户目录或人员档案、授权范围、字段和导出接口。若其“人员”与平台“登录用户”含义不同，登记“导出人员档案”并在有歧义时让用户选。 |

**跨外壳页面怎样触发。** 平台内由原生外壳领取页面动作。嵌入现有 MES 时，由项目在 MES 外壳注册页面处理器；助手发起实例与目标宿主在登录会话中绑定。可用受信宿主桥传递动作与回执，例如嵌入页通过限定来源、窗口与会话的消息通道交付已登记的 pageId 和参数。现有 MES 也可在其已认证前端领取属于该实例的待办动作。SignalR 只作刷新提醒。独立窗口未建立宿主通道时仅可操作 KnowledgeHub 自己的页面，访问 MES 采用其登记的手动入口。具体传输可替换，页面权限、过期、重复动作、未保存内容和真实回执沿用公共约定。

**双模式验收。** 用相同问句分别连接平台和两个定义不同的 MES 测试项目。核对实际数据源、日期/状态口径、路由、执行者与结果；一个 MES 仅有手动入口，另一个支持筛选回执。分别验证无权限、同名异义、项目切换、撤销绑定、过期及重复回执。查询不得串源，平台权限不得替代 MES 权限，未接入的 MES 功能不得回落到平台。模拟适配的结果与真实项目联调分开记录。

### 9.3 模型与检索

DeepSeek通过后端ModelGateway调用 Responses API，查询工单、页面导航与用户导出的工具往返详见交互及协议示例。后端采用此协议接入，ModelId可配置，固定实际SDK/模型能力矩阵后验收。API key经服务端Secret引用配置，不进入浏览器、知识正文或提示词。发送内容限定为本轮已授权且必要的片段/结果，不自动上传整库。流式文本只是生成进度，不决定工具完成状态。

Embedding服务独立选择；当前无已批准供应商，不安装本地模型。检索先保留关键词能力，向量适配验证通过后合并排序；关键词入口不能被包装成向量检索已完成。候选索引中必须先按项目、当前发布指针和访问范围过滤，交给模型前再核对；引用包含DocumentNId、RevisionNId、Locator和适用版本。无足够证据时回答未找到，提供登记问题入口。

## 10. API与回执草案

拟用`/api/v1/knowledgehub`前缀，命名须在Gateway/UnifiedHost路由目录复核。下表只固定动作语义，核心DTO/校验/事件及页面映射见接口页面规格，其余管理链由D04补齐。

| 路径/动作 | 关键输入 | 成功结果/边界 |
| --- | --- | --- |
| GET /knowledge | 关键词、分类、版本、分页 | 当前可读文档与发布/索引状态；编辑视图单独授权 |
| POST /knowledge | title、content、applicability、operationKey | 新文档草稿NId/version |
| PUT /knowledge/{nid}/draft | optimisticVersion＋concurrencyVersion、内容/引用 | 草稿版本；不能改已发布修订 |
| POST /knowledge/{nid}/collect | optimisticVersion＋concurrencyVersion、revisionNId、operationKey | 发布修订、indexState；不是承诺已索引 |
| POST /knowledge/{nid}/disable | optimisticVersion＋concurrencyVersion、reason | 停用生效，索引清理另计 |
| POST /knowledge/imports | operationKey、逐项文件清单与重复处理选项，KM | 202 返回 importNId 和逐项标识；prepare/commit 后按批次查询原件、修订和索引状态，见接口 §2.2 |
| GET/POST /issues | 查询或问题草稿字段 | 按项目授权的列表/草稿 |
| POST /issues/{nid}/transitions | optimisticVersion＋concurrencyVersion、action、reason、assignee/verifier | 状态和历史版本；服务端检查迁移规则 |
| POST /issues/{nid}/knowledge-drafts | mode=Collect/Draft、解决方案版本、所选附件、operationKey | 转换状态及知识草稿标识，可重试核对 |
| POST /conversations/{nid}/messages | clientMessageId、text、pageContextId/version | messageNId、executionNId；重复提交不重复运行 |
| GET /executions/{nid} | 执行标识 | 步骤/结果状态与可用操作 |
| POST /executions/{nid}/cancel | operationKey | 接受取消请求；最终状态另行读取，已完成步骤保留 |
| POST /executions/{nid}/page-receipts | actionId、pageContextId、状态、实际参数 | 导航/条件应用/数据加载分别记录；不能作为数据权限证明 |

页面动作包含 `{actionId, executionNId, capabilityId, capabilityVersion, parameters, expectedContextVersion, requiredOutcome, pageContextId, expiresAt}`。导航参数及各阶段回执按接口规格 §4.4 校验。离开编辑页沿用原有未保存提示，目标页分别确认到达、筛选生效和查询完成。

统一错误：401未登录、403无权限、404不存在/不可见、409并发或幂等冲突、422参数/状态非法、429预算超限、503依赖未就绪；错误体携带traceId及安全错误码，不含凭据/原始SQL。检索无结果不是接口失败。

Dataset现有缓存最长60秒，不能作为会话结果存档。导出原结果必须保存已授权快照及过期时间；快照失效提示重新查询，禁止用新数冒充旧结果。快照保存期限/容量、文件权限和来源撤权规则见两份核心规格；File适配与真实预算验证仍待核验。

## 12. 验收与技术核验

| 场景 | 验收结果 |
| --- | --- |
| 入库与修订 | 上传完成且文件可读后即可打开原件；新草稿不影响旧发布；新修订发布后检索不引用旧指针；索引失败可重试 |
| 停用/撤权 | 当前页面、引用、历史回答、摘要及导出均按新权限/状态限制，模型不收到失效片段 |
| 问题闭环 | 登记→受理→补充→送验→退回→再送验→关闭→重开，权限和必填规则均有实际页面证据 |
| 问题转知识 | 同次确认只生成一份知识，Collect模式绑定成功自动生效，索引完成后可引用，Draft模式保留草稿 |
| 连续助手 | 问故障→补充版本→打开引用→创建问题草稿→打开编辑页，条件/项目/回执一致 |
| 执行恢复 | 刷新或断线只恢复记录；旧请求不覆盖新条件；写结果未知不自动重复执行 |
| 不可用依赖 | DeepSeek/Embedding/工具故障分别可见；知识和问题核心继续可用，文件不可用不绕过权限 |
| 项目级简化 | 默认项目可直接使用；维护人上传即入库，无跨项目共享/多级审批的强制配置步骤 |
| 监控缺席 | 未安装ServerMonitor、无VPN、未运行ServerOpsCenter时KH-01～07核心链仍按各自实际依赖工作 |

技术核验限定输入与输出：

- 文件/检索：依据知识主线 K01～K06冻结同一份真实脱敏样本、原句和坐标。两种部署分别核对搜索排名、可回答题答出比例、关键结论的原文支持及失效来源隔离。
- DeepSeek：模拟业务工具＋正式服务端校验验证参数纠正、多轮指代、流式与断线、限流、工具预算、创建草稿幂等；API/资料发送范围在项目配置中明确后才调用。
- MCP/HTTP：至少一个真实受控只读目标验证发现/启用/调用/错误/取消；缺目标时只记录合同测试，不宣称外部接通。
- 数据库/运行：沿PG/SQLite/SQL Server与Shared/PerService要求；无源码改动的本轮不运行构建。未来源码验证先新鲜Release后测试，生产范围和跳过项分别记录。

### 12.1 容易给错结果的现场场景

下表是两种部署共用的设计与验收约定。前四项随知识主线和首批行为验证，资料包合并随辅助功能验证，整机恢复随发行验证。

| 用户遇到的情况 | 产品如何处理 | 验收时看什么 |
| --- | --- | --- |
| 同时有《本月工单.xlsx》和工单查询。“列出本月生产工单”该取哪份？ | 用户点名附件或说“按这张表”就查该修订，结果标文件、工作表和原格。询问当前业务数据时走当前宿主登记的工单查询，结果标项目、来源、日期口径、实际查询时间。只有两种解释都合理且会改变结果时才追问。未接工单查询时明确提示，可由用户选择查看已有报表。 | 准备一条只存在于实时系统的工单。实时查询应能查到，按附件提问应回到对应单元格。断开查询后再问当前工单，旧表不能冒充实时结果。统计截止时间取来源明示值，不能用上传时间或查询时间替代。 |
| 手册已上传，但答案所在页是扫描图，或同一版本的两份手册说法冲突 | 检索能定位的原句照常展示。证据不足且有已知未解析范围时，提示“可检索内容中未找到”，给出有权查看的相关原件和未覆盖范围。对同一现场、版本的相反说法并列原句与位置，指出争议项；有明确适用条件才据此选用。 | 用一份部分可解析 PDF 和两份结论相反的手册出题。核对用户能打开未解析页、逐份复核冲突原文；命中排序和上传先后都不能替用户裁定现场做法。 |
| 可以读内部资料或导出用户清单，哪些信息会发给 DeepSeek？ | 项目在现有模型配置中声明允许发送的内容，如提问文本、知识摘录或指定工具的结果字段。每次模型请求按当前配置重建输入，覆盖首轮问题、历史摘要和工具回传。导出明细在宿主生成，模型通常只需文件就绪状态和条数；下载票据、凭据留在宿主。项目禁止模型出站时，界面说明原因，并保留直接搜索、阅读入口。 | 两种装配均在网关测试替身检查实际请求体。让用户导出含测试手机号的清单，下载内容按业务授权核对，模型只收到约定摘要。收紧配置后继续原会话，历史摘要也不得带回禁发字段；关闭出站后请求数为零。 |
| 独立 MES 只提供一个能看全厂的集成账号，操作员只可看本车间 | 优先沿用 MES 的用户身份。只能使用服务账号时，提供方须能将当前用户和项目映射为 MES 可执行的行、列范围，并在服务端约束查询、汇总、导出和文件领取。无法验证范围的项目暂不启用该项业务行为，知识检索仍可用。平台内由原业务服务按调用者授权执行。 | 用两个可见车间或字段不同的用户输入同一问句，分别核对列表、条数和下载文件。撤销其中一个用户权限后，再从历史结果卡下载也须重新鉴权。界面隐藏列不能替代服务端检查。 |
| 旧项目资料带到新项目，同名手册已在现场修改 | 合并预览分别展示资料来源、源修订和目标适用范围。来源项目用于追溯；原文注明的产线、设备或系统版本照原样保留。可直接复用的按批收录。来源限定与新现场不符的资料可保留原范围供查阅，目标适用性不明时只作为带来源的参考。用户可为目标现场另建修订。导入资料包只搬资料与附件，MES 行为绑定和连接沿用目标项目自己的配置。 | 将 A 线专用手册导入 B 项目：按手册名能找到原件，问 B 线参数时助手应指出适用范围。再导入同一包并保留一项本地修改，检查未变项跳过、冲突可选、当地修改保留，当前项目工具目录也不变。 |
| 从备份恢复后，引用能点开吗？恢复前正在执行的动作会再做一次吗？ | 平台通过宿主文件服务、独立版通过本地文件存储取得与业务库同一恢复点的原件及密钥。先核对当前修订与原件摘要，再重建缺失索引。对已发往宿主但无最终回执的动作，按原操作键查询目标状态；无法核实则显示“结果待核对”。恢复前已外发而回执和操作记录都晚于备份点的动作，需按宿主审计核对恢复窗口，再开放相关写行为。 | 在隔离环境恢复一份含 PDF 引用和未决动作的备份。核对恢复后的原件摘要、引用页及索引重建结果；模拟目标已执行但本地缺回执，核对目标侧实际执行次数仍为一次。两种部署分开记录。 |

首期联调应取得同一份脱敏工单报表及对应业务查询样例、一组含缺页文字或结论冲突的真实手册，以及两个数据范围不同的现场测试身份。模型发送范围由部署项目确定。拿不到现场接口或身份时可先测工具回执和请求体，现场权限及数据口径保留待验。

## 15. 解析组件与索引选型

两种宿主共用组件版本、解析配置和索引规则。真实样本与目标发行验证通过后锁定生产版本。

<a id="pdf"></a>

### PDF：PdfPig

首选 NuGet 包 `PdfPig`，本轮核对的正式候选为 **0.1.16**，Apache-2.0，属于拟新增依赖。用 PdfDocument 顺序枚举物理页，普通单栏用 ContentOrderTextExtractor 起步，复杂页结合单词坐标、版块分组及阅读顺序提取。为每个块保存从 1 开始的物理页号、页内块序号及可选坐标。页码作为稳定入口，文本摘录校验通过后才高亮。

用中文嵌入字体、双栏、跨页步骤、无文字页和缺字映射样本对照原页。错序会改变操作含义的块保留原页入口、标记需查看原文，排除在问答证据之外。无文字页记录 NoText，密码保护和损坏单独报告。扫描页首期只供原件阅读；切分与时间上限沿主线执行。发行时随包保存许可证与适用 NOTICE。

<a id="word"></a>

### Word：Open XML SDK 的 WordprocessingML

DOCX 使用仓库已固定的 **DocumentFormat.OpenXml 3.5.1**，MIT。只读打开 WordprocessingDocument，按正文元素实际出现顺序处理段落和表格；在段落内合并 runs、显式制表/换行，保留段落样式和标题路径。表格保留行列顺序及表头。修订显示策略取最终可见正文，纳入插入内容、跳过删除内容、批注及隐藏文字。页眉页脚、文本框或布局无法可靠解析时标记覆盖范围。定位以本修订的可见块序号和段落摘录为准。首期旧 DOC 作为附件；两种宿主均可在无 Word 的环境解析 DOCX。

<a id="excel"></a>

### Excel：同一 SDK 的 SpreadsheetML

XLSX 也用 **DocumentFormat.OpenXml 3.5.1**。按 workbook relationship 找 worksheet，逐行读取，较大 sheet 使用 OpenXmlReader。以单元格自身的 A1 引用处理空行、稀疏列和合并区域，解析共享字符串、内联字符串、布尔、数值和日期样式。保留显示值、单位、工作表名和原范围。识别日期时同时检查日期系统和样式；精度、前导零或单位显示无法可靠还原时标记并回到原格。隐藏表、隐藏行列默认排除；合并单元格按锚格取值并保留范围。公式只引用文件保存的缓存值并标注来源，缓存缺失不产生数值证据。限制解包后字节数、共享字符串数、单元格数及内存，遇超限按文件报告失败。

仓库另有 ExcelReader.NET 7.5.0，ExcelDataReader 3.9.0 出现在 Studio 测试工程。知识中心需要可靠的原格坐标、样式和公式缓存语义，首期用同一个 Open XML SDK 即可覆盖两种 Office 格式。旧 XLS 延续附件策略。测试夹具覆盖 00123、日期、百分比、含单位的表头、公式有/无缓存及同名列。

<a id="chinese"></a>

### 中文：应用层分析，SQLite FTS5 召回

首期首选 **Microsoft.Data.Sqlite 10.0.9 + SQLite FTS5**。索引是本地可重建的派生数据，原生业务数据库即使用 PG/SQL Server 也走这套检索。按可信租户和项目隔离索引空间。写入和查询共用带版本的 .NET 分析函数，先保留原文，再对检索副本做 Unicode NFKC、大小写和空白规范化。连续汉字段按 Unicode 字符切相邻双字，例如“回执超时”产生“回执 / 执超 / 超时”。独立英文词另入索引。单字检索优先元数据，正文单字使用单独的 unigram 列、结果上限及明确提示。该列只参与单字请求。标题、标签、正文的词串以空格分开交给 FTS5 unicode61；中文切词由应用负责。

首轮完整短语优先，随后按分析词交集召回；不足时按多词覆盖率补候选，结合列权重 BM25 排序，标题权重高于正文。按文档去重，同分用稳定业务标识排序。查询参数绑定，MATCH 表达式由服务端从分词结果逐项转义后构建。一字词、术语同义表达、超长重复页眉及中文数字混写纳入真实题集。质量不足时先以评测对比项目词表/同义词的增益。

<a id="codes"></a>

### 错误码、型号与版本：独立精确键

扫描原始文本里的字母数字标识及内部连字符、点、下划线；同时允许在相邻中文边界抽取，例如“回执E-204超时”。标识必须包含数字，纯数字只有字段明确表示编号时才纳入精确键。保留原式及定位，用 NFKC、ASCII 大写和登记过的横线变体形成规范键，保留分隔符、前导零和版本段。键写入 B-tree 等值索引 `(normalizedCode,chunkKey)`，原文和授权信息通过 chunkKey 关联。全角“Ｅ－２０４”与 E-204 同键，E204、E-0204、E-2040 仍各有自己的键。若项目确有两种合法写法可登记别名，并区别显示。输入中的显式系统版本同时作为适用范围条件处理。

例如“v2 的 E-204 回执超时”，先在获准范围按 E-204 等值取证，再按版本和中文词对候选排序。仅有 E-2040 时给出未找到该码的反馈。可另外展示人工可选的文字相关资料，不把近似码作为 E-204 的答案。引用仍使用原文件中实际拼写和坐标。

<a id="deploy"></a>

### 平台与独立部署：一套组件，两种装配

解析和索引实现属于 KnowledgeHub，由同一应用服务调用。两模式共用依赖锁、解析配置、分词规则和 indexProfileVersion；输入使用经过权限核验的文件流，输出采用同一块结构和定位符。平台接 File/Audit/Jobs，独立版接本地文件、审计和任务 worker。索引自身只持久化到 KnowledgeHub 私有卷。每个索引分区由一个写入者维护；平台多实例时，查询与写入路由到同一分区所有者，其他节点走内部检索接口。首期验收单节点，跨节点所有权切换与恢复需独立验证。禁止让多个节点并发写共享网络盘上的同一 SQLite 文件。

在索引库内完成本代次片段、精确键及 FTS 的事务提交，然后以业务库 CAS 核验当前修订和代次并标记 Ready。读取只接受两侧代次匹配且授权仍有效的命中。崩溃遗留的待确认代次允许重试和清理。索引丢失时保留权威资料和原件阅读，重新构建后恢复问答。升级分析器需写入新 profile 并重新验证查询样例。独立包随目标系统携带 SQLite 原生库，在临时库执行真实 CREATE VIRTUAL TABLE、写入和 MATCH 检查 FTS5。平台按宿主已加载的原生版本执行同样探测。

<a id="verify"></a>

### 冻结前的实证与退出条件

本轮直接加载当前 Studio Release 输出中的 win-x64/e_sqlite3.dll，在内存库获得 SQLite 3.53.3；创建 FTS5 unicode61 表，预切分中文后“回执 AND 超时”只命中目标行。普通 B-tree 方案使用的等值语义另以二进制排序规则核对，E-204 只匹配 E-204，不匹配 E-2040。此实验覆盖当前二进制的 FTS5 能力及两个查询语义，未运行 PF-10A 解析器、词法生成器或完整检索链。

开发时固定候选包和传递依赖，记录许可证、目标 RID、原生库及解析配置。两种装配用同一组真实文件逐项比对原始块、原文位置、精确键、预期文档排名及生成答案的依据；同时用无 Office、无模型网络环境验证解析与关键词搜索。按 K01～K06 记录 PDF 阅读顺序、Word 行锚、Excel 原格、无结果、索引恢复、撤权和延迟。样本验证通过后再锁定 PdfPig、分词权重、文件容量预算和发行组合。
