# 4. 引擎职责、业务事务与权威

## 4.1 单一执行引擎

保留Hangfire为首选待核验方向；G07-1确认三Provider存储、受控DDL、原生错过策略、重试限制、尝试历史/保留和取消接口后冻结。若不满足，主控重新定型一个成熟引擎；不预写自制调度器备选实现，不同时维护两套执行机制。

| 所选引擎权威 | 业务层必要职责 |
| --- | --- |
| Cron/时区、下一次时间、周期投递 | 租户任务配置及显式启停，保存与引擎同步状态可见 |
| 持久队列、工作器、重试计时/尝试历史 | Run业务快照、人工请求防重、动作权限及实际Audit |
| 工作器心跳/失联事实、原生执行状态 | 同租户Job最小数据库占用；结果未知保留占用；处理器自身副作用幂等 |

引擎Dashboard不替代平台菜单/权限；底层ID只作诊断关联。原生周期与重试能力分别见[周期任务](https://docs.hangfire.io/en/latest/background-methods/performing-recurrent-tasks.html)、[重试配置](https://docs.hangfire.io/en/latest/background-processing/dealing-with-exceptions.html)；SQL Server需[关闭自动DDL](https://docs.hangfire.io/en/latest/configuration/using-sql-server.html)并纳入受控迁移。资料说明候选能力，不是已选包验证。

## 4.2 最小业务保护

自有表只有Job与Run，完整物理合同见明细§2。Run的过滤唯一活动槽保证同租户Job只有一个获得业务执行资格的运行；ExecutionToken拒绝旧回包，未知结果不自动清槽。不给它租约期限、fence计数或第二套工作器。该保护仍不能保证外部副作用只发生一次，处理器必须通过自己的事务/OperationKey实现安全性；非幂等处理器未知后不自动接管。

## 4.3 原子接受与状态映射

配置实际变更与既有Audit/可靠同步同事务，计划配置用稳定键同步至引擎；旧版本消息不能覆盖最新配置。人工Run/Audit/可靠投递同事务提交，引擎重复投递仍用原RunNId；周期Run按引擎调用ID唯一创建。真正执行前CAS占用及快照，结果按当前执行token提交；引擎状态适配映射尝试/重试，必要的业务投影幂等修复，不另建调度循环。详细事务、重放顺序、Unknown/取消条件见明细§3。

# 6. 全局技术约束

时间DateTimeOffset/RFC3339 UTC；三Provider物理类型、Entity完整基组、中文字段语义见明细§1～2。long DTO用十进制string。管理员配置双版本，Run动作stateVersion；租户与操作者来自可信上下文，不从业务参数传入。

参数最大16KiB、脱敏结果4KiB。Run历史初90天，活跃/Unknown不清；引擎历史与Run保留/审计保全对齐。来源凭据、端点地址留部署唯一配置，页面只显示允许字段。健康只保留每项最新内存快照，重启Unknown，过期不能继续Healthy。

# 7. 组件与状态

Job是配置实体；Run是无软删的技术/业务执行投影。状态枚举及转移见明细§1.3/3.3；AttemptsUsed仅记实际调用次数，不驱动第二套重试调度。一个Cron内嵌Job，无独立Trigger配置生命周期。健康状态依来源与时间计算，无Probe/Observation/Incident实体。

Job.Disabled影响未来触发，执行取消是独立动作；删除前无非终态运行，恢复Disabled。Unknown须核对旧进程/业务结果才释放占用，无强制解锁或直接重试。
