## 2. 定位与边界

拥有宿主能力、设备桥接、生命周期和安装/更新；不拥有消息服务、标签业务、称量判定或 MDM。保留 Vue3，不改用 React Native 重写 UI。首版不做 PC 单独 Web 热更新、多厂商 SDK 全覆盖、永久后台 BLE、静默 APK 安装、完整离线业务或复杂灰度平台。

2026-09-14用户追加：当前项目接入SQL Server 2019/2022，登记为**TASK-PF06A-009 平台SQL Server兼容接入**。这是本阶段新增的后端跨模块兼容范围，具体字段/迁移/配置/验收以[SQL Server补充规格](details/PF06A-SQLServer2019-2022接入补充规格.md)为唯一明细源；原001～008编号不变。保留PostgreSQL/SQLite，当前云库不自动切换；原生客户端只经API/Hub访问平台，不直连SQL Server。

## 3. 前后端与架构

业务页面 → 共享 Runtime 接口 → Web/Electron/Capacitor adapter → 浏览器/OS/厂商 SDK。业务请求仍使用平台共享 API client、可信身份与现有服务前缀，不经 Runtime 重建另一套认证协议。更新分发只托管签名清单/包；有现成发布能力时复用，不为首版新增核心 Service Host。

原生生产包加载本地已校验Vue产物；API/Hub远端地址与本地页面Origin分开。启动先完成容器配置、版本握手和会话存储适配，再装配现有应用；所有HTTP/Hub读取同一有效配置。当前bearer/mock的`sessionStorage`持久化、embedded的HttpOnly会话恢复、`createWebHistory`路由和多处`loadRuntimeConfig`读取必须按细化规格§7分别适配；保留Web显式同源API路径解析，不将embedded会话转换为Bearer或复制Cookie到桥接存储。离线可打开壳及诊断，不自动增加离线业务写入能力。

## 5. 初始化与持久化

终端运行时本身不是数据库 Service Host，不为Runtime新增Schema、SystemData初始化单元或空账本。009将现有服务自有表/迁移/初始化映射到SQL Server，仍由各服务拥有，不建立新的数据库业务服务。客户端安装配置、版本清单、更新暂存/最后良好版本、本地脱敏日志由容器维护；凭据放受支持安全存储，不写普通配置或日志。设备执行账本归 PF-10B Agent，当前不预建长期离线消息数据库。

时间用 DateTimeOffset/UTC RFC3339，超时用单调时钟。租户与用户来自可信身份，设备标识不是认证因素。插件权限、安装权限与平台业务权限分别验证。

## 6. Runtime 契约

| 能力 | 最小契约/行为 |
| --- | --- |
| capabilities | 容器、OS、NativeVersion/WebVersion/BridgeContractVersion 与 Supported/Unsupported/PermissionRequired 状态 |
| lifecycle | start/stop/resume、前后台/休眠、主体换人清理；resume 必须恢复权威状态 |
| scanner | acquire/release 当前输入会话；ScanResultV1(contractVersion, eventNId, value, source, symbology?, receivedOn, sessionNId, subjectEpoch)，source=keyboard/broadcast/camera；按eventNId去重，连续相同条码不丢弃 |
| camera/bluetooth | 权限请求、取消、一次扫描、受权设备连接/读写/断连；不开放任意命令 |
| files/printer | 受限选择/预览/保存和批准打印能力，按实际支持说明；标签任务后续接 Agent |
| notifications/navigation | 应用/系统提醒、受权打开会话；点击后重新鉴权 |
| updater | check/download/verify/activate/status；Native/Web 兼容与忙闲状态门禁 |

完整方法、补充DTO、能力枚举和错误分类以细化规格§1/2为准；包括配置读写、设备快照、更新订阅、受控测试打印、诊断导出和取消。subjectEpoch、请求ID、扫描会话ID、更新代次及PF06协商版本各司其职。超时须区分明确失败与结果未知，清理不依赖远端成功。用户界面给重试/设置/稍后升级入口，不显示 JAR、IPC 等实现细节。

## 7. 页面与交互

“终端与版本”显示容器、当前版本、更新状态和可用设备；“扫码设置”只展示已支持模式与结束符；权限拒绝说明如何恢复，不能无限弹系统授权。PDA 工作页保持 48px、Mobile 44px 触控与软键盘安全区；PC 使用现有黄金页/抽屉。更新提示显示下载/校验/等待业务结束/可重启/失败恢复，用户看得懂当前是否能继续作业。

聊天列表/全屏、PC 抽屉/工作区及远程协助继续用原页面；Electron 关闭窗口、退出进程、托盘驻留分别约定；Mobile 原生未冻结范围不展示假完成入口。

细化规格§4固定PageId、命名路由、权限与字段动作映射，§8固定关闭/最小化/锁屏/杀进程的结果。远端观看仍为页内浮窗，Electron不另建媒体业务窗口。系统选源器不可用时的受控来源选择弹层仅用于授权采集，不承担观看或语音生命周期。

## 8. 安全、设备和协作

按蓝图 34 第 3/5 节实施受限 IPC、Origin/导航、插件权限、广播来源、设备互斥、换人清理和后台恢复。打印、称量与共享的 busy 由各所有者提供，不在 Runtime 猜测业务完成。系统通知不得含敏感正文；服务端已保存消息与后台通知实际可达分别验收。

## 9. 更新详细流程

受信清单维护发布通道、客户端兼容范围、产物hash/签名、下载位置和安全最低版本，精确JSON字段以细化规格§1为准。校验清单来源与产物签名，限制下载目标；离线停留最后良好版本。下载→校验→暂存→等待安全点→激活→启动健康确认；PDA Bundle按细化规格§3的60秒健康窗口回退安全的最后良好包，PC安装包/APK按系统规则恢复，必要时操作员介入，不承诺任何失败均可自动降级。Web 包不能调用当前原生没有的 bridge；插件、JAR/AAR、权限清单变化走 APK 完整升级。

PC 首版完整安装包更新；PDA 分别做 Bundle 与 APK。001先核验 electron-builder/electron-updater、Capacitor 更新插件或自托管方案的版本/许可/离线可用性并回写规格，005实施已明确路线，尚未核验不能写已采用。

细化规格§3/9约束包身份、API契约兼容、签名输入、公钥信任、原子激活、解压安全、版本防回放及安装恢复。现有更新库的元数据/自动安装/健康回退必须接入同一门禁；不能另开一条绕过签名或busy的自动更新路径。001未核验的算法、证书、插件精确版本和发布渠道保留为显式输入，不临时写成已选型。

## 10. 验收矩阵

R1：浏览器回归与三容器相同业务页；R2：Windows 安装/安全 IPC；R3：真 PDA 文本框/广播/相机/BLE；R4：PC/Bundle/APK 三种升级及损坏/中断/回退；R5：聊天、共享、换人、锁屏恢复；R6：内网交付与诊断。各任务下的具体负例均为门禁，保留软件版本、设备型号、固件、权限、日志与截图证据。
