# PlatformStudio双模式适配与按需部署合同

版本：V1.2；日期：2026-10-22。设计合同，尚未实施。本文是实施11/12的部署、适配和装配验收唯一细化源；不改变四部分业务模型、页面和已确认概念。字段类型沿[数据规格§2](PF08-PF09-数据模型与生命周期.md#2-类型通用列及约束)，业务API沿[接口规格](PF08-PF09-接口与配置合同.md)。

## 1. 已确定的交付方式

**同一Studio核心，平台内原生契合优先，平台外可以脱离我们的平台接入现有MES。** 产品为LowCode、Dashboard、Report（包含Excel）、Traceability四个模块；客户可选任意非空子集，不以PF08/PF09排期强制安装前面的产品。

| 配置模式 | 身份/授权 | 数据/字典/编号 | 自有文件/审计/后台任务 | 必须存在的服务 |
| --- | --- | --- | --- | --- |
| PlatformNative | 当前平台可信上下文及Identity公开授权 | 平台公开合同；保留注册外部来源能力 | 直接用平台File/Audit/PF07 Scheduler公开适配 | 所选能力的现有平台服务；同进程或受信API，不改其原部署拓扑 |
| ExternalMes | OIDC或MesCode接目标MES；Studio执行自己的资源授权 | 受控API/只读SQL/具名过程；字典与编号通过登记的MES接口映射 | Studio随包的Embedded运行组件；不要求MES另建文件/审计/调度系统 | Studio宿主、Studio数据库、目标MES身份/业务接口；按模块增加文件扫描、Renderer/Office |
| ExternalMes + LocalAdmin | 无MES身份时的最小独立登录装配，只用于已确认的无宿主场景 | 模拟源或已登记业务源 | 同ExternalMes | 不需要Identity/SystemData/ReferenceData；不能替代目标MES身份接入验收 |

外部模式首版不再并列让开发选择“MES调度/远端任意文件服务/另一个审计产品”：**Studio自有产物、审计和报告任务使用Embedded默认实现**；MES已有附件通过§6.3只读文件桥接，审计可按§7镜像给MES。身份适配器可选Oidc/MesCode/LocalAdmin，由安装配置明确指定，失败不自动切换。未来增加其他实现需要同一合同验证，不是本轮任意插件市场。

原生模式不通过自己搭建的MES桥绕一圈：登录、权限、菜单、主题/语言、黄金页控件、ReferenceData、File/Audit/Scheduler直接沿现有公开能力，保留平台已有配置与用户体验。

## 2. 模块选择、依赖和安装清单

### 2.1 模块依赖矩阵

| 选定模块 | 必带共用基础 | 额外运行依赖 | 不构成安装依赖 |
| --- | --- | --- | --- |
| 任一模块 | 身份/授权、DataSource/Dataset、Publishing/版本/资源授权、数据库/迁移、可靠审计、工作台及基础健康 | 所选身份端点、已注册数据源；静态合法字体/图标随包 | 不要求购买或启用LowCode设计器 |
| LowCode | 上述基础；台账、字段/动作运行 | 使用附件字段/上传资产时需要File与扫描；Rule编号需要登记编号提供者 | Dashboard、Report、Traceability、Office、Renderer、报告调度 |
| Dashboard | 上述基础；页面实例、组件、Playlist、参数/跳转 | 上传图元/图片时需要File与扫描；仅随包静态资产可不启用上传 | LowCode、Report、Traceability、Office、Renderer、报告调度 |
| Report | 上述基础；单报表、两类组合、HTML与Excel | File/扫描、报告Scheduler、Renderer及Office全部必需 | LowCode和Dashboard设计器、Traceability、MES工单执行模块 |
| Traceability | 上述基础；对象/关系/起点/运行 | Owned明细需File；Mes明细需受控文件桥及§6.3扫描策略；上传资产需File/扫描 | LowCode、Dashboard、Report、Office、Renderer、报告调度、图数据库、IoT/MES领域Host |

Report仍是一个交付模块，包含首期Excel编辑保存；不能以客户只选Report为由再删掉Excel。客户安装清单不含Report时，不随Studio安装Office/Renderer/报告worker；平台本来已有的共享服务不由Studio停止。InstalledModules含Report但EnabledModules暂不含Report时，保留其库、文件和已装依赖，排空后停止Studio的报告处理入口及专属进程，不擅停平台共享Scheduler/File。其他模块无需File的配置可运行；依赖File的控件不能发布为空实现。

### 2.2 配置字段及固定校验

部署级配置只由运维文件/受控安装输入提供，浏览器普通设计页不能改装配或秘密。`PlatformStudio.Enabled=false`仍是安全默认，安装时显式开启。新增字段如下，原预算/超时字段沿数据规格§6：

| 字段 | 类型 / 取值 / 默认 | 校验与效果 |
| --- | --- | --- |
| DeploymentMode | PlatformNative / ExternalMes；必填 | 不自动根据连接失败猜模式；与ExecutionMode进程内/远端调用不是同一个概念 |
| InstalledModules | 枚举数组，允许上述四值；必填、去重 | 安装清单中的模块；运行时只读。正常业务包至少1项，0项仅初始化/运维模式 |
| EnabledModules | 枚举数组，默认等于InstalledModules | 必须为其子集；生效需受控排空及重启，不提供热装卸插件 |
| Identity.Provider | Platform / Oidc / MesCode / LocalAdmin；必填 | PlatformNative仅Platform；ExternalMes不接受Platform，也不指向平台Identity |
| Identity.IssuerKey / TenantMappings / RoleMappings / FactoryMappings | 受控键、明确映射表 | issuerKey稳定；外部租户、角色、工厂映射见下文；禁止默认全租户管理员 |
| Identity.PolicyVersion | 十进制字符串，初始"1" | 任一授权映射改变必递增并重验会话；与部署ProfileVersion分别表达 |
| Identity.AuthorityKey / ClientCredentialRef / ContextEndpointKey | 服务器登记键/秘密引用 | OIDC配置authority/client；MesCode配置桥端点/客户端；两种MES模式都配置可信授权上下文端点；Oidc须能从已验证来源会话取得可核验contextHandle，不只查询同名用户启用状态 |
| Identity.LocalAdminEnabled | bool=false | 仅Provider=LocalAdmin可true；不与MES身份自动混用 |
| Identity.LocalAdminFactoryNIds | string[]，默认[] | 仅LocalAdmin的显式数据范围；空数组不授权任何工厂；创建资源的权限不扩大业务数据范围 |
| Files.Provider | Platform / Embedded / Disabled | 原生使用Platform或显式Disabled；外部使用Embedded或Disabled。InstalledModules含Report时不允许Disabled，停用模块仍需保全既有产物 |
| Audit.Provider | Platform / Embedded | 必需且固定：PlatformNative仅Platform，ExternalMes仅Embedded；无Disabled/Noop |
| Jobs.Provider | Platform / Embedded / Disabled | EnabledModules含Report时固定为原生Platform/外部Embedded；否则为Disabled。停用不删既有Job/Run表及历史 |
| Files.Root / ScannerEndpointKey | 绝对受控目录 / 已登记扫描端点 | 仅Embedded；目录不在wwwroot，运行账号最小读写权限；秘密不下发 |
| PublicOrigin / PathBase / AllowedFrameOrigins | HTTPS地址 / 绝对路径前缀 / origin数组 | URL来自配置白名单；不从Host头/页面参数拼接任意回跳。嵌入与独立入口使用同一业务路由 |
| Database | 独立安装入口`{Provider,ConnectionStringRef?,SqliteFile?,Schema?}` | ExternalMes按数据规格§6.3.4投影唯一拓扑；PlatformNative禁止覆盖宿主连接；秘密不下发 |
| ProfileVersion | 十进制字符串，初始"1" | 安装配置版本；升级递增，纳入诊断与证据，不是模板或数据版本 |

InstalledModules决定交付物、许可清单和依赖安装；EnabledModules决定路由、Handler、菜单和后台运行注册。校验顺序为安装清单合法→Enabled子集→模式/适配器组合→各已启用能力健康；组合不合法启动失败，不能静默退回另一适配器。依赖故障只使对应能力不可用，不把未启用模块显示为故障。

安装包`studio-deployment.json`字段固定为`{schemaVersion:1,productVersion,profileVersion,deploymentMode,installedModules,enabledModules,adapters:{identity,files,audit,jobs},requiredCapabilities:[],artifactHashes:[{path,sha256,licenseRef}],supportedTarget:{os,architecture,provider},configTemplateHash}`。不含Secret、客户SQL/连接串或生产模型；不能把这个安装清单与模板导入manifest混用。

映射形状固定：TenantMappings=`[{externalTenantId,tenantNId}]`；RoleMappings=`[{externalTenantId,externalRoleId,roleNId,permissions:string[]}]`；FactoryMappings=`[{externalTenantId,externalFactoryId,factoryNId}]`。同一issuer下外部键不可重复或一对多；roleNId也使用§4.1稳定hash生成（前缀`mes-role-`，末段为externalRoleId）。tenantNId/factoryNId为客户配置的规范键，不自动创建平台组织。身份响应只保留已映射角色/工厂，未映射租户拒绝登录；未映射角色不授权，空工厂范围不能解释为全部工厂。若MES响应permissions，则与角色映射所得权限再取交集；若省略则按已映射角色授权。Native不应用这些MES映射。

### 2.3 未安装、停用及跨模块引用

- 未安装/未启用模块的专用API不注册，返回404；公共resource API收到该kind的创建/发布/运行请求返回409 `STUDIO_MODULE_UNAVAILABLE`，不得只隐藏菜单。资源kind归属固定：Dataset为共用基础，LedgerModel/LowCodePage归LowCode，Dashboard/Playlist归Dashboard，Report/ReportBundle归Report；Workbook独立表/API同归Report，但不加入resource kind枚举，TraceModel归Traceability；source不属于产品kind。没有LowCode仍可设计数据集。
- 组件跳转必须检查目标模块及资源可用性。保存草稿可带定位诊断；发布时必需目标缺失拒绝发布。已有已发布跳转在目标停用后显示“目标未启用”，不跳404空白、不隐式安装目标。
- Report依赖子Report模板是同模块依赖；Report读取MES工单不依赖LowCode。Traceability的普通MES详情模态框不依赖Report；只有用户显式配置Studio报告入口才形成资源引用。
- 停用先进入维护排空：阻止新提交，等待已受理报告/动作和Office会话结束；PendingDispatch/Queued须受控取消，Running/CancelRequested/Unknown不能通过关模块抹掉。存在Unknown或未确认写会话时，检查命令返回409 `STUDIO_MODULE_BUSY`，保留旧配置。异常停机后按原清单恢复诊断，不能用删包清槽。
- 后续增装复用原Studio库和修订。移除不删除客户模型、文件、审计及账本；重新启用可恢复原配置。跨模式迁移不是改一个开关：须冻结写入、迁移/核对主体授权和文件引用、清空已确认活动任务，再切换，默认不自动迁移。

## 3. 工程边界与可复用运行组件

Studio的Domain/Application只依赖Studio消费方端口和既有中立BuildingBlocks，不引用Identity/SystemData/ReferenceData的Api/Infrastructure或Repository。新增`Contracts/Integration`放DTO，`Application/Integration`放消费方端口，`Infrastructure/Integration/{Platform,Mes,Embedded}`放适配器；不新增核心Service Host。

外部默认实现复用现有File/Audit/Scheduler算法，**将可独立运行部分抽到一个中立类库**：`src/backend/src/BuildingBlocks/IndustrialPlatform.RuntimeSupport/`，内部Files/Auditing/Jobs各自按需注册。它不是新的HTTP服务、不带组织/菜单/通知/聊天/主平台控制面。平台旧公开接口保留为兼容门面，调用抽出的同一实现；Studio Embedded调用相同实现，禁止复制后两边分别维护算法。只有明确列出的移出代码和适配调用可改，不做整仓重构。

| 部分 / 写入者 | 当前复用源与必须移除的耦合 | 新落点及回归 |
| --- | --- | --- |
| File / PF08-001先完成 | SystemData Application `Files/FilePorts.cs`、Infrastructure `Files/`、OperationalStore中文件方法与实体；新增owned-reference端口。不调用聊天标识、控制面租户/目录或整套AddSystemDataModule | RuntimeSupport/Files；平台门面保留。同一上传、扫描、引用、保全测试分别经Platform/Embedded运行；PF09-009只消费不并写 |
| Audit / PF08-001 | `Auditing/AuditPorts.cs`、本地审计、失败spool/事实与生命周期；不带Notification或RabbitMQ发布必需项 | RuntimeSupport/Auditing；Embedded投递到本地持久事实，外部镜像可选，平台原投递链保持 |
| Scheduler / PF09-009 | `SchedulerPorts.cs`、Job/Run领域/仓储、HangfireSchedulerEngine/任务执行及Unknown判定；当前SchedulerRuntime依赖IControlPlaneTenantSource并创建systemdata.reconcile，必须拆出平台专属引导 | RuntimeSupport/Jobs只接显式TenantSource/Handler白名单；平台门面负责原对账种子和ReconciliationMode，Embedded只注册studio.report.render，不载入SystemData控制面 |
| LocalAdmin安全 / PF08-001 | §4.3列出的密码策略/哈希接口实现/锁定策略，不带Identity注册、用户/组织/SSO服务 | RuntimeSupport/Security的最小共用代码；旧Identity门面与hash兼容性回归，Studio使用自己的三技术表 |

新库迁移清单与旧平台迁移分开：旧已应用SQL/checksum/ID保留，抽实现不能修改旧DDL输出；对旧库做账本升级/二次启动回归。Embedded由Studio初始化器调用共享组件的独立迁移集合，不能调用整套SystemData初始化器，也不能复制其已应用账本冒充完成。

### 3.1 Embedded持久表与安装边界

Studio原13张表和3张身份表使用同一稳定结构版本；`studio-core`是迁移单元键，不是数据库schema名。精确schema/表/账本分配以[数据规格§6.3](PF08-PF09-数据模型与生命周期.md#63-单库下的schema表和账本分配)为准：PG沿实际业务schema（ExternalMes新安装默认platform_studio），SQL Server业务表dbo，SQLite主文件main。Embedded核心/File/Audit/Jobs业务表可在同一业务库，Hangfire在PG/SQL Server另用scheduler_hangfire schema、SQLite另用派生.scheduler.db文件。未选功能的核心空表不算启用，迁移不能按组合重写。Embedded不得接管正在使用的SystemData物理目标。

| 初始化集合 | 表/字段依据 | 注册条件 |
| --- | --- | --- |
| Studio核心 | 原STU-001～005的13表；新增STU-006-ExternalIdentity的§4.4三技术表（原生也允许空表） | 一次受控schema升级按顺序执行，避免新增模块补插旧ID；不开未选模块种子/任务 |

## 4. 身份、会话与权限适配

### 4.1 统一可信上下文

`StudioPrincipalV1={tenantNId,subjectNId,issuerKey,externalSubjectId?,externalTenantId?,displayName,roles:string[],permissions:string[],factoryNIds:string[],authVersion:string,policyVersion:string,issuedOn,expiresOn}`。日期UTC；permissions只取已注册Studio码（含`deployment.inspect`、`audit.view/export`、`report.reconcile`）及RegisteredAction明确登记的业务permissionKey，未知码拒绝/诊断，不解释通配管理员。所有tenant/subject/factory均来自服务端验证，查询参数不能覆盖。

消费方端口`IStudioIdentity.GetCurrentAsync(ct)`、`RefreshAsync(principal,ct)`和`IStudioAuthorization.CheckAsync(principal,{permission,resourceNId?,factoryNId?,operation},ct)`。有效权限为可信功能权限∩本地resource grant∩数据策略∩已启用模块；拒绝优先。后台代表原发起人重新求值，不以worker服务身份扩大数据权限。

原生直接映射Identity当前用户、角色/AuthVersion及可信租户，不重复登录或产生外部Studio会话。外部主体NId固定为`mes-`+base64url(SHA256(issuerKey+NUL+externalTenantId+NUL+externalSubjectId))，租户NId由显式TenantMappings确定；不以显示名/email匹配账号。角色先经RoleMappings映射Studio权限；资源grant可指该稳定User或带issuer/tenant命名空间的Role。映射改动递增policyVersion，旧会话下一次授权更新，不复制MES人员密码/全量组织表。

hash输入为上述顺序的UTF-8原值，以单个零字节分隔；拒绝输入NUL，不改大小写或裁剪后碰撞；base64url不带padding。接口层的User/Role、工作簿owner和审计actor使用此规范NId，绝不混用外部显示名。新用户没有资源grant时只能访问明确授予对应角色的资源；功能角色不自动授予所有资源。

### 4.2 外部认证路线与HTTP

默认有OIDC时使用ASP.NET Core现成OIDC机密客户端的授权码+PKCE流程，服务器保管secret/token、验证state/nonce/issuer/audience/签名/有效期；authority只在内网白名单，浏览器不保存bearer token。依据[Microsoft OIDC配置](https://learn.microsoft.com/en-us/aspnet/core/security/authentication/configure-oidc-web-authentication)。无OIDC的既有MES实现下面有限的MesCode桥，不开放任意签名算法/自定义脚本认证。

| 入口 | 请求→响应 / 行为 |
| --- | --- |
| GET /api/v1/studio/auth/login | `returnPath`只能Studio允许的相对路径；创建随机state、nonce/verifier及5分钟auth_request，跳登记MES登录页。Oidc交给标准中间件；MesCode带state、clientId、redirectUri、codeChallenge(S256) |
| GET /api/v1/studio/auth/callback | code/state；仅对应Created、未过期请求可CAS为Exchanging，服务端一次交换；失败要求重新登录，不自动重复消费不确定code |
| POST MES /studio-bridge/v1/auth/exchange | 双向TLS服务认证；`{clientId,code,redirectUri,codeVerifier}`→`{issuer,subjectId,tenantId,contextHandle,authVersion,expiresOn}`。MES必须把code绑定原客户端、redirectUri与challenge，60秒有效且原子消费；code/handle不入日志 |
| POST MES /studio-bridge/v1/auth/context | 双向TLS；`{contextHandle,requiredPermission?,resourceNId?,operation}`→`{active,subjectId,tenantId,roles,permissions?,factoryIds,authVersion,expiresOn,contextHandle?}`；Oidc标准回调后首次通过该桥传`{issuer,validatedSubjectId,validatedTenantId,issuerSessionId,authTime}`，active=true时响应必须含绑定来源会话的contextHandle，随后统一用handle；这些值只来自已验证令牌。MES桥须核验该来源会话仍有效，无来源会话/注销语义支持的提供者不能标此合同通过，改用MesCode。无MES会话或停用用户返回active=false |
| POST /api/v1/studio/auth/logout | CSRF保护，撤销当前Studio session并清cookie；按已配置支持的MES退出入口协同退出，不能因MES退出失败恢复本地会话 |
| GET /api/v1/studio/auth/me | 返回规范主体、允许模块/权限和有效期，不含code/token/contextHandle。跨租户切换重新认证并清页面缓存/草稿授权上下文 |

MES桥路径是交付给目标MES适配工程的标准合同，可由部署中的已登记路径映射，不要求客户修改现有业务API命名；请求/响应语义不可省略。客户端身份绑定允许issuer/租户，MES不能接受任意服务客户端查询全员上下文。首次MES接入至少提供exchange（MesCode时）、context及一条业务查询样本；生产连接由用户配置。

MesCode也必须绑定发起登录的浏览器：生成随机nonce放入仅该回调路径的受保护相关性cookie（Secure/HttpOnly、SameSite=Lax、5分钟），request表保存nonce_hash；回调先比对cookie、state、时效，再CAS消费，完成/失败均清cookie，不能仅凭数据库中存在state就创建会话。Oidc使用中间件相关性保护。会话句柄、verifier及contextHandle加密沿ASP.NET Data Protection，密钥持久保存并按运行身份保护，进入备份恢复清单；重启不得丢key导致全量不可解密，也不能将明文key随开源包分发。

外部cookie只存256bit随机session句柄，Secure/HttpOnly，默认SameSite=Lax，CSRF token用于所有写接口；绝对有效期不超过8小时、空闲30分钟，且不超过MES给定expiresOn。跨站iframe受浏览器cookie限制时使用MES同源反向代理或顶层Studio入口，不能关闭认证解决嵌入问题。允许跨站的部署显式配置SameSite=None+Secure并完成真实验证；不承诺任意浏览器第三方cookie可用。

写操作、发布、导出、文件下载、后台执行和任务核对每次刷新MES上下文；普通只读可缓存最多30秒且不得超过expiresOn。context超时5秒或过期不使用旧授权放行，返回503 `STUDIO_IDENTITY_UNAVAILABLE`；active=false返回401并撤销会话，权限不足403。报告执行与保存产物前均重验；刷新失败进入明确失败/待核对，不伪装已完成。

后台和Office回调没有浏览器cookie，必须保留受理时的身份依据：`IdentityEvidenceV1={provider,tenantNId,subjectNId,issuerKey,authSessionId?,authVersion,policyVersion,issuedOn,expiresOn}`，由服务端生成；ExternalMes引用§4.4的auth_session内部ID，不能改找同用户最新会话来延长授权。Report放入既有access_snapshot_json.identityEvidence；WorkbookSession用专列identity_evidence_json。Job只带runNId回查，不把code/token/contextHandle写进Job参数。回调/执行先核对依据与当前源会话，再求“受理时范围∩当前有效范围”；Native按可信主体公开授权端口重验，LocalAdmin按自己的行版本重验。源会话过期/退出则不能继续取数或正式保存；未开始的报告明确失败、已有不确定副作用按Unknown核对；Office保存不得覆盖旧版，按既有冲突/恢复副本规则提供重新登录后的处理。该规则不意味着支持不受会话约束的长期定时报表，首期仍为已确认的一次性生成。

### 4.3 无MES的最小管理员

LocalAdmin只用于显式无宿主装配，首期不建设通用用户/组织中心。命令`--studio-create-admin`从受保护交互输入读取一次性初始密码，首次登录必须改密；禁止源码/模板默认密码。复用当前[PasswordPolicy](../../../src/backend/src/Services/Identity/IndustrialPlatform.Identity.Domain/Passwords/PasswordPolicy.cs)（12～128字符、大小写/数字/指定特殊字符且不等于账号）、[BcryptPasswordHasher](../../../src/backend/src/Services/Identity/IndustrialPlatform.Identity.Infrastructure/Passwords/BcryptPasswordHasher.cs)（当前workFactor=12）及[LoginAttemptPolicy](../../../src/backend/src/Services/Identity/IndustrialPlatform.Identity.Domain/LoginSecurity/LoginAttemptPolicy.cs)（5次失败锁15分钟）。PF08-001仅把这些无宿主依赖的策略/接口/实现抽到RuntimeSupport/Security，Identity保留兼容入口和现有hash格式，新增共用回归；不能改用另一套算法或带入Identity数据库/服务。默认每配置租户一个管理员，可以停用/重置并递增AuthVersion、撤销会话；MES模式下不注册本地登录入口。该模式仍执行相同resource/data/module授权检查，不允许拿本地超级账号绕过外部MES测试。

LocalAdmin专用入口为`POST /api/v1/studio/auth/local-login {tenantNId,loginName,password}`、`POST /auth/local-change-password {currentPassword,newPassword}`；前者同源/限流/相关性与CSRF检查，账号不存在及密码错误同一401，锁定返回429。成功设置同一会话cookie；mustChangePassword=true时只能改密或退出，改密后撤销旧会话重新登录。管理员创建/重置/停用仅由上述受保护安装工具提供，不建设用户管理产品；安装工具各动作记录可靠审计，不能直接改表。

安装命令具体为`--studio-create-admin --tenant <NId> --login <name>`、`--studio-reset-admin --tenant <NId> --login <name>`、`--studio-disable-admin --tenant <NId> --login <name>`，前两者密码均仅受保护交互输入；创建重复返回冲突，不覆盖。LocalAdmin可获得已安装模块及共用管理功能码，但资源仍按owner/grant，工厂范围仅取LocalAdminFactoryNIds，不能隐含ALL。独立登录/强制改密页沿公共表单控件；MES模式入口显示“通过MES登录”，平台原生仍沿原登录页。登录跳转只记已校验returnPath，失败保留返回入口，不让登录循环丢失设计草稿。

## 5. 数据、字典与业务动作

共用消费端口为已定Dataset执行/RegisteredAction合同；两种模式不改变页面绑定Schema。原生使用公开API/Querying及ReferenceData端口；外部使用登记的HttpApi/SqlQuery/StoredProcedure source。配置时固定base地址键、超时、查询参数Schema、结果Schema、读写语义、允许工厂范围与credentialRef；Designer只见credentialConfigured，运行请求不得提交SQL/URL/秘密。

外部数据权限取可信工厂/用户范围，映射到来源的参数或所选行策略；普通页面lineCode只缩小范围。来源不能表达受控范围且无法安全在服务器限制时，拒绝发布敏感Dataset，不能把全厂数据先返回浏览器。执行结果不因HTTP200变Fresh，observedOn/checkedOn/receivedOn保持真实来源含义。

`IStudioReference.LookupAsync(context,{datasetRevisionNId,parameters,cursor?},ct)`→`{items:[{value,label,disabled}],nextCursor?}`；`AllocateNumberAsync(context,{actionKey,ruleKey,operationKey,parameters},ct)`→`{number,receiptNId}`。原生映射现有ReferenceData；外部字典就是受控Dataset的value/label映射，编号是登记的MES写动作，不另建ReferenceData库。取号必须同一operationKey幂等；MES无该能力则Rule模式不可发布，Manual模式由设计者显式选择。

写动作只由所属MES校验并完成，传递可信操作者/范围采用已登记服务凭据+受控上下文，不信任裸userId头。超时后receipt=Unknown，只可查已登记`statusByOperation`接口确认，未证明幂等不得自动重发。查询失败不回退内置模拟数据；Demo源只允许Development/Test标记。

## 6. 文件适配与保全

### 6.1 自有文件

浏览器通用上传统一走[接口规格§8.5](PF08-PF09-接口与配置合同.md#85-公共文件传输门面)的Studio门面；复用真实公共上传控件，仅替换端点/上下文适配，不能让ExternalMes控件请求SystemData地址。`system_file_upload_session`增加`owner_context_json:json(8)?`，精确内容/授权见该合同；原平台旧会话为null且行为不变，Studio会话必须非空。原生在File所属初始化器追加新迁移，Embedded首个尚未应用的STF-001含此列；不重写原平台已应用DDL/checksum。

持久资源引用统一消费`IStudioOwnedFiles`，方法与接口规格§8.1的Prepare/Commit/Read/Release合同一一对应，补`GetStatus(referenceNId)`及保全设置；平台适配转到新增IOwnedFileService，Embedded调用同一RuntimeSupport文件实现。Studio数据库中的FileNId/ReferenceNId始终是不透明标识，不存外部物理路径或浏览器可访问的永久URL。

Embedded沿现有受控上传流协议、offset/WriterEpoch/长度/hash确认，文件写临时区→完整校验→不可变内容区；先登记Pending引用，扫描通过才可Active和下载。扫描未知/失败保持隔离，不能因为内网或系统生成文件免扫描。File状态回传使用本地持久Outbox投递给Studio能力消费者，同eventId幂等；不需要RabbitMQ，不启动平台消息消费者。

### 6.2 保全与所有权增量

在接口规格的`file_owned_reference`追加`retention_until:time?=null,legal_hold:flag=false,hold_reason:text(512)?=null,last_updated_on:time`；hold为true须reason，版本沿原version。`SetRetentionAsync(context,{referenceNId,expectedVersion,retentionUntil,legalHold,holdReason?})`仅允许所属业务的已授权维护动作；释放受版本CAS、保留时间/hold约束，不能由普通设计者缩短保全。属于新的STF-002/平台下一新迁移，不修改旧File步骤。

删除检查同时覆盖活跃owned引用、旧普通引用/平台既有hold和所选运行组件支持的保全；Embedded不导入聊天hold表。过期Pending回收与已有24小时条件一致。ReportPreview归属的临时引用按数据规格§4.1期限及终态证据回收，Unknown不可因过期释放。正式Artifact/WorkbookVersion内容不可原地覆盖，所有写入生成新文件版本；授权撤销后每次读取重新核对，旧短票据不变成长期通行证。

抽离时把平台聊天引用/hold检查保留为原生注入的引用检查器；Embedded只注册owned/普通引用检查器，不执行查询不存在的聊天表的SQL。审计Scope/租户查找同样由已验证Studio上下文提供，不实例化控制面TenantLookup。这两项须经无SystemData表的冷初始化测试，不能仅以编译通过认定解耦完成。

### 6.3 MES已有附件

登记`MesFileSource`字段`{key,metadataEndpointKey,contentEndpointKey,credentialRef,allowedContentTypes,maxBytes,permissionAction,scanPolicy:ImportAndScan|VerifySourceEvidence=ImportAndScan,trustedScannerKey?}`。节点设计页通过接口规格§7的fileSource选择Owned或Mes、来源键、当前节点fileId/版本字段；不能把MES fileId当Studio referenceNId。`IStudioMesFiles.GetMetadataAsync(context,{sourceKey,externalFileId,version?})`→`{externalFileId,version?,name,contentType,length:string,sha256?,modifiedOn,authorized,scanEvidence?:{scannerKey,status:Clean|Pending|Unknown|Rejected,scannedOn,sha256,version}}`；`OpenAsync`由服务端鉴权代理内容，外部文件ID必须来自已授权节点/记录映射，不能接收任意URL。

默认ImportAndScan：服务端拉取并导入临时Owned引用，扫描Clean后开放模态；需要File与扫描能力，临时引用ownerKind=DetailPreview、ownerNId为服务端新建的本次明细请求NId，expires_on固定创建后30分钟；签名读取凭证绑定actor/tenant/模型版本/node/sourceKey/fileId/version/referenceNId，到期拒绝，每次读取仍重验节点来源权限。无活动上传/扫描后按CAS Release，未确认停止则保留并诊断，不新增报告任务或正式Artifact；不因单选Trace启动Report。VerifySourceEvidence仅允许登记的可信MES扫描来源，其Clean证据必须绑定本次不可变version、长度/hash；代理在放出内容前核验完整hash，失败/未知/源版本变化拒绝。此模式可不启用Studio自有File；没有可信证据时不自动绕过扫描，也不静默改策略，配置页提示切换ImportAndScan及所需依赖。扫描证据只经可信服务端端点取得，客户端字段不构成证明。

追溯模态只读预览可按外部当前版本显示，但权限需每次检查，响应受CSP/sandbox/大小及类型白名单约束；外站拒绝iframe时显示当前模态中的可用下载/无法嵌入说明，不自动打开新Tab。用于正式电子记录/归档的MES附件必须按确定版本拉取并导入OwnedFiles，校验hash/长度并扫描后固定引用；源不支持稳定版本时记录取数时点和不一致风险，不能宣称原件已永久冻结。MES源文件所有权与删除仍归MES。

## 7. 审计适配

统一`IStudioAudit.AppendAsync(context,AuditFactIngestRequest,ct)`→`{auditEventNId,acceptedOn,duplicate}`；事件字段沿当前Audit合同，actor/tenant来自服务端，payload只存白名单摘要/对象版本/操作键，不存密码、SQL秘密、HTML全文或全部业务行。

业务提交与studio_audit_outbox同本地事务。平台由Platform适配可靠送统一Audit；外部由Embedded适配写`system_audit_fact/lifecycle`，再标Sent；重复事件键且hash相同返回原确认，不同hash409并告警。无论选哪模块，不能禁用审计或使用Noop；数据库/Outbox不能持久时写操作失败，不能返回成功丢证据。查询/下载的审计按原合同单独持久，写失败时阻止敏感导出/下载。

外部提供统一公共设置下的审计查询/导出入口`GET /api/v1/studio/audit?page&pageSize&from&until&actor&action&objectNId`，`POST /audit/export`（按现有安全分页/流式导出，不依赖Report）；权限`studio.audit.view/export`，仅当前租户允许范围。原生导航至现有统一Audit，不建第二套事实副本。无端点允许修改/删除事实，生命周期保留/hold沿既有合同。

可选MES镜像`POST <登记的MES审计端点>`，body=`{schemaVersion:1,tenantId,eventId,occurredOn,actor,action,objectType,objectNId,traceId,payloadHash,payload}`，MES按eventId+hash幂等，响应`{eventId,acceptedOn}`；仅本地事实提交后投递。Embedded `system_audit_outbox`随固定STA-001建表，镜像启用才写入/注册投递器，使用现有全部字段/重试/死信合同；不阻塞本地已持久事实、不声称镜像已经成功。禁用镜像不影响Studio审计可靠性，也不修改已应用DDL。

## 8. 调度适配与Unknown保护

统一`IStudioJobs.SubmitOnce/GetByOperation/GetStatus/RequestCancel/Reconcile`；SubmitOnce沿接口规格§8.2字段，返回统一`{jobNId,runNId,stateVersion}`。原生调用PF07受信端口；外部Embedded复用同一Job/Run状态机、CAS和Hangfire固定Provider，直接执行Studio登记Handler，不调用目标MES调度也不加载SystemData。

`GetStatus(runNId)`→`{status,stateVersion,operationKey,executionEpoch,startedOn?,completedOn?,workerReference?,reasonCode?}`；`RequestCancel({runNId,expectedStateVersion,reason})`只表示请求；`Reconcile({runNId,expectedStateVersion,evidence:{workerStopped,artifactChecked,businessResult:NotExecuted|Succeeded|Failed,referenceIds:[]},resolution:ConfirmSucceeded|ConfirmFailed|ConfirmCancelled})`要求`studio.report.reconcile`，证据由服务端核查，不能信任浏览器勾选的workerStopped。Unknown先证明旧worker停止与产物状态，再推进并释放活动槽；没有证据拒绝，不能直接Update数据库。

报告开始仍用operationKey+executionEpoch和持久CAS占槽；引擎补偿/重投不得启动第二个已占用执行。`AutomaticRetry.Attempts=0`仅关闭显式自动重试，不能代替槽与幂等保护，Hangfire仍有至少一次补偿行为，见[官方说明](https://api.hangfire.io/html/T_Hangfire_AutomaticRetryAttribute.htm)。PF07已有保护必须原生/Embedded同用，不能凭“只启一个worker”移除。

外部默认同一Studio进程一个Embedded worker入口，渲染总并发2、MaxAttempts=1、NoAutomaticRecovery；不在每个API副本都启动独立worker。首版ExternalMes按单活动Studio实例交付，跨主机HA不新增承诺；使用平台原生时保留现有平台拓扑。Report未选时不注册worker/引擎存储，Audit/File恢复用自身受控后台恢复流程，不借机强制安装报告调度。

任务列表/Unknown核对入口：原生沿既有Scheduler页面；外部在Report运行详情内显示上述诊断/核对，不额外搬入平台调度产品。所有核对动作审计。Embedded没有`systemdata.reconcile`任务，不读取/更改平台ReconciliationMode；原生Scheduler.Enabled与ReconciliationMode仍分开核验。

## 9. 部署、初始化和诊断操作

Windows/Linux、PG/SQLite/SQL Server2019/2022、既有Web/Electron/Android运行范围保持；SQLite含Report时还有.scheduler.db调度引擎文件，不能对外写成整个安装严格单文件；旧未测矩阵继续待实测。ExternalMes默认只需一个Studio可执行服务、其数据库及所选依赖；没有Redis/RabbitMQ/Identity/SystemData/ReferenceData硬依赖。需要File时加合法内网扫描服务，需要Report时加Renderer/Office；引擎发行许可/OS适配未过G02不得标发行完成。

新增启动命令均是待实现合同：`--studio-inspect`只读输出清单/模块/依赖/迁移差异，不建表、不打印Secret；`--studio-initialize`使用migration账号执行计划并退出；正常服务使用无DDL的runtime账号；`--studio-check-change <新清单路径>`只读检查模块引用、未终结任务/写会话及兼容版本，失败非0，不自行改配置。首次LocalAdmin使用§4.3命令。操作JSON结果统一`{ok,profileVersion,modules,checks:[{key,status,reasonCode,checkedOn?,receivedOn?}],migrationPlan:[{moduleKey,stepId,checksum,status}]}`。

核心首次交付在C0按固定顺序创建STU-001～006共16张表（原13张业务/运行表+3身份技术表），PF09后续只启用已交付模块，新增字段时再追加007及之后步骤；空表不计功能已实现。当前这些STU步骤尚未在仓库实现/应用，本次细化首次目标清单，不改任何已应用账本。初始化顺序：实际业务schema/主文件及2张Studio框架账本→Studio核心16表→所选Embedded运行表→所选租户/权限/模块种子→验证→启动对应后台服务。原生公共表由原服务初始化器负责，Studio不能代它迁移。首次STU-004包含Report Preview快照/期限/manifest及用途约束（数据规格§4.1），首次STU-005包含本轮补充的WorkbookSession身份依据列、006为新身份表；已有平台的历史迁移保持原样。实际交付版本包含的目标步骤必须与已安装账本核对，不用跳账本方式切模块。

管理入口放各产品共用设置中的“部署与接入诊断”，不增加第五个产品菜单。固定布局：顶部模式/安装模块/已启用模块/ProfileVersion；中间身份、数据、File、Audit、Jobs、Renderer、Office检查表；右侧选中检查明细与最后来源时点；按钮“重新检查/导出脱敏诊断/返回”。只读默认；跳转的身份映射/数据源/授权操作走各自权限，不能从诊断页编辑Secret。未知/过期来源不能因点击刷新变绿。

`GET /api/v1/studio/deployment`→上述清单的脱敏摘要及数据规格§6.3.4的storageTargets；`POST /deployment/check`→checks（权限`studio.deployment.inspect`，限流，不改配置）；capabilities扩展`installed/enabled/available/reasonCode`与所需适配来源。不允许浏览器切DeploymentMode/InstalledModules。入站端口/PathBase均由实际配置解析，不写旧聊天端口。

备份包含Studio核心及实际Embedded表、2张Studio框架账本、文件内容、密钥/证书、清单及配置秘密恢复方案；PG/SQL Server包括实际业务schema和scheduler_hangfire，SQLite包括主文件及已存在的.scheduler.db，使用受控一致备份/恢复，不能只复制运行中的主文件；MES业务库不属于Studio备份范围。恢复后核对文件hash、修订引用、授权映射版本和未终结任务；清单与组件版本不匹配停止相关能力。旧程序回退遇不可逆schema须恢复一致备份，不只换DLL。
