# PF09 报表分页与追溯运行规则

版本：V1.2；2026-10-22。实现行为合同，不是现有概念HTML已具备的生产能力。配置结构见[接口与配置](PF08-PF09-接口与配置合同.md)，存储和状态见[数据模型](PF08-PF09-数据模型与生命周期.md)。本轮补齐带内增长、表格行上下文和电子记录调用主从子树的执行语义。

2026-10-30 功能范围补充见[报表与临时查询表格整体说明](PF09-报表与临时查询表格整体说明.md)：汇总预览、导出、高级控件及临时表格的多人隔离和退出清理要求。新增范围不表示本规则中的实现与验收已完成，也不将临时查询清理规则套用于正式报表产物。

## 1. 报告执行流水线

`受权受理 → 固定定义/参数 → 数据与资源采集 → 组装计划 → 主从展开 → 连续内容流 → 布局分页 → 完整性检查 → File持久确认（正式归档或临时预览） → 成功`。

每阶段输出受runNId隔离；未通过完整性检查不标Succeeded。设计试运行和正式生成调用同一DataResolver、AssemblyPlanner、BandExpander、HtmlNormalizer、Paginator，不维护第二套“预览近似排版”。预览数据可少量/模拟，但算法相同，明确显示数据来源。

未发布设计按接口PreviewInput冻结root草稿和显式保存的子草稿/发布依赖，设计预览直接调用共用规划器与分页引擎，在一次请求返回页面，不经过Jobs排队或Files归档。正式生成只能按发布修订，并继续走任务、文件确认及产物归档。规划器读取固定快照，不在运行中重读编辑中的草稿。预览没有固定到期时间，仍复核发起人、权限与数据范围，不隐式发布。旧execution_kind=Preview记录及其读取端点保留兼容，同样不按历史30分钟期限拒绝或回收；Unknown不按时钟清槽。存储与端点见数据规格§4.1/接口§6，B43覆盖两次草稿预览互不污染和正式入口隔离。

查询与输出共用ReportDesign.ResolveSort：未传排序使用固定文档defaultSort，显式空数组清空排序；正式受理保存解析后的排序而不是一律空数组，重新取数/快照重排沿原排序。简单组合及电子记录中的Query子报告同样应用各自默认排序，不修改固定原文档。

应用端口固定：

```text
IReportPlanner.PlanAsync(ReportDefinitionSnapshot, ParameterValues, DataSnapshot, CancellationToken)
  -> AssemblyPlan { instances, skipped, diagnostics }
IReportExpander.Expand(AssemblyPlan, DataSnapshot)
  -> ContentFlow { blocks, provenance, expectedMarkers }
IReportRenderer.RenderAsync(ContentFlow, PaperDefinition, ResourceManifest, CancellationToken)
  -> RenderResult { pages, pdfStream, markerLedger, diagnostics, engineManifest }
IReportExecution.ExecuteAsync(runNId, TaskExecutionContext, CancellationToken)
  -> ScheduledTaskResult
```

ReportDefinitionSnapshot是内部只读定义投影，包含kind/document/dependencySnapshots/sourcePins/contentHash；Production从固定修订组装，Preview从preview_snapshot_json读取，不要求伪造ReportRevision实体或主键。两者采集的数据快照/输入资源在source_manifest_json登记；Preview所有临时文件统一使用ReportPreview ownerNId=runNId，失败也可按owner枚举回收，不依赖成功manifest才知道文件存在。

这些类放PlatformStudio.Application/Report，渲染引擎放Infrastructure/Report；不要把节点展开语义嵌进第三方编辑器私有JSON。ContentFlow是内部类型，不开放用户提交原始HTML指令或任意脚本执行。

## 2. 任意配置层级的等宽主从带

展开从Root Detail集合开始，逐条建立不可变上下文栈`{root,bandId,currentRow,parentRows}`。当前行控件求值后，按结构树顺序依次展开子带，再进入下一主行。兄弟带不继承前一兄弟的currentRow。祖先引用按bandId定位，非法跨分支引用发布即报错。

带的几何宽度统一为`paper宽度 - 左右页边距`；层级只显示在结构树/带标题，正文x坐标从0开始。`heightMm`是设计最小高度，CanGrow后按实际文本/表格增长，下一个带跟随实际底部。带内控件可自由拖放，但“下一个带跟随”不能解决同一带内签名栏被长HTML覆盖，须同时执行ReportControl.flow。

Follow控件按afterControlIds拓扑顺序测量：控件实际y=`max(设计y, 每个前置控件实际底部 + 原设计间隔)`；原设计间隔=`当前设计y - 前置设计底部`，负值拒绝为跟随关系。同一行表格单元格取实际最高单元格作为行高，不能各列自行覆盖下一行。未选前置的控件保持设计y；若增长后正文控件发生非设计允许的覆盖，返回REPORT_LAYOUT_OVERLAP并定位两个控件，不能静默输出。最终带高=max(最小带高,所有正文实际底部)。流内容再统一分页，设计器百分比缩放不参与测量。Overlay仅容纳明确固定装饰，不开放一个未定义的“层叠容器”类型给开发猜测。

Table.BandRow不会再遍历集合：带展开2个工序即输出2行，列Row为对应工序。Table.Collection在每个带实例内遍历value数组，列Row为数组项，ParentRow为所属带行。OncePerParent表头按(父带实例key,控件id)去重，续页表头另外标记repeat；不能对整份报告全局只留一次，也不能每行重新打印。单报表emptyBehavior=Label在空集合位置输出一次说明且不运行行字段绑定；电子记录业务空实例在生成流之前即跳过，包括Label/装饰/物理页眉页脚，不产生空记录证明。

GroupHeader/Footer按配置键分组，合计作用域为指定带实例，不按页意外重置；空集合Count=0、Sum=0、Avg/Min/Max=null并按格式显示。仅空集合触发Skip；路径不存在、类型不符和取数失败是诊断错误。数据关联查询先收集父键、分批最多200个键执行并建索引；未支持批量的来源并发最多4、总查询最多200次，超出报预算错误，不悄悄跑N+1至超时。

设计层级不固定3级。默认保护深度32、带定义200、展开块100000、最终页数2000、单run采集50MiB；可由运维调整，页面显示限额与实际估算。循环parentBandId直接拒绝；达到保护上限报错误，不忽略后代。

## 3. 两种组合

### 3.1 简单组合

逐项解析固定子报表修订及参数，先独立验证。每份报告默认新页开始、保留自己的纸张方向/页眉页脚。Preserve保留各自页码；Global由渲染器抑制各子模板PageNumber控件后统一输出页码，不能在已打印页码上叠印。不能访问的必需项使整个任务失败；可选空项明确记录Skipped，失败仍不是空项。首期不合并用户上传的任意PDF作为模板，避免无法重排页码与资源权限的隐含需求。

### 3.2 电子记录动态组装

按实际工单稳定排序，逐工单取实际工序，再在该工序上下文求每条AssemblyRule：条件false→SkippedCondition；数据成功但空→SkippedEmpty；有数据→0..N个实例；required=true但空→DATA_REQUIRED；任何取数错误→Error。有无数据由repeat或presence明确指定：repeat逐行输出，presence非空只输出本工序一份，不能用一直存在的工单页头认定子报告有数据。判空和渲染共用采集快照，不额外重查导致两次判断不一致。每次跳过留设计诊断行，**不输出空标题、占位框、空白页**。

所有Include实例先展开为ContentFlow，再按一份母版分页。母版统一纸张方向、正文宽度、页头页脚和总页码；子报表嵌入时改用母版正文宽度并验证列宽，不能带着原来的A4整页盒子拼接。子模板只有显式breakBefore=Page才另起页，默认Auto继续前页。报表首尾说明属于内容流；子报表的物理PageHeader/Footer不重复插入流。

### 3.3 主从模板与组合的接合

每条规则先选择子报告及固定修订，再选择WholeReport或BandSubtree。WholeReport求parameterMap并正常执行报告；BandSubtree明确选择输出起点Detail带，把当前来源行通过rowMap转换为该带行Schema，并通过ancestorMap供给实际引用到的祖先行。入口带原data查询不再运行，后代仍按原绑定展开；不能重新查询整张工单造成每条记录重复一整份主报告。

例如母版当前工单WO-A、工序OP-10，规则repeat取其`weighRuns[]`的两次称量；子模板入口为`detail-weigh`，映射`Row.runCode→code`、`Row.lines→materials`、`Root→工单祖先带`、`ParentRow→工序祖先带`。输出两次称量及各自材料明细，数量按各自lines长度，工单/工序上下文不串；不是固定输出五张子报告。对象/集合映射按完整Schema校验，不得把lines转成JSON文字代替下级明细。

计划持有`instanceKey,ruleId,sourceRowKey,entryBandId,resolvedMappings,contentRowCount`；contentRowCount只计实际正文记录，不把固定页头或“无明细”标签算成有数据。模板入口/字段变更后重新验证所有受影响规则；未明确应用新修订前，已发布组合仍使用旧修订。设计“进入子模板编辑→返回组装”保留工单、工序、规则、滚动/缩放及未保存草稿，回到母版明确提示应用新模板草稿或继续原绑定；禁止悄悄改已发布闭包。

以下数量样例是另一种按records类型选择完整子报告的配置；两种输入结构均须支持，不能要求现有MES强制把所有表改为同一个records联合数组。

示例仅作验收数据，不是产品写死结构：

```json
{
  "workOrders": [
    {"id":"WO-A","operations":[
      {"id":"OP-10","records":[{"type":"weigh","id":"R1"},{"type":"mix","id":"R2"},{"type":"qc","id":"R3"},{"type":"html","id":"R4"},{"type":"event","id":"R5"}]},
      {"id":"OP-20","records":[{"type":"qc","id":"R6"},{"type":"event","id":"R7"}]},
      {"id":"OP-30","records":[{"type":"html","id":"R8"}]},
      {"id":"OP-40","records":[]}
    ]},
    {"id":"WO-B","operations":[{"id":"OP-50","records":[{"type":"weigh","id":"R9"},{"type":"weigh","id":"R10"}]}]}
  ]
}
```

5条type匹配规则且repeat=匹配记录集合：A输出8实例，B输出2实例，共10；A的OP-40不占正文位置，但组装计划保留5条空匹配诊断。新增第6类规则不改核心代码。若R6数据源故障，必须报Error，不能仍声称“7实例完整记录”。设计页展示工单/工序/规则/源数据数/决定/原因/输出页范围，点击定位对应模板或页段。

## 4. HTML归一化、长内容和纸张

HTML是外部保存的人工填写记录输入，不是本期制作工单录入页。接收`{html,resourceRefs,sourceRecordKey,sourceVersion?,recordedOn,formValues?}`：若源只保存未序列化的DOM value，必须提供formValues按稳定控件name/id补值，否则报缺失，不把空input当完整生产记录。

归一化允许文本、p/div/span、h1..h6、br、strong/em/u/s、ul/ol/li、table/thead/tbody/tfoot/tr/th/td、img、sup/sub及安全链接显示文本；表单input/textarea/select转为静态值/勾选框，保留明确填写状态。保留许可内字体、字号、颜色、边框、对齐、间距、列宽、rowspan/colspan。拒绝脚本、事件属性、object/embed/iframe、javascript URL、动态CSS表达式；固定定位/浮动/动画/外链CSS不直接进入纸张。被移除的影响内容元素列出诊断，不能静默删掉后成功。未知业务标签需登记转换器，否则422。

全部资源由File或受信来源资源适配取得，复制为固定hash资源清单；禁公网临时URL/本机路径/任意SSRF。图片解码失败、字体缺失、HTML样式不能转换都有定位。净化前后保留来源hash及转换策略版本；未净化源只在受控快照中存储，不给浏览器执行。

### 4.1 分页确定规则

1. 等字体ready、图片尺寸明确后，以固定引擎/浏览器版本、100%内部缩放测量；预览显示缩放不影响物理mm。正文高度为纸高减上下margin、header/footer及明确间距，页头页脚不侵入正文。
2. 普通文本按行盒分页，最少保留2行孤行/寡行；长词允许按字符换行，不能横向撑宽。普通能放下一页的表格行可keepTogether；**整行高于一页**时必须进入单元格碎片续排，不能一直挪到下一页。
3. 表格续页复制表头并标记为重复呈现；正文行/单元格各有源marker。跨页单元格记录字符/子块范围，延续剩余内容；相邻单元格已结束可显示空延续格，但不能重复原值。rowspan跨页拆成视觉延续格，保留原始逻辑关系；嵌套表格递归执行同规则。
4. 图片若超过正文可用尺寸，保持宽高比缩放到整页可容纳范围；默认不裁切。若配置的最小可读尺寸不满足，报布局错误；不靠无限缩小字体完成验收。签名图/不可拆块仅在本页剩余放不下且下一页放得下时换页。
5. keepWithNext仅作用于标题及下一首段；若组合高于一页解除该保留约束并给诊断，防死循环。无显式分页且下一块的最小合法片段能放入剩余区，就必须继续填；禁止对子报表/HTML根元素整体`break-inside:avoid`。
6. 最终页数生成后填全局页码，再验页码变化未引起额外分页；有界二次布局（最多3轮）。仍不收敛报REPORT_LAYOUT_UNSTABLE，禁止无限循环或伪成功。
7. 每页输出sourceMarker范围和fragmentIndex。非重复正文marker覆盖恰好一次；表头标记repeat不参与正文重复计数。比对归一化文本token、表行key、填写值及图片hash，核验无遗漏/重复。

需要写可测试的断言：在没有显式分页、孤行规则、不可拆块约束的边界，剩余高度≥下一最小片段高度时，不允许换页。不是笼统要求所有页填满；最后一页、合法keepTogether、签名块换页产生的留白必须在布局诊断说明原因。

### 4.2 渲染与输出边界

优先验证Paged.js作为分页底座，PlatformStudio负责展开/净化/长单元格预处理和标记核对，服务器同版Chromium输出PDF。**不能将CSS分页库的存在当作上述极端内容已通过**。正文HTML在隔离渲染进程，输入数据不具脚本执行权；CSP只准已打包渲染脚本与hash资源，网络默认拒绝。生成CPU/内存/页数超限终止时需确认进程退出，未确认进入Unknown。

预览可展示分页HTML，但正式导出PDF由服务器固定引擎生成；浏览器直接“打印当前网页”不作为电子记录归档证据。同输入/字体/引擎应页数及marker分布稳定；PDF二进制若含生成时间不要求byte hash重复相同，但内容/页序/版本依据必须一致。

## 5. 追溯起点与关系取数

### 5.1 自建模拟接入表（不复制客户SQL）

以下建在独立Fixture库，绝不放PlatformStudio业务库当事实主表。字段名仅是可映射的例子。

| 视图 / 过程 | 字段 / 键 | 用途 |
| --- | --- | --- |
| v_inventory_lot | factory_code,lot_id(PK组合),material_code,material_name,lot_code,quantity(decimal),unit,object_type,status | 起点批次检索与库存摘要；工厂+批次ID是身份，不以lot_code跨厂合并 |
| v_work_order_operation | factory_code,operation_id(PK组合),work_order_id,operation_code,operation_name,started_on,ended_on | 预溶解/生产工序事实节点 |
| v_material_movement | factory_code,movement_id(PK组合),from_type,from_id,to_type,to_id,semantic,quantity,unit,occurred_on,document_id | 消耗/产出/拆并关系，movement_id为独立事实证据 |
| v_shipment_line | factory_code,shipment_line_id(PK组合),lot_id,shipment_id,customer_code,quantity,unit,shipped_on | 成品到销售出库 |
| v_object_document | factory_code,object_type,object_id,document_id(PK组合),label,file_reference/external_link_key | 明细附件与受信外链 |

起点搜索传值→已发布Dataset参数→来源只读查询→列映射→选中真实rowKey→执行追溯。允许从工单开始另配start Dataset；不把所有节点都假定来自库存表。

关系示例`ConsumeRaw`：forward输入当前node.businessKey→from_id、可信factory→factory_code，返回movement_id/to_type/to_id/quantity/unit/document_id；reverse以当前node.businessKey→to_id返回from_type/from_id。节点明细Dataset用当前object_type+businessKey+factory查询，不把摘要字段数组代替完整明细授权。

### 5.2 展开算法和身份

从授权起点执行有界BFS；队列项为(nodeKey,direction,remainingDepth,relationFilter)。先按方向和关系规则批量收集当前前沿key；去重查询键是(nodeKey,relationId,direction,sourceObservationScope)，不是只用nodeKey，因此双向、不同关系不会被误跳过。每个事实边key=tenant/source/factory/relationId/evidence.recordKey/from/to的规范化hash；同一对节点的两次消耗保留两条边。

节点去重按完整稳定身份；环只停止重复扩展，不删已发现真实边。`Context`设备/检验边默认可显示但不自动计入物料影响范围；只有选中的Genealogy关系进入上游/下游影响计算。返回路径不能把“使用同设备”推断成物料实际流入。

运行节点位置由选定布局算法计算，可人工移动本次视图；不把运行节点写回模型节点。加载/取消/明细失败各自局部反馈；旧请求迟到不能覆盖新起点。没有通用事实快照库或图数据库依赖；源系统无包装记录时展示Batch粒度和缺失依据，不补造包装链。

## 6. 追溯模态框明细

右侧详情展示字段和值、数据时间、证据单据。点附件/外链进入当前页面模态框，图谱仍保留缩放/选中/展开上下文。文件按配置区分Owned与Mes：Owned核验Studio引用和当前资源权限；Mes按适配部署§6.3配置来源/版本、ImportAndScan或可信Clean证据。两者均检查扫描/隔离及当前权限，内容地址有期限；HTML文件不直接以宿主同源执行，采用净化或安全预览。

外链只允许登记origin及协议https（受控内网http须部署登记），URL参数编码，iframe sandbox默认不允许顶层导航/弹窗，必要能力按注册链接策略最小开放。若目标X-Frame-Options/frame-ancestors禁止嵌入，模态框显示“来源不允许嵌入”及复制地址按钮；不得自动新Tab、移除目标CSP或反向代理绕过。复制需用户操作，不能把链接解析失败当空明细。

## 7. 端到端故障语义

| 场景 | 报告 | 看板 / 追溯 |
| --- | --- | --- |
| 缺必填查询参数 | 未受理/Failed，不全量查工单 | 阻止取数，显示具体参数 |
| 权限撤回 | 下一执行检查停止；旧产物下载再次授权 | 当前请求拒绝并清不可再见内容 |
| 来源超时 | Failed或执行结果Unknown，不能SkippedEmpty | 看板旧值Stale；追溯Partial附失败源 |
| 跨源数据时间不一致 | manifest明确观察时间，不声称事务快照 | 每来源observedOn，不用页面generatedOn冒充 |
| 上传/扫描失败 | 不登记成功产物；重试不重复业务执行 | 文件模态框显示明确错误 |
| 取消后旧worker仍在跑 | CancelRequested/Unknown，保留活动槽，不另起替代执行 | 前端丢弃旧结果不等于服务器已经停止 |

## 8. 后续实现不得自行改变的决定

不将等宽主从带改为缩进卡片；不将电子记录实现为PDF整页拼接；不把“最多五种子报告/三级明细/半导体链”写成模型上限；不将HTML转整张截图规避跨页；不以CSV下载代替在线Excel；不从浏览器直接执行SQL；不根据拖拽连线创造追溯事实。
