# 平台单页入口与独立部署：后续主控交接

日期：2026-09-15。依据：用户最新入口说明和四阶段顺序。本文件记录后续开发输入，不表示功能已实现，也不授权当前主控实施第 3、4 阶段。

## 1. 不可混淆的入口契约

| 入口 | 适用范围 | 参数含义 | 展示结果 |
| --- | --- | --- | --- |
| 原平台页面，不传新参数 | 平台现有业务页面 | 使用既有登录和路由规则 | 保持现有平台外壳及行为 |
| `?mode=single&token=...` | 平台通用单页接入 | `single` 表示单页呈现；`token` 是需验证的有效访问凭证 | 只显示允许接入的目标业务页面 |
| `?mode=single&ticket=...` | 平台通用单页接入 | `ticket` 是由受信任流程签发并兑换的票据 | 与 token 入口复用同一单页布局 |
| `?mode=standalone` | 独立部署页面 | `standalone` 是独立入口标识，不代表平台 token/ticket 登录 | 只呈现独立模块及必要交互 |
| `?mode=standalone&account=xxA` | 独立部署的 Collaboration 页面 | `account` 标识 MES 嵌入的登录用户；不是所有独立模块的必选参数 | 以该用户打开通讯页面 |

示例：

```text
/pc/collaboration?mode=single&token=<有效Token>
/pc/collaboration?mode=single&ticket=<可信票据>
/pc/collaboration?mode=standalone&account=xxA
```

- 不把 `single` 等同于某个认证模式，不把 `standalone` 改写成另一种平台单点登录，不强制独立地址追加 `ticket` 来混同两种合同。
- 正式独立接入如何由宿主确认 account 对应的当前登录主体，留给第 4 阶段的适配合同；演示固定 A/B/C 与真实 MES 接线分开。仅 URL 标识本身不能承担可信身份验证；这是服务端接入职责，不改变上述 URL 形状。
- 保留现有路由形式，不因旧项目使用 `/#/` 就修改全平台路由。第 3 阶段明确开放页面名单，不默认让所有管理页面支持单页访问。
- 展示参数不切换数据库、Schema、服务地址或身份验证规则。平台部署与独立部署的默认入口、旧无 mode 地址兼容规则由对应阶段单独确定，当前不改默认值。
- `token` 和 `ticket` 的合法来源、冲突输入、身份不匹配、参数清除与日志脱敏在第 3 阶段设计；不得以长期保存密码或十年访问令牌替代续期。

## 5. 第 4 阶段：独立部署交接

- `IndustrialPlatform.Collaboration.EmbeddedHost` 是当前独立宿主；其 `EmbeddedHandshake.cs` 已有挑战/断言、映射、KeepAlive、撤销，`EmbeddedHubSessionValidator.cs` 已有连接会话校验。优先审查复用，不能再造一套同职责会话层。
- `StandaloneConfiguration.cs` 和 `src/backend/appsettings.Standalone.Development.local.json.example` 是独立配置入口；平台私有配置、ReferenceData 历史账本兼容和现有数据库/Schema布局保持不变。私有实际配置不得提交或写入本文。
- 宿主用户接口、人员 Search/Get 由用户后续填写；保留 .NET Framework 4.5.2/.NET 6 可理解的 HTTP 适配边界和中文注释。具体类/方法/字段交付到代码，不让接入者猜。
- Collaboration 既有需求继续保留：离线可留言、媒体邀请需要对方在线；页面连接决定在线状态；同账号多页面关闭一页不全局注销；媒体仅选定终端参与。它们不是所有独立模块的通用规定。
- 当前独立通信仍有用户报告的列表超时、未知在线和媒体不可达。PresenceRegistry 依赖 Redis，独立配置未显式配置时会使用默认连接；这是已发现的依赖风险，尚不能认定为全部症状的唯一根因。部署阶段先核实际依赖和请求链，不能当作布局或 token 问题反复修改。
- 首先明确是新标签页还是实际 iframe，以及同源/跨源部署、宿主会话可用条件、人员接口和信令依赖。真实 iframe 的语音/观看权限与生命周期必须单独验证；不能用新标签页成功替代。
- 数据库提供程序扩展、Electron/Capacitor、后置云 Docker/TURN 和稳定性验收仍按用户另行阶段处理，不在当前清理阶段追加。
