# 通用生产全链路追溯模板

本模板在原“示例·CMP批次追溯”模型上扩展，模型资源标识保持 `21b43867-65f7-4153-a4f2-1c5a62ab7ddb`，发布版本 2。原版本 1 和原示例数据保留。数据为合成教学数据，不代表实际生产记录。

## 对象与关系

主线为“原料 → 母液预混生产情况 → 半成品混配生产情况 → 罐装生产情况 → 销售出库”。另外包含原料直接补加混配、耗材领用、余料留存和清洗记录关联。

| 对象 | 示例编号 | 含义 |
| --- | --- | --- |
| 原料 | TPL-RAW-001 / TPL-RAW-002 | 80 kg 硅溶胶经预混投入，20 kg 添加液直接补加 |
| 母液预混生产情况 | TPL-PRE-001 | 80 kg 母液预混批次 |
| 半成品混配生产情况 | TPL-MIX-001 | 合并为 100 kg 半成品 |
| 罐装生产情况 | TPL-FILL-001 | 处理 100 kg 半成品的罐装批次 |
| 耗材 | TPL-SUP-001 | 领用 3 个包装桶，独立计量 |
| 剩余量 | TPL-REM-001 | 留存 10 kg 余料批次 |
| 清洗生产情况 | TPL-CLEAN-001 | 罐装线 GZ-01 清洗验收记录，按次计量 |
| 销售出库 | TPL-OUT-001 / TPL-OUT-002 | 分别向两个客户出库 60 kg 和 30 kg |

共 8 类对象、8 类关系、10 个对象实例、9 条事实记录。数量闭合为 `80 + 20 = 100 = 60 + 30 + 10 kg`；耗材的“个”和清洗的“次”不混入物料质量平衡。

参考图中的反向箭头由每条关系的反查映射实现，不重复创建方向相反的投料事实。起止圆点是示意边界，没有建成无业务数据的对象。“剩余量”用有身份的余料批次承载；“清洗”使用上下文关联，不参与物料谱系的自动递归传播。

## 使用

1. 从“工业应用 → 追溯执行”选择“通用模板·生产全链路追溯”。
2. 点击“选择追溯图谱”，弹框自动展示起点数据。可输入 `TPL-FILL-001` 或 `TPL-OUT` 等编号片段查询，勾选当前页的一个或多个起点并点击“确认”。取消弹框会保留主页面原有选择和图谱。
3. 选择上游、下游或双向。关系筛选和最大深度放在“高级选项”中；关系留空时追溯物料谱系，查看完整教学链路时选中全部 8 类关系，包括“清洗记录关联”。
4. 点击“加载图谱”，点击节点查看编号、名称、数量、单位、业务状态、记录时间和工厂；点击关系查看记录标识、时间、数量及单位。
5. 可从出库批次反查原料、预混、混配、罐装及相关耗材，或从原料正查影响的生产批次和出库去向。

## 复用到业务场景

当前复用既有只读示例数据源 `trace-cmp-example`，只追加 `TPL-` 前缀的示例行。新配套数据集为 `pf09-generic-template-starts/detail/forward/reverse`，分别承担起点检索、身份明细校验、下游事实和上游事实。

接入真实业务时，先建立并发布对应业务数据集，再替换模型中的固定数据集修订引用及输入/输出字段映射。必须保留完整身份的“来源系统、工厂、业务标识”，并为事实提供稳定记录标识。配置目标用户原本拥有的工厂范围；不能靠扩大权限使数据通过校验。

可复用文件见 `docs/examples/trace/production-chain.template.json` 和 `production-chain.fixture.json`。模板文件的数据集修订使用占位符，须替换为目标环境已发布的数据集修订；它不是可直接跨环境运行的数据库备份。当前环境完整快照与恢复备份保存在忽略目录 `.run/pf09-trace/`。
