# PF-10A 资料解析、原文检索与引用验收

V0.8 · 2026-11-18 · KH-01、KH-02 的设计与验收规格。平台内优先，独立部署沿用相同的解析、检索、引用和可见性规则。两种装配的依赖见[双模式清单](PF10A-双模式装配与助手行为接入.md)。

## 1. 从一份资料到可核对的答案

假设测试用的《接口联调手册》适用于 v2，第 7 个 PDF 物理页写有“错误 E-204 表示回执超时。请先在接收记录中核对工单号，再按本节步骤处理”。上传者选文件即可。另一位有查看权限的实施人员可以：

1. 在解析期间按“接口联调手册”找到资料，打开原件。列表显示“已入库，正在解析”。
2. 索引就绪后搜“E-204”，看到包含原句的命中片段、v2 标签和“第 7 页”。点击片段直接进入 PDF 第 7 页，也可以从标题打开整份资料。
3. 提问“v2 出现 E-204 先查什么”，助手回答“先到接收记录核对工单号”，紧跟可点击的出处。追问“那 v1 呢”时重新按 v1 检索。只有 v2 材料时，向用户说明缺少 v1 依据。

该例的错误码含义仅用于说明验收方法。现场以实际手册原句和预先标注的位置替换。

## 2. 上传、解析与检索就绪分别判定

| 发生什么 | 后端处理 | 用户能做什么 |
| --- | --- | --- |
| 上传中、扫描待确认 | 按租户、项目、维护权限接收文件，校验大小、实际格式和扫描结果。批次逐项返回状态 | 上传者能看进度或失败原因。普通阅读列表仅展示已入库项 |
| 文件可读，入库成功 | 以稳定操作键创建文档/新修订，保存文件引用，在本地事务切换有效指针并登记索引任务。原文件名作为默认标题 | 立即可按标题、文件名和已填元数据查找并打开原件。任务重复投递返回同一修订 |
| 正在处理 | worker 领取租约，读取当前授权原件，按资源上限解析、分块，写到本代次的暂存索引 | 显示“解析中”或“建立索引中”，同一状态页刷新。正文结果只读取已就绪代次 |
| 有可引用内容 | 核对修订、代次、启用状态及租约，原子标记就绪。分来源记录提取页数、空页、警告及失败原因 | 支持正文搜索和带引用问答。含扫描页或不可提取附件时提示覆盖范围，引用只落在已提取部分 |
| 没有可提取文字或处理失败 | 全扫描件记“无可提取文本”，损坏、受保护、超限或超时保留具体原因。临时存储/worker 故障沿已有退避重试，格式问题提示换文件或补充文字 | 保留有权读取的原件和元数据命中。用户可补说明、替换修订，或对临时故障重试 |

入库与索引状态沿[数据规格](PF10A-核心数据与一致性规格.md)。任务继续使用 Pending、Processing、Ready、Failed、Obsolete，进度和可检索覆盖度是附加信息。建议增加每个来源的 extractionOutcome（Indexed/Partial/NoText/Unsupported/Failed）、原因及覆盖计数。仅有预期不可提取的空页或普通附件时可提交其余有效片段并提示部分覆盖；损坏、超时、资源超限属于处理失败，本次任务的暂存片段整体不可见。全部来源都无依据时以 Failed 加 NO_INDEXABLE_TEXT 结束，界面显示“仅可查看原件”。

同名文件由用户决定新增或替换。旧索引晚到、任务中断、停用与恢复均以文档当前指针和索引代次判断。重启后回收过期租约，重复生成覆盖同代暂存键；待提交时再次核验。切换修订后旧片段即刻退出候选，新版尚未就绪时人工仍可打开新版。预算沿用单文件 20 MiB、每批最多 50 项且总计 200 MiB、单文件提取 4 MiB/60 秒的设计初值，现场样本测试后冻结。

## 3. 解析要保留用户能找到的位置

| 来源 | 提取单位与边界 | 打开引用 |
| --- | --- | --- |
| TXT、Markdown、富文本 | 提取可见内容，保留标题层级、段落、列表、代码与错误码原样。文件解码失败给明确提示 | 阅读器定位修订中的段落，显示命中上下文。富文本按安全渲染结果编号 |
| 文本 PDF | 逐物理页提取，保留页内顺序。无文字页记录页号。多栏、表格阅读顺序不可靠时保留原页入口，不能据错序片段断定步骤 | PDF 预览定位从 1 开始的物理页，印刷页码另作展示。无法高亮时仍定位页 |
| DOCX | 按文档顺序保留标题、段落、普通表格的行/列语义。表内行形成带表头的可定位文本单元 | 定位提取阅读视图中的段落/表行锚点，可打开原 DOCX。段落与表行共用该修订内从 1 开始的可见块序号 |
| XLSX | 按工作表和连续数据区域提取，保留列名、单位及行号，重复表头仅作上下文。公式仅采用文件中已有的可读缓存值，缺值显示未提供 | 显示工作表名与真实 A1 范围，如“参数表!B5:D8”。预览定位该范围并保留原工作簿入口 |
| 图片、纯扫描 PDF、旧 DOC/XLS 等附件 | 保留原件。维护者另写的说明作为独立正文来源 | 文件名命中打开原件，人工说明命中定位到说明段落。扫描件首期无 OCR |

每个原始块记录租户、项目、文档、修订、正文或附件标识、定位符、原始可见文字和摘要哈希。用于检索的规范化副本可折叠空白、统一大小写和全半角，引用摘录取原始可见文字。格式组件按 [PdfPig](../13A-Industrial%20Platform知识中心开发实施方案.md#pdf) 和 [Open XML SDK](../13A-Industrial%20Platform知识中心开发实施方案.md#word) 选型，工作簿的读取细节见 [XLSX](../13A-Industrial%20Platform知识中心开发实施方案.md#excel)。

## 4. 切块、建索引与回到原文

一个检索片段属于一个修订、一个来源。按标题和语义相近的段落装入片段，禁止跨附件、PDF 页或工作表。可从约 600 个可见字符/片段起测；过长段落按句拆，长表按行分，保留同一源块内的字符范围或原始单元格范围。步骤和前置条件尽量同行文展示。重复表头、标题路径和相邻上下文标记为检索辅助信息，引用时定位提供事实的原始行。此长度是调优起点。

索引至少保存 generation、profileVersion、chunkKey、所属文档/修订/附件、原始块有序列表及定位、供召回的文本和精确标识词。chunkKey 在同一修订、来源、代次内可重复生成。用户链接始终用稳定的文档/修订/来源/位置；重建检索引擎后仍能解析同一修订的来源。解析阅读视图按源修订与解析配置固定，有历史锚点的修订保留相应映射或凭摘录校验，无法核对则提示定位已变化。

首期以关键词倒排和标识词精确匹配作为可交付基线。规格建议中文连续文本生成相邻双字词候选，型号、版本、错误码另外保留完整 token，输入和索引使用同一规则，同时保留连字符原式。按租户、项目、权限、有效修订、适用范围过滤，再在候选中优先排序完整错误码/型号、标题短语、标签及正文命中。首选 [SQLite FTS5 与应用层分词](../13A-Industrial%20Platform知识中心开发实施方案.md#chinese)，标识词走[独立精确索引](../13A-Industrial%20Platform知识中心开发实施方案.md#codes)，权重、吞吐和发行兼容性用两种宿主实测。后续经批准的向量服务可以补充候选，合并去重后仍走相同版本、权限和来源校验。首期验收在关闭向量服务时也要完成。

## 5. 搜索页与知识问答共用一套证据

**搜原文。** 沿用 GET /knowledge 的 q、分类、标签、系统版本及分页。搜索同时查询可见文档元数据和已就绪片段，以文档去重并稳定排序。建议有 q 时增加 matches 数组，每条含命中类型、摘录、revisionNId 和可选 locator。只命中文件名时显示“文件名匹配”，正文命中才给段落/页/单元格位置；同一文档可展开其他命中。空结果保留原条件，允许去掉版本筛选或换关键词。已指定版本默认匹配 Listed 对应版本及 All；Unspecified 单列为可手动查看的“适用版本未注明”，不支持确定版本结论。

**问答案。** 助手通过已有 knowledge.search 以相同授权与过滤取得不超过其 limit 的证据，从中选取互补片段。服务端给本轮每条证据分配临时编号，并保存它与文档、修订、附件、原文坐标及摘录的对应关系。发送 DeepSeek 的内容只取本轮允许的文字及必要上下文。要求按事实或操作步骤返回答案和所依据的证据编号。平台生成最终的文档名、版本、定位链接与摘录。流式输出阶段显示“正在查证”，涉及具体操作的带出处答复在引用检查后展示。

**能点开与能佐证分开检查。** 返回前核对编号属于本轮候选、摘录来自指定位置、来源仍可读；错误码、数值、单位和版本等关键字面值对照证据。存在引用只说明位置有效。缺少支持结论的原文时删去该结论或提示证据不足，不让真实页码给猜测背书。多个来源冲突时分别列出依据，询问版本或表现差异。模型断线仍可展示授权搜索结果。每次打开引用或恢复会话再查当前指针和文件权限，变更或撤权时限制旧回答及原始摘录。引用对象沿用[页面规格 §2.3](PF10A-核心接口与页面规格.md#23-文件入口与引用定位)。

## 6. 两种部署用同一题集分别验收

测试前冻结资料摘要、适用范围、人工核对的原句/位置、测试账号、问题与预期行为。资料至少覆盖实际脱敏手册、同一错误码的两个版本、表格数值与单位、同名不同附件、纯扫描件、混合扫描页、损坏件、跨项目受限资料。准备一份用户可读但答案缺失的资料以验证拒答。模型答案允许换说法，位置、条件、步骤含义和单位须可从原文核实。

| 用例 | 两种部署都应观察到 | 平台内怎样验 | 独立部署怎样验 |
| --- | --- | --- | --- |
| K01 上传到可读 | 同批逐项进度，Clean 原件可打开，处理中可按名搜。无提取文本只展示已知元数据 | 从实际菜单用维护人上传，换只读用户打开，经平台 File 取票据 | 空环境本地登录，独立扫描引擎和文件卷办理全程。记录实际进程与出口 |
| K02 解析与定位 | TXT/MD/DOCX 的段落、PDF 物理页、XLSX 表头/单位/范围与人工真值一致。两附件都含“第1页”时分别命中正确附件 | 通过结果卡打开对应平台阅读页，核验原件哈希 | 在独立外壳按相同位置打开本地原件，原生平台地址保持不可达 |
| K03 搜索质量 | 错误码精确查询、中文现象查询、版本过滤分别留存前五结果和命中位置；同一问题两端满足相同质量门槛 | 用实际角色和当前项目记录搜索请求与命中 | 无 Studio、无 Embedding 重跑同一题集，记录使用的解析/索引配置 |
| K04 有依据的回答 | 逐条核对关键结论，冲突分列、无依据题明确说明；点击引用能核对原句 | 用项目 DeepSeek 配置走真实知识工具和模型，记录修订及回执 | 只开放已批准的模型出站，在本实例用相同题集核验。另测断开模型时仍可搜索与读原文 |
| K05 新修订和撤权 | 索引 A 晚于新版 B 完成，A 不回流；停用/撤权后搜索、问答、历史引用均不暴露失效片段 | 平台权限/文件状态改变后，用原账号重开引用 | 改本地角色或停用知识后复现相同请求。读取缓存也须重新鉴权 |
| K06 失败与恢复 | 重复任务不重复结果，损坏/超限/无文本原因可区分；暂存代次不能被召回 | 中断知识作业，按任务代次和审计确认恢复 | 解析中终止宿主再启动，以持久卷和数据库恢复。清空可重建索引后由权威修订重建并重跑 K02/K03 |

**拟定判据。** 各环境分别统计。固定错误码题的预期文档须入前 3；中文现象题建议至少 10 题，预期文档入前 5 的比例起点为 80%，现场资料冻结时确认。对已给出答案的题逐条人工核对每个关键结论与引用位置；引用错原件、错版本、错数值、无依据操作建议、撤权泄露均判该用例失败。同时统计可回答题中实际给出有依据答案的比例，建议起点为 80%，避免全靠拒答过关。无依据题不得给出确定步骤。单列索引耗时、查询及首答延迟、文件大小、题数、硬件与模型配置，实测后冻结性能目标。

每次记录安装模式、样本/查询编号、期望位置、实际排名/引用、截图或实际交互记录、操作/任务标识及失败原因。真实模型未接通时只记检索和协议验证。以上是设计判据，两种环境分别产生实测结果后才可登记通过。

详细选型和相关分册统一见[实施 13A 文末索引](../13A-Industrial%20Platform知识中心开发实施方案.md#details-map)。
