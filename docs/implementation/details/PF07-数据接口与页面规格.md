# PF07 数据字典、接口与页面规格

更新：2026-10-19；复核稿V1.3。对应[实施10](../10-Industrial%20Platform%20Scheduler%20Platform%20Health开发实施方案.md)。本稿按实际实现回写；设计前置已核验、开发完成，启动/页面返修与菜单图标已复验，用户已确认页面整体效果，整包继续待验收。实现、测试及未测边界见[实施证据](../../evidence/PF-07.md)。

## 1. 首版范围、类型与字段基组

### 1.1 收敛结果

首版保留任务管理、执行历史、健康概览三个PC页面，以及既有工作台健康摘要。一个任务配置一个Cron计划；人工触发单独创建运行。周期投递、队列、工作器、重试计时和尝试历史由一个所选引擎负责，业务层不再实现到期扫描器。

自有业务存储仅`scheduler_job`、`scheduler_run`两表。健康检查使用既有检查及受控适配，保留有界内存快照，不建业务健康表。原草案的Trigger/Attempt/Lease/Request表、健康三表及探针/异常页面均未实施，本版撤出首版；相关未来需求有实际场景后另行细化。原生存储已按固定包和实际元数据补齐[完整字段字典](PF07-Hangfire存储字段字典.md)，不能把“两张自有表”当成全部存储。

### 1.2 三Provider类型

自有表沿SystemData当前默认schema：PG为`current_schema()`、SQL Server为`dbo`、SQLite无schema；使用`scheduler_`前缀。LogicalDatabaseName仍为`systemdata_db`，实际库由DatabaseTopology解析。引擎schema/前缀按所选存储包单独登记，不移动既有表。

| 记号 | .NET / PG / SQLite / SQL Server | JSON与约束 |
| --- | --- | --- |
| id | Guid / uuid / TEXT / uniqueidentifier | 非空GUID字符串，应用签发 |
| key(n) | string / varchar(n) / TEXT / nvarchar(n) | string，长度≤n，标识无首尾空白；SQLite补length CHECK |
| text(n) | string / varchar(n) / TEXT / nvarchar(n) | 中文string，最大n字符 |
| bool | bool / boolean / INTEGER / bit | boolean；SQLite CHECK IN(0,1) |
| i32 | int / integer / INTEGER / int | JSON number，范围逐字段规定 |
| i64 | long / bigint / INTEGER / bigint | JSON十进制string，0～9223372036854775807 |
| time | DateTimeOffset / timestamptz / TEXT / datetimeoffset(7) | RFC3339 UTC；SQLite固定UTC文本并验证瞬时round-trip |
| json(n) | string持久化、DTO明确字段 / text / TEXT / nvarchar(max) | UTF-8对象≤n字节，应用验证，不直接回传引擎payload |

`?`可空，其他NOT NULL；“初值”由应用赋值，所有自有字段无数据库DEFAULT。标识使用PG C、SQLite BINARY、SQL Server BIN2比较；UTC比较共同精度取PG微秒。内部FK用Id和RESTRICT/NO ACTION，同租户在事务内另验。

## 2. 自有表、引擎存储与维护

```text
scheduler_job 1 ── N scheduler_run（普通FK，禁止级联删历史）
                       │
                       └·· EngineReference → 引擎任务/状态/尝试历史
                           （经引擎适配器读取，不跨表Repository）

运行占用：UQ(tenant_n_id, active_job_id) WHERE active_job_id IS NOT NULL
健康摘要：既有检查/受控来源 → 有界内存快照 → 查询/工作台；无健康业务表
审计事实：复用既有Audit；运行历史不充当操作审计
```

### 2.1 scheduler_job：任务与唯一周期计划

一行表示租户的一项业务任务及其唯一Cron计划。目标`SchedulerJob / SchedulerJobTable`；完整字段E+B+下表。管理员维护配置，引擎时间/状态不写回配置版本。

| 属性 / 物理列 | 类型 | 初值、中文语义与维护 |
| --- | --- | --- |
| Name / name | text(128) | 必填非空，页面显示名，可编辑 |
| Description / description | text(1000)? | 初NULL，用途说明，可编辑 |
| HandlerKey / handler_key | key(128) | 代码注册白名单键，创建后固定；不保存反射类名 |
| ParametersJson / parameters_json | json(16384) | 处理器明确DTO，首个处理器固定`{"schemaVersion":1}`；代码校验 |
| Status / status | key(32) | 初Disabled，控制未来周期触发与人工触发 |
| CronExpression / cron_expression | key(120) | 五字段周期，初`*/15 * * * *`；Disabled时可改 |
| TimeZoneId / time_zone_id | key(128) | 初Etc/UTC，保存IANA标识，部署OS须可解析 |
| TimeoutSeconds / timeout_seconds | i32 | 初300，5～3600且不超过处理器代码上限 |
| MaxAttempts / max_attempts | i32 | 初1，1～5含首次；NoAutomaticRecovery强制1 |
| RetrySafety / retry_safety | key(32) | 注册代码提供，管理员不可修改 |
| IsSystemOwned / is_system_owned | bool | 初false，bootstrap内建对账任务true，禁止删除/改Handler |

PK(id)，UQ(tenant_n_id,n_id)覆盖软删除；IX(tenant_n_id,status,is_deleted,name,n_id)供列表。不存NextFireOn/CursorVersion；下一次时间只从引擎查询。任务配置和运行分开，改配置不改已接受运行快照。删除须Disabled且无Queued/Running/RetryWaiting/CancelRequested/Unknown；恢复为Disabled。启停/修改通过现有可靠设施同步引擎，SyncState见§4，不把“配置已保存”显示成“引擎已生效”。

### 2.2 scheduler_run：逻辑执行与最小业务防重

一行表示引擎的一次周期调用或管理员一次触发；引擎自动重试仍属于同Run。实际模型`SchedulerRun / SchedulerRunTable`；完整字段T+下表。此表保存租户可查询的业务快照及执行资格，不另建Attempt/Lease/请求响应表。

| 属性 / 物理列 | 类型 | 初值、中文语义与维护 |
| --- | --- | --- |
| JobId / job_id | id | FK Job，同租户校验，用于历史关联 |
| Source / source | key(32) | Schedule/Manual/Retry，接受后固定 |
| InvocationKey / invocation_key | key(180) | 周期`engine:{引擎调用ID}`；人工/重试`request:{SHA-256(动作+操作者NId+请求key)}`，规范编码后生成稳定键，防重 |

| OriginalRunNId / original_run_n_id | key(128)? | Retry原运行引用，否则NULL，无历史FK |
| OperationKey / operation_key | key(128) | 初RunNId；安全重试沿原值，交业务处理器防重复副作用 |
| RequestedByUserNId / requested_by_user_n_id | key(128)? | 人工/重试可信操作者，周期NULL |
| AcceptedOn / accepted_on | time | 首次接受UTC，固定；不冒充计划应触发时间 |
| Status / status | key(32) | 初Queued，按§3.3修改 |

| TimeoutSeconds / timeout_seconds | i32 | 5～3600配置快照 |
| MaxAttempts / max_attempts | i32 | 1～5配置快照，引擎重试策略使用此值 |

| EngineReference / engine_reference | key(128)? | 初NULL，首次持久投递/实际进入时CAS绑定唯一原生调用；后续不同ID重复投递不执行，不能覆盖；通过引擎接口查询，不作API身份 |

PK(id)，UQ(tenant_n_id,n_id)，UQ(tenant_n_id,invocation_key)。活动槽索引：PG/SQLite与SQL Server均过滤UQ(tenant_n_id,active_job_id) WHERE active_job_id IS NOT NULL；CHECK active_job_id IS NULL OR active_job_id=job_id，非空时ExecutionToken/WorkerReference/DeadlineOn必须非空。该槽只补业务互斥缺口，不提供到期抢租/自动释放。IX(tenant_n_id,job_id,accepted_on,n_id)供历史，IX(tenant_n_id,status,id)供状态同步；FK(tenant_n_id,job_id)→Job(tenant_n_id,id)，RESTRICT/NO ACTION；Job补UQ(tenant_n_id,id)。

人工触发/重试同请求key只返回原Run身份和当前授权状态，不保存完整HTTP响应。Run保留90天，活跃及Unknown不清；清理每批最多200，只删可信终态且超过保留期的记录。请求防重在原Run保留期内有效，清理后旧key不得重用，前端对未确认的请求在当前页面保留同一key，成功确认后新的人工动作签发新key。原生尝试历史固定保留90天；Run可配置90～3650天，超过原生保留期的详情明确显示历史不可用。统一Audit沿既有保留/保全策略，本版不增设跨表保全联动。

### 2.3 已冻结的引擎物理字典与受控初始化

2026-10-12进入实施，冻结Hangfire.Core/SqlServer 1.8.25、Hangfire.PostgreSql 1.20.13、Hangfire.Storage.SQLite 0.4.3；PG依赖Npgsql 6.0.11，随数据库回归验证。PG/SQL Server原生存储关闭PrepareSchemaIfNecessary，受控迁移应用所选包原生脚本，引擎schema为scheduler_hangfire。SQLite 0.4.3没有关闭初始化的开关，物理表为Job/State/JobParameter/JobQueue/Server/List/Set/Hash/Counter/AggregatedCounter/DistributedLock，Prefix只作用逻辑数据。为避免共享业务库的通用表名冲突，SQLite引擎使用从业务库路径派生的独立`.scheduler.db`文件，同属systemdata受控初始化；初次建表仅初始化阶段执行，运行前逐表/列/索引校验，缺失拒绝启动，不由运行构造补建。SQLite仅开发/测试单机。[完整物理字典](PF07-Hangfire存储字段字典.md)已从实际安装脚本及三Provider隔离库元数据补齐，受控实现与PG/SQL2019真实验证见[PF07实施证据](../../evidence/PF-07.md)，不把单机探针扩大为全部Provider通过。

## 3. 配置、调度、执行与健康语义

### 3.1 配置与引擎同步

JobCreate以租户+NId唯一保证防重：与当前配置一致返回现有Job，内容不同409并提示读取；任务已被后续编辑时不承诺重放原始创建响应，不再创建第二项。更新用双版本和明确DTO；启停是设置目标状态，同状态返回当前值且不重复审计。实际变更与既有Audit/可靠同步记录同事务，无通用scheduler_request。保存返回JobDto，SyncState以当前原生元数据为准，待同步为Pending；可靠适配按最新Job配置执行原生AddOrUpdate/移除，重复投递按稳定引擎计划键幂等；旧配置同步不能覆盖新版本。DesiredVersion就是Job.OptimisticVersion，引擎计划元数据保存已应用版本；停用/删除后计划不存在时结合既有可靠记录确认该版本已处理。Applied须核对一致；原生查询失败为Unavailable及脱敏码，待处理版本为Pending，不另建同步表。同步元数据/公开方法及旧消息排序保障由G07-1/2冻结。

### 3.2 周期计划与首条处理器

首版每Job一个Cron，精度至少1分钟，使用数字、`* , - /`，解析和时区规则沿同一引擎/解析库，不手写日历。预览最多10条UTC/时区时间，配置无未来时点422。错过时点固定跳过，不提供补偿策略选择；必须由G07-1确认所选引擎原生选项及DST行为，不能自行维护LastScheduledOn/NextFireOn。现行Hangfire源码提供[错过处理选项](https://github.com/HangfireIO/Hangfire/blob/master/src/Hangfire.Core/MisfireHandlingMode.cs)，该资料不代替已选版本/Provider验证。

计划键由TenantNId+JobNId稳定构造，跨租户隔离；一次周期调用的业务Run以引擎调用ID防重。引擎多副本竞争是否产生同一逻辑时点的重复调用须实测，不用随机ID代替该证据。暂停/启用只影响未来触发，启用期间无需补停用时点。

首条真实处理器`systemdata.reconcile`，参数固定`{"schemaVersion":1}`，页面只读显示“权限与负责人快照对账”，无版本选择或动态JSON表单。租户来自上下文；抽取现有一次对账逻辑的按租户公开入口，不重复实现其业务规则。未证实重放幂等前RetrySafety=NoAutomaticRecovery、MaxAttempts=1；证明同OperationKey可安全重放后才开放重试。其他处理器未来通过代码注册及明确DTO/普通表单接入。

对账配置Mode只允许Legacy或Scheduler，默认升级仍Legacy。切换是部署操作，不提供进程内热切：先核对同库所有实例Mode一致，排空并确认所有旧模式执行已停止，再启动新模式；不能滚动混跑两种模式，无法确认停止时不切换。切Scheduler还须模块已启用且内建配置已生效；暂停任务不会静默回退Legacy，回退同样先排空。实际切换验证属于A19，不在本轮运行。

### 3.3 执行、互斥与重试权威

1. 人工Run与既有可靠投递/Audit同事务接受；提交前不调用Handler。接收新周期/人工Run须在短事务核验当前Job启用/未删除及租户，与配置停用/删除串行；已接受Run沿快照执行，后来停用不冒充取消。重复投递仍带相同RunNId。周期由原生引擎持久入队，固定包装入口首次进入时按原生调用ID建立Run，再取得执行资格；周期排队期间由原生队列管理，业务Queued投影从包装入口建立，人工运行在请求接受时建立。两者以InvocationKey防重，不新增原生回调投影框架。
2. 原生调用ID首次通过EngineReference CAS绑定Run，同Run不同ID的重复引擎任务只短路，不进入Handler或增加尝试；回执迟到不能换绑定。引擎负责工作器领取、重试计时与尝试历史。包装入口在短事务内CAS取得Run资格、占用ActiveJobId、签发ExecutionToken并增加AttemptsUsed；重复/终态调用不再执行。同Job其他运行占用时本次保持Queued，由引擎原生延后策略处理，不计业务尝试、不另写队列轮询器；延后不消耗业务重试次数的原生映射是G07-1必核项。
3. Handler在事务外执行。结果写回匹配Tenant/Run/ExecutionToken，并读取当前允许状态后以当前StateVersion做CAS；取消命令推进版本不应阻止同一实际执行提交可信结束结果。旧token回包不覆盖新资格。已知结束才释放ActiveJobId。这个数据库保护不能阻止旧进程继续调用外部设备；业务副作用必须由处理器自己的事务/OperationKey保证。
4. 自动重试仅限Idempotent且已知失败、已停止的尝试；MaxAttempts包含首次，由引擎同一个重试策略约束。RetryWaiting和尝试详情从引擎状态转换映射，业务层不计算指数延迟或另建Attempt表。未知结果及取消/超时未确认停止禁止自动重投；引擎重启重投也必须经过业务资格校验，AttemptsUsed不可超限。
5. 状态适配消费引擎公开转换/工作器事实，修复缺失投影须幂等；不自行建失联租约服务。引擎处理器丢失但业务槽仍占用时显示Unknown并保持槽，不能因原生锁已释放继续执行。状态/历史暂时无法读取时显示查询错误，不推测成功。

| 转移 | 条件与槽处理 |
| --- | --- |
| Queued → Running | 取得本Job活动槽，签发执行token；并发竞争失败不执行 |
| Running → RetryWaiting | 已知可重试失败且旧尝试已停止，释放槽；引擎安排下一次 |
| RetryWaiting → Running | 引擎再次进入，重新验证资格/次数并取得槽 |
| Queued/RetryWaiting → Cancelled | 后端确认没有正在执行的Handler，后续投递入口仍拒绝 |
| Running → CancelRequested | 记录请求，通过适配传合作取消；槽保持 |
| Running/CancelRequested → Succeeded/Failed/Cancelled/TimedOut | 处理器可信结果且已结束；槽释放；已经成功不能改为取消 |
| Running/CancelRequested → Unknown | 失联或无法确认停止/提交，槽保持，不再自动执行 |
| Unknown → Succeeded/Failed | §3.4授权核对，事实与Audit同事务，确认可释放才清槽 |

取消/截止不是强杀线程；TimedOut仅在确认处理器停止且未成功时成立。期限到达请求合作取消，若无法确认停止则Unknown。Running只有支持合作取消的Handler才开放canCancel；Queued/RetryWaiting可请求取消。Unknown后的迟到结果只作核对证据，不自动改终态/释放槽；详情中其completedOn使用“结果未知判定时间”标签，不显示为实际完成时间。AttemptDto完全来自已选引擎公开接口，缺失历史返回availability=Unavailable，不能凭AttemptsUsed生成假尝试记录。[Hangfire官方](https://docs.hangfire.io/en/latest/background-processing/throttling.html)说明锁依赖连接、不能单独保证副作用只执行一次，这是保留最小业务保护的依据。

### 3.4 人工触发、重试与未知结果

人工触发及重试须Idempotency-Key（1～128字符），稳定key+命令hash落Run；先核验当前身份/权限及已存在InvocationKey，同hash返回原Run，不因原命令版本已推进而拒绝重放；不同hash409。新命令才检查当前版本与合法状态。手工重试仅Failed/TimedOut且处理器Idempotent、原进程已停止；创建新Run并沿OperationKey、原参数和来源引用，不修改旧事实。请求hash包含动作、目标NId与规范化命令字段，不复制敏感参数。

Unknown核对要求stateVersion、decision=`ConfirmedSucceeded | ConfirmedFailed | ConfirmedNoEffect`、reason(10～1000字符)、evidenceReference(1～256字符)。须确认旧执行已停止且不会继续产生副作用，并核对业务结果；只看到某个结果不等于旧执行已停止，未确认409，不能“强制解锁”。ConfirmedNoEffect映射Failed/RESULT_VERIFIED_NO_EFFECT；成功/失败映射对应终态，核对结果记既有Audit。原尝试在引擎历史中仍是当时事实。Unknown不能直接重试，核对完成后仍按处理器安全条件决定是否可重试。

### 3.5 健康来源、快照与聚合

PlatformHealth用独立BackgroundService及现有HealthCheck/只读适配，初始快照Unknown。检查目标/启用状态来自部署受控配置及服务目录校验，管理员不能添加任意URL；固定间隔/超时/并发见§1.3。HTTP不跟随重定向、响应有大小上限；本地来源不递归调用本聚合器。各副本可以独立做只读检查，不争数据库采样槽，不要求同一时点只发一次请求。

每项快照含serviceNId、capabilityKey、criticality、reportedState、effectiveState、checkedOn?、receivedOn?、reasonCode?、reasonSummary?、traceId?、sourceTraceId?。checkedOn由真实本地检查或来源合同提供；来源没有时间则NULL/Unknown，不用接收时间假造。traceId是聚合检查实际trace，sourceTraceId来源未给则NULL。每轮结果带本轮序号，超时/迟到结果不能覆盖新快照；存储每项最新结果，无历史表/异常阈值状态机。

| 条件 | 查询结果 |
| --- | --- |
| 已配置但未完成/来源合同缺时间 | Unknown，分别NOT_SAMPLED/SOURCE_TIME_MISSING |
| 距min(checkedOn,receivedOn)>90秒或来源时间超前>5秒 | Unknown，STALE_OBSERVATION/SOURCE_CLOCK_SKEW；保留reportedState与真实时间 |
| 能力未启用 | Disabled，既不是Healthy，也不是“检查失败后恢复” |
| 必需依赖故障 / 可选能力故障 | 沿来源合同分别Unavailable/Degraded，不能仅凭HTTP200全绿 |
| 来源无适配/旧阶段未实测能力 | Unknown或来源明确Degraded，如SCAN_BYPASSED；不推断业务验收通过 |
| 进程重启/快照不可用 | Unknown或当前查询503，不用持久化旧绿状态 |

聚合规则：模块或服务显式关闭→Disabled；已启用但无启用检查→Unknown；Required Unavailable→Unavailable；Required Unknown/Disabled→Unknown；任一启用项Degraded或Capability Unavailable/Unknown→Degraded；其余有效启用项Healthy→Healthy。Disabled独立计数；停用可选能力不伪装成健康。lastObservedOn取启用项中最旧有效检查时点，任何启用项尚无时间则NULL，不用generatedOn代替检查时间。工作台与概览调用同一授权过滤/聚合逻辑。只读采样与日志/指标不逐次产生业务Audit。

### 4.3 公开契约与既有审计入口

处理器公开接口`IScheduledTaskHandler.ExecuteAsync(TaskExecutionContext,CancellationToken)`，注册目录由部署代码DI提供；TaskExecutionContext字段TenantNId/JobNId/RunNId/OperationKey/Parameters/DeadlineOn/TraceId，不加入尚无处理器支持的通用fencing/外部结果对账协议。TaskResult字段Outcome=Succeeded/Failed/Cancelled/Unknown、ResultCode、Summary、Retryable:bool；Unknown必须false，安全性由处理器代码保证。引擎适配提供计划同步/预览、投递、状态/尝试读取、合作取消；准确方法签名/原生接口映射由G07-1冻结，不额外抽象通用插件框架。

健康公开查询`IPlatformHealthQuery.GetSummaryAsync(scope)`；受控Adapter读取现有HealthCheck或来源摘要，返回State/CheckedOn?/ReasonCode?/ReasonSummary?/SourceTraceId?。同宿主使用进程内接口，跨宿主使用白名单只读端点；不跨Repository，不能把服务目录URL直接当探测授权。

既有审计保持两个入口：Identity登录审计`/pc/identity/audits`；PF04统一审计查询`/pc/systemdata/audits`（权限systemdata.audit.read）。PF07创建/编辑/启停/删除恢复/人工触发/取消/重试/未知结果核对复用后者，无第三个审计模块或独立审计表。

每项实际写入AuditFactV1：TenantNId、ProducerServiceKey=systemdata、稳定AuditEventNId、OccurredOn、ActorUserNId、Action、ObjectType、ObjectNId、脱敏PayloadJson、TraceId、Severity；ReceivedOn由接收方赋值。Action使用scheduler.job.* / scheduler.run.*；Payload只含受控变更摘要、RunNId/JobNId/OperationKey引用及处置依据，不复制原参数/凭据。成功关键写与既有可靠审计同事务，拒绝沿既有失败路径；具体适配由G07-2定位。执行结果看“执行历史”，操作者改了什么看“审计查询”，只读健康刷新不逐条审计。
