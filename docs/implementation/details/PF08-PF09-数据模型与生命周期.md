版本：V1.0；日期：2026-10-21。设计合同，尚未实施。与实施11/12共同作为开发输入；业务字段和生命周期按本文，接口及配置结构见[接口与配置](PF08-PF09-接口与配置合同.md)，页面与测试见[页面与验收](PF08-PF09-页面与验收规格.md)。

## 1. 工程与所有权

新增目录 `src/backend/src/Services/PlatformStudio/`，工程名统一为 `IndustrialPlatform.PlatformStudio.{Contracts,Domain,Application,Infrastructure,Api}`；可执行宿主 `src/backend/src/Hosts/IndustrialPlatform.PlatformStudio.Service/`。UnifiedHost装配相同Application/Infrastructure/Api，不复制业务实现。Contracts内按Data、Publishing、LowCode、Dashboard、Report、Traceability分目录；Application同名目录放命令、查询和运行器。Publishing持有资源元数据及修订仓储，各模块通过 `IStudioResourceStore` 应用端口读写并注册本模块文档验证器，不直接调用其他模块Repository。

前端新增 `src/frontend/src/pages/pc/studio/{lowCode,dashboard,report,traceability,shared}`、`src/frontend/src/api/studio`、`src/frontend/src/components/studio`；现有管理组件保留。后端测试 `src/backend/tests/PlatformStudio/IndustrialPlatform.PlatformStudio.Tests/`，真实集成沿现有IntegrationTests工程；前端就近 `.spec.ts`，浏览器用现有Playwright项目。首次实现将新工程登记到slnx，不更改现有包版本以迁就候选。

统一初始化：ServiceKey=`platform-studio`，ModuleKey=`studio-core`，LogicalDatabaseName=`platformstudio_db`，PG schema=`platform_studio`；SQL Server schema=`dbo`；SQLite独立文件由拓扑解析。ModuleKey是具名持久化单元，不代表只初始化LowCode。Domain Module归属在验证器、表和代码边界表达，普通模块不另建账本。

四种文档模块共用版本机制，避免四套发布器；**不建通用任意对象数据库**。可注册的资源种类固定：`Dataset/LowCodePage/LedgerModel/Dashboard/Playlist/Report/ReportBundle/TraceModel`。ReportBundle的组合类型不可运行时切换。代码扩展Action/Component注册表由代码白名单提供，不存在上传DLL/脚本安装接口。

## 2. 类型、通用列及约束

表中列名为物理snake_case，DTO为camelCase，C#为PascalCase。`?`可空；未标`?`均NOT NULL；默认值由应用创建时显式填入，不用数据库默认时间。字符串按Unicode字符数限制，JSON另按UTF-8字节限制。所有时间UTC，ISO8601带Z；真实SQLite往返必须验证。

| 代号 | C# / JSON | PostgreSQL / SQLite / SQL Server | 限制 |
| --- | --- | --- | --- |
| id | Guid / GUID字符串 | uuid / TEXT / uniqueidentifier | 非空GUID，物理主键不供用户编辑 |
| key(n) | string / string | varchar(n) / TEXT / nvarchar(n) | 业务标识，Ordinal比较；SQLite加length检查；SQL Server标识列用BIN2排序规则 |
| text(n) | string / string | varchar(n) / TEXT / nvarchar(n) | 中文显示名、说明 |
| json(n) | string持久化 / 结构化JSON | text / TEXT / nvarchar(max) | n为KiB上限，应用校验结构与大小；不是任意扩展字段包 |
| flag | bool / boolean | boolean / INTEGER / bit | SQLite只允许0/1 |
| i32 | int / number | integer / INTEGER / int | 明确下界/上界，不能存版本 |
| i64 | long / 十进制字符串 | bigint / INTEGER / bigint | 0～9223372036854775807，禁止JS Number中转 |
| time | DateTimeOffset / RFC3339 | timestamptz / UTC TEXT / datetimeoffset(7) | 时间点比较，PG微秒精度 |
| sha | string / string | varchar(64) / TEXT / varchar(64) | 小写SHA-256十六进制 |

**E基类列**（对齐现有Entity）：`id:id PK`、`is_frozen:flag=false`、`is_locked:flag=false`、`is_deleted:flag=false`、`entity_type:text(512)`、`created_on:time`、`last_updated_on:time`、`optimistic_version:i64=0`、`concurrency_version:id=新GUID`。实际修改同时递增版本/重生令牌并更新时间；无变化幂等不递增。普通修改同时校验冻结、锁定、删除。

**B业务列**：`n_id:key(128)`、`tenant_n_id:key(128)`。UQ(tenant_n_id,n_id)，软删仍保留唯一性，不复用编号。租户只来自可信上下文。

**T技术记录列**：`id:id PK`、`n_id:key(128)`（服务生成）、`tenant_n_id:key(128)`、`created_on:time`；同样UQ(tenant_n_id,n_id)。T不继承可编辑实体的冻结/删除状态。不可变记录禁止UPDATE/DELETE，依法保留清理另行授权实现。

同库外键均`ON DELETE RESTRICT`，写入同事务检查父子tenant一致；不建立跨服务数据库外键。下文FK指Id；对外用NId。所有索引名称采用`ix_st_<短表>_<用途>`/`uq_st_<短表>_<用途>`，ASCII不超过63字节。枚举持久化key(32)，CHECK白名单；复合CHECK使用表级约束。所有表名固定，不由页面名称拼SQL。

## 3. PF08表字典

### 3.1 studio_source（DataSource，E+B）

| 字段 | 类型 / 默认 | 含义、来源与修改时机 |
| --- | --- | --- |
| name | text(128) | 工程师配置显示名 |
| description | text(1000)? / null | 来源用途说明 |
| provider | key(32) | RegisteredApi/PostgreSQL/SqlServer/Sqlite，创建后不能改变 |
| endpoint_key | key(128) | 指向服务端部署配置的连接/受信API登记键，不存明文地址与凭据 |
| credential_ref | key(256)? | 服务端秘密库引用；API不回传，页面仅显示credentialConfigured |
| catalog_key | key(128)? | 受控库catalog，库来源必填；API来源为空 |
| allowed_objects_json | json(64) / [] | 允许视图/过程/已登记操作名列表，每项kind+qualifiedName；不允许通配全库 |
| is_enabled | flag / false | 受权管理员验证后启用；禁用立即阻止新取数 |
| configuration_version | i64 / 1 | 非秘密语义配置修改递增；凭据轮换不递增 |
| timeout_seconds | i32 / 30 | 1～120，执行取来源与Dataset较小值 |
| max_rows | i32 / 10000 | 1～100000；来源允许总行数，嵌套集合计入 |
| max_bytes | i64 / 10485760 | 响应上限，最大52428800 |

额外索引(tenant_n_id,provider,is_enabled)。不持久化“健康=true”；连通测试结果有checkedOn及配置版本，修改来源即失效。endpoint_key内容改变属于配置部署变更，必须推进configuration_version，禁止偷偷把原键换成另一业务库。

### 3.2 studio_resource（Publishing，E+B）

| 字段 | 类型 / 默认 | 含义与修改时机 |
| --- | --- | --- |
| kind | key(32) | §1资源种类，创建后不可改 |
| name | text(128) | 显示名称 |
| description | text(1000)? | 说明 |
| folder | text(256)? | 展示分组路径，不参与授权 |
| document_schema_version | i32 / 1 | 配置JSON结构版本；迁移器显式升级 |
| draft_json | json(2048) | 所属kind的完整配置，详见接口与配置；每次保存验证 |
| draft_base_revision_id | id? FK revision / null | 本草稿起于哪版，便于冲突比较 |
| published_revision_id | id? FK revision / null | 当前发布指向，只能通过发布/回退事务修改 |
| revision_sequence | i64 / 0 | 分配递增不可复用修订号；发布事务递增 |
| is_enabled | flag / false | 新建不可运行，首次发布可显式启用；禁用不删除历史 |
| owner_user_n_id | key(128) | 当前负责人，创建来自操作者；转交有审计 |

索引(tenant_n_id,kind,is_deleted,last_updated_on,id)。循环FK在revision表建好后添加；SQLite在建表时声明。published/base必须指向自己的revision。无第二个发布状态字段：未发布/已发布/已停用由指向及enabled导出，存在草稿改动由内容hash比较导出。

### 3.3 studio_revision（Publishing，T，不可变）

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| resource_id | id FK resource | 所属资源 |
| revision_no | i64 | 资源内部版本号，UQ(resource_id,revision_no) |
| document_schema_version | i32 | 该版文档解释版本 |
| document_json | json(2048) | 完整规范化配置副本 |
| dependencies_json | json(512) | [{resourceNId,revisionNId,contentHash}]；含递归依赖闭包，已去重排序 |
| source_pins_json | json(64) | [{sourceNId,configurationVersion}]；来源被改后拒绝静默运行旧合同 |
| content_hash | sha | 规范化文档+依赖+来源版本SHA256，UTF-8、序号排序、无无关空白 |
| published_by | key(128) | 可信操作者 |
| release_note | text(1000) | 本次发布说明 |

唯一修订内禁止依赖循环（LedgerModel不能引用Page；ReportBundle不能引用自身）；应用端口检查所有依赖租户、访问权、类型和已发布状态。文件资源依赖另含fileNId+sha256，不能指向变化中的工作副本。

### 3.4 studio_grant（Publishing，T）

字段：`resource_id:id FK resource`、`subject_kind:key(16)=User/Role`、`subject_n_id:key(128)`、`capability:key(16)=View/Design/Publish/Run/Export`、`revoked_on:time?`、`granted_by:key(128)`。UQ(resource_id,subject_kind,subject_n_id,capability)；撤销后原行重新授权可清revoked_on并审计。索引(tenant_n_id,subject_kind,subject_n_id)。资源授权与平台功能权限取交集；负责人不自动绕过平台权限；有效角色使用Identity现有组继承结果。不在grant放SQL过滤片段；数据行列授权沿数据合同服务器策略。

### 3.5 studio_ledger_record（LowCode，E+B）

字段：`model_resource_id:id FK resource`（必须LedgerModel）、`schema_revision_id:id FK revision`（写入所用模型版）、`values_json:json(256)`（按稳定fieldId保存值）、`created_by:key(128)`、`last_updated_by:key(128)`。索引(tenant_n_id,model_resource_id,is_deleted,created_on,id)。编号由调用者或登记编码规则生成；与客户库存/工单标识分离。

**明确选择：固定记录表+类型索引，不按客户字段动态DDL，不用ReferenceData存记录。** JSON为完整值真源，索引只为筛选/排序/唯一约束服务，必须同事务更新。附件值存File引用而非路径。不能持久化外来任意字段。

### 3.6 studio_ledger_value（LowCode，类型索引）

字段：`record_id:id FK record`、`tenant_n_id:key(128)`、`model_resource_id:id FK resource`、`field_id:key(64)`、`value_kind:key(16)`、`text_value:text(512)?`、`number_scaled:bigint?`（C#long，JSON不直接输出）、`bool_value:flag?`、`time_value:time?`、`unique_key:sha?`。PK(record_id,field_id)。只保存已声明queryable/sortable/unique字段；缺失/null不建行。CHECK：value_kind对应且只有一个值列非空。Decimal统一6位缩放，允许±999999999999.999999；输入超精度报错，不四舍五入；SQLite不转REAL比较。

索引(tenant_n_id,model_resource_id,field_id,text_value,record_id)、同number_scaled/time_value/bool_value；唯一索引(tenant_n_id,model_resource_id,field_id,unique_key) WHERE unique_key IS NOT NULL（三Provider分别生成）。unique_key=类型+规范化值SHA256；遇hash同但原值不同拒绝并报诊断，不当作同值。唯一字符串默认区分大小写，忽略首尾空白；模型显式caseInsensitive时用Invariant大写生成键。软删记录删除索引；恢复重建，冲突返回409。

### 3.7 studio_operation_receipt（LowCode/集成，T）

字段：`operation_key:key(128)`、`actor_user_n_id:key(128)`、`operation_kind:key(64)`、`resource_n_id:key(128)`、`request_hash:sha`、`status:key(32)=Pending/Succeeded/Failed/Unknown`、`response_json:json(64)?`、`external_reference:key(256)?`、`error_code:key(64)?`、`completed_on:time?`。UQ(tenant_n_id,operation_kind,operation_key)。记录台账创建、外部业务动作、报告提交、工作簿保存的防重结果；长运行自身状态另存run。相同键不同hash报409；Pending/Unknown不可重放有副作用调用。完成记录保留90天，清理窗口后的客户端禁止重用键；Unknown不能定时清理。

### 3.8 studio_audit_outbox（宿主级技术表）

字段：T + `module_key:key(32)`、`audit_event_n_id:key(128)`、`payload_json:json(64)`（AuditFactIngestRequest白名单）、`status:key(16)=Pending/Sent`、`attempt_count:i32=0`、`next_attempt_on:time`、`sent_on:time?`、`last_error_code:key(64)?`。UQ(tenant_n_id,audit_event_n_id)，索引(status,next_attempt_on,id)。与发布、写台账、权限、动作受理等本地事务同写；统一Audit接收端按事件ID幂等。只为可靠审计投递，不新建审计查询入口。送达30天后可清理；payload不存HTML全文、数据源凭据或行数据全文。

## 5. 事务、状态与恢复

| 操作 | 原子范围及失败规则 |
| --- | --- |
| 保存草稿 | 校验Schema和引用语法→对resource双版本CAS→写draft+审计；草稿允许未就绪绑定，但诊断必须随保存回传，发布禁止错误级诊断 |
| 发布 | 在事务内锁资源/校验当前版本、所有依赖及来源版本→分配revision_no→插不可变revision→切published指向/更新草稿基版→审计；任一步失败无半发布。幂等键重复返回同版 |
| 回退 | 指定本资源历史revisionNId，重新验证权限/来源仍可用→CAS改指向+审计；不改历史revision、台账值或业务事实；不自动覆盖未保存草稿 |
| 停用/恢复 | 停用阻止新运行；已受理报告仍按冻结合同且重验授权。资源恢复默认disabled，需显式启用。被引用资源软删阻止新发布，不物理级联删依赖 |
| 台账增改删 | 先按已发布模型验证→record及value索引、receipt、outbox同事务；并发以旧版本CAS；外部File绑定先准备引用，失败可重试/回收，不能跨库伪事务 |
| 台账模型升级 | 加可空字段/显示名变更兼容；新增字段默认值只影响新记录，旧记录保持null。删除用retired保留旧值。有既存记录时新增必填、改变类型/精度/唯一性均判不兼容，发布409 MODEL_SCHEMA_INCOMPATIBLE，给出受影响字段/记录数；首版不自动重写既有台账数据。应新建模型并按独立受控的数据迁移工作处理，不能让开发在发布时暗自补值；空台账可直接改约束。修订回退也重新检查当前数据兼容性 |
| 业务动作 | 先落Pending receipt→调用登记端口→确定结果落Succeeded/Failed；网络不确定落Unknown并禁止自动重发。只可查询业务端operationKey确认结果，不能把超时当未执行 |
| 报告生成 | receipt+PendingDispatch run同本地事务→向Scheduler幂等受理→登记run映射；网络断开按operationKey查询接收结果。取数快照及资源清单固定后才分页；文件上传/扫描/绑定成功后事务登记artifact并成功。孤儿临时文件由明确引用超时回收 |
| 取消/故障 | Queued可确认取消；Running只变CancelRequested，收到执行结束确认后Cancelled。进程失联、到期不确定=Unknown，保留PF07活动槽；健康恢复不表示旧执行停止 |
| Excel保存 | 校验会话/锁/权限/base→File临时上传、扫描、引用确认→CAS当前指向并插version+receipt+审计；并发冲突409，保留恢复副本7天可另存；重试同key返回原版本 |

报告首次数据采集完成生成DataSnapshot；同run重排版读取快照，不重新查变动源。对无历史/一致性快照能力的跨系统来源，manifest标记`consistency=ObservedAtDifferentTimes`并列每次observedOn；禁止写成一个精确业务时点。再次取数生成新run及operationKey。

## 6. 初始化、升级与运行配置

迁移产物：PF08为`studio-core-schema-v1`，含 `STU-001-Resources`（source/resource/revision/grant）、`STU-002-Ledger`（record/value/receipt）、`STU-003-AuditOutbox`；PF09升级为`studio-core-schema-v2`，保留前3步原文和checksum，再追加`STU-004-Report`（run/artifact）、`STU-005-Workbook`。不得为了分部交付先应用005再回头补003。Provider脚本分开，首次提交后不可修改旧checksum；后续一律追加迁移。schema/seed账本沿服务初始化框架创建，不另命名私有账本。Manifest的RequestedVersion随实际交付v1/v2变化，不提前把未实现PF09标已迁移。

SeedSet：`studio.core.baseline` v1（SystemBaseline，权限/组件注册映射）、`studio.navigation` v1（TenantBaseline，四菜单/公共设置动作）、`studio.examples` v1（EnvironmentSample，仅Development/Test）；初始化Manifest只传产物引用/hash/版本，不传SQL、连接串或Secret。最小账号分migration与runtime，runtime不具DDL/建库权限。新增种子升级必须同时更新清单目标及旧库一致性种子；保留旧账本验证失败重启与重复启动。

配置绑定 `PlatformStudio`：`Enabled=false`、`ExecutionMode=InProcess/Remote`、`RendererEndpointKey`、`OfficeProviderKey`、`SourceRegistry`（服务器秘密配置）、`DefaultQueryTimeoutSeconds=30`、`MaxQueryConcurrencyPerTenant=8`（每来源执行进程）、`MaxReportConcurrency=2`（渲染入口总并发）、`ReportTimeoutSeconds=300`、`TraceTimeoutSeconds=30`。首版单个受控Renderer入口集中排队，最多2个渲染worker；不能在每个API进程各开2个又宣称全局2。渲染入口失联保留Unknown，不自动起第二入口接同一运行。配置型上限允许运维收紧，不能让普通模板提权增大。初始化拓扑与连接全部从当前有效配置解析，文档不固定端口。

平台原生装配依赖现有Identity/SystemData；独立装配使用相同模块的精简宿主，仍含登录/权限、File/Audit/初始化及Scheduler能力，不要求MES或Collaboration启动。不另建身份产品。Renderer/Office可独立进程，但不变成新的核心领域Host。支持范围继承平台，禁止因为引擎只在Linux验证就宣布Windows不支持。

readiness拆数据库迁移、身份、File、Scheduler、Renderer、Office和必需来源；各项`status/checkedOn/receivedOn/reasonCode`。摘要`generatedOn`只表示组装时刻；来源超过60秒默认Stale，缺检测Unknown，不用网页轮询刷新旧来源。Scheduler.Enabled与ReconciliationMode分别检查，不自动切换或开启第二个对账入口。

`EnabledModules`明确列出已装配的LowCode/Dashboard/Report/Traceability，PF08首次交付仅LowCode；后续每部分验收后按部署配置开启。未装配模块不能创建/发布其kind，菜单不显示假可用入口。coreReady只判断共同存储、初始化和身份；模块按所需能力判断可用性：LowCode/看板/追溯查询不依赖Office或报告Renderer，PDF依赖Renderer和File，工作簿编辑依赖Office和File。某可选能力故障给对应操作503与降级状态，不把全部低代码停掉；正式整套交付验收仍须四部分和Excel全部通过，不能用禁用模块绕过范围。

## 7. 交付与不变量

服务端始终重验租户、功能权限、资源授权与数据范围；前端隐藏不是授权。运行合同仅引用不可变版本；Designer不持有DB凭据。Dataset不允许对平台业务库跨模块取Repository，外部MES受控只读连接是明确登记的集成边界。

PF08表结构属于001～005；PF09运行/工作簿属于009/010。上线前数据库三Provider必须真实DDL、索引、事务回滚、UTC/decimal/大版本往返，8路SqlSugar异步上下文隔离通过；迁移构造器不访问Ado/CurrentConnectionConfig。旧证据只复用未受影响部分，设计完成不等于这些检查已执行。
