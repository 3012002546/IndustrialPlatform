# PF-10A 全局助手与资料复用

V0.4 · 2026-11-18 · 已确认的业务交互与行为扩展设计

## 知识中心的使用顺序

主线是收资料、查原文、带引用问答。维护人选一个或多个文件，上传完成且 File 确认可读后，后台按项创建当前有效修订并开始索引。标题默认取文件名，分类和适用版本可以留空。页面分别显示“已入库，可以查看原件”“正在解析”“可用于问答”或“需处理”。不可提取的扫描件仍可按文件名搜索和打开。未注明版本的资料可以被检索，回答具体版本的问题时必须标明适用性未知。修订替换、停用和撤权即时影响读取和引用。手写资料可暂存草稿或直接收录。项目内查看和维护两类知识权限足够。

经验整理与项目迁移属于辅助功能。问题处理人员可预览准备收录的现象、方案及所选附件，一次确认后系统完成绑定并收录。用户也能直接在资料列表选择文档或分类导出 ZIP。导出包含所选有效版本的文件、正文和 UTF-8 manifest（格式版本、稳定来源标识、源修订、展示名称、分类、标签、适用范围、文件路径和 SHA-256）。目标项目由维护者预览合并。以来源实例＋原项目＋原文档稳定标识匹配，用内容摘要判断是否相同，保留沿途来源以支持重复迁移。新增项默认导入，完全相同的跳过，有本地修改或同名异源时供用户选择另存、跳过或明确替换成新修订。导入重新授权、校验清单与文件、生成目标项目自己的引用并建索引。每项有结果并可重试。问题私密时间线、聊天、用户记录及访问凭据均留在原项目。知识 ZIP 与业务表 XLSX 在界面上分别称为“导出资料包”和“导出表格”。

## 从日常用语到可用结果

面板沿用主界面的语言、时区、登录身份和当前筛选。空会话提供“问项目资料”“查业务数据”“打开页面”三个示例入口，也可直接输入句子。有唯一可执行解释就执行。需要选择时，只问一个影响结果的问题，候选用按钮显示，保留已填条件。结果摘要先说查到了什么或哪里需要处理，明细按需展开。

| 用户的话 | 助手如何行动 | 用户看到的结果和后续操作 |
| --- | --- | --- |
| 帮我列出本月的生产工单信息 | 从当前授权的业务目录匹配“生产工单”及已登记别名，读取项目配置的默认日期口径，把本月换算为项目时区的本月一日零时到下月一日零时的半开区间。交给绑定的 Dataset 修订或登记的只读 API 执行。若“创建日期”和“计划开工日期”都合理且无默认值，只问用户选哪一个。 | 条件条显示项目、日期口径、实际日期区间及数据截至时间，下面是分页表格。列按源提供，典型为工单号、产品、计划量、状态。可点“只看未完工”“打开工单”“导出本次结果”。无匹配显示 0 条，源不可用显示具体原因。 |
| 帮我打开工单页面 | 在当前有权菜单中匹配名称、别名和终端。唯一匹配直接导航，重名则列“生产管理 / 工单列表”等完整菜单路径。未保存编辑沿用现有离开提示。 | 目标页确认到达后提示“已打开工单列表”。若请求带“仅看未完工”，收到筛选生效回执后才显示该条件。用户取消离开则保持当前页。 |
| 帮我导出一份用户数据 | 当前业务语境唯一指向平台用户时，按调用者在 Identity 中的范围生成 XLSX。优先沿用当前用户列表筛选，其他页面使用已登记的默认范围并展示。若现场还登记了客户用户目录且语境无法区分，提供两个名称供选择。 | 卡片写明来源、筛选、列和数量上限。默认列建议登录名、姓名、状态。文件完整生成后显示“下载用户.xlsx”。可接着说“只要启用的”，沿用用户目录并更新条件。 |
| 把刚才那张表导出来 | 从上条表格卡读取 resultNId，导出当时的范围和排序。快照到期需由用户选择重新查询。 | 文件卡标出数据截至时间和实际导出范围。“导出刚才工单”与“新导出一份当前用户目录”分别绑定各自的数据。 |

业务目录由项目绑定，登记业务名称、别名、数据源及修订、日期字段/默认口径、可筛选字段、展示列、支持动作和实际权限。查找只返回当前用户可见项。一个名称没有绑定时提示“当前项目尚未接入生产工单数据”，有权限的人可打开配置。前端只传页面标识及白名单筛选值。数据执行方负责行列权限，助手不接收连接串，也不从名称拼接 SQL 或 URL。

用户目录已经具备 Identity 所属的 `GET /odata/users/export`。控制器使用 `PermissionPolicies.UserView` 与当前租户，校验 columns、quantity、culture、timeZone 后流式输出工作簿。助手拟通过登记的适配器传递调用者身份，使用助手允许的列与显式数量，照实展示租户范围。若项目要求比租户更窄的范围，适配器须能表达并执行该限制才可启用。文件流完整结束且校验为可读工作簿后才交付，失败可在卡片重试。若宿主启用独立导出策略也同时校验。明细和下载票据始终在平台内交付，模型仅接收任务状态和必要摘要。[现有导出实现](../../../src/backend/src/Services/Identity/IndustrialPlatform.Identity.Api/Controllers/UsersODataController.cs)

## 新行为怎样接入助手

行为目录按当前部署装配。平台原生业务行为绑定平台数据、身份和平台页面。独立模式内置知识搜索、问题草稿和自身页面导航，接入既有 MES 时由该项目重定义业务语义、权限、提供方及前端回执，再启用匹配项。例如“导出用户”只有在该宿主提供允许的目录导出时才可办理。两种外壳使用同一套动作、结果和回执语义。 绑定与缺失行为按[两种宿主的行为提供方矩阵](PF10A-双模式装配与助手行为接入.md#3-同一行为在两个宿主中怎样接入)执行。

每项能力由拥有业务的模块声明，助手负责发现、调用和展示。用业务名称找到目标后，服务端把目标绑定到一个已登记动作。例如“工单”和“物料”可以共享 dataset.query，两个页面共享 navigation.open。Identity 的用户导出有独立的字段与权限约束，由 Identity 提供导出处理器。查询、导航、导出是验收样例，后续模块可以登记其他行为。

| 谁提供 | 接入时要说明什么 | 运行时用途 |
| --- | --- | --- |
| 业务模块 | 稳定 capabilityId、version、用途、模型侧唯一函数名、参数 JSON Schema、只读/页面/写入分类 | 生成 Responses 的 function 声明，将返回的 name 映射回本轮固定版本。发生名称冲突或缺少处理器时拒绝注册 |
| 项目配置或模块目录 | 业务名称、别名、资源标识、允许的能力、已注册数据源/页面/操作以及参数默认口径 | 识别对象，只提供当前项目和用户可用的候选。绑定版本和目标由服务端保存 |
| 执行方 | 业务权限与范围校验、处理器、成功凭据、返回类型。写操作另提供幂等键、重试与状态查询规则 | 用当前调用者身份执行，返回实际状态、结果引用及可展示摘要。页面到达、文件就绪和草稿创建各有自己的成功条件 |

已有行为通过绑定新资源扩展；新行为由模块提供执行权限、参数、处理器和成功凭据。页面动作由发起请求的外壳实例领取并交给页面执行，详见[接入位置与回执规则](PF10A-核心接口与页面规格.md#44-页面动作与回执)。

一次调用依次经过能力筛选、参数解析、鉴权、执行、结果呈现。模型只收到本轮候选函数的名称、用途和参数约束。执行器根据本轮登记信息解析参数，复查启用状态、版本、业务授权和对象范围，执行后把结果写回已有 Execution/Step。客户端按结果类型渲染表格、页面回执、文件、业务对象或文本。缺参数只补问缺失项，异步办理先显示已受理。重放按业务 operationKey 查询原结果，模型 call_id 只用于同一轮协议配对。

**扩展示例。** 接入“查询本周到货单”时，如果已有受控 Dataset，只需登记别名、数据源修订、到货日期口径、可筛选列和权限，复用查询处理器与表格卡。若以后要支持“生成巡检任务草稿”，巡检模块需提供创建草稿的业务契约、权限、幂等及结果核对，再注册独立函数，返回草稿标识和打开入口。两个例子均沿用同一个聊天入口、模型请求格式和执行记录。巡检草稿仅用于说明新行为的接入方式。

## 创建模型响应

首期由 ModelGateway 调用 DeepSeek Responses API 创建模型响应。其格式兼容 OpenAI Responses，具体字段、工具回传和会话行为以 DeepSeek 文档为准。前端动作的领取、执行和扩展见[接口规格 §4.4](PF10A-核心接口与页面规格.md#44-页面动作与回执)。[DeepSeek 接口文档](https://api-docs.deepseek.com/api/create-response/) · [兼容说明](https://api-docs.deepseek.com/guides/responses_api/)

后端向 `POST https://api.deepseek.com/responses` 发送 JSON，使用服务端 Secret 构造 `Authorization: Bearer <key>`。模型名作为项目配置。以下是已唯一绑定工单数据源后的一次最小请求例子，业务函数和枚举由平台按当前授权生成。[Responses API 参数](https://api-docs.deepseek.com/api/create-response/)

```json
{
  "model": "deepseek-flash",
  "instructions": "使用已登记的业务工具查询，依据返回的结果回答。",
  "input": [{"role":"user","content":"帮我列出本月的生产工单信息"}],
  "tools": [{
    "type":"function",
    "name":"query_dataset",
    "description":"按项目登记的默认日期口径查询已授权业务数据。work_orders 表示生产工单。",
    "parameters":{"type":"object","properties":{"resource":{"type":"string","enum":["work_orders"]},"period":{"type":"string","enum":["this_month"]}},"required":["resource","period"],"additionalProperties":false}
  }],
  "tool_choice":"auto",
  "stream":false
}
```

1. 后端按会话归属和当前授权组装 input 与 tools。平台负责保存消息、结构化条件、结果引用和当前工具轮次。每次请求携带所需对话上下文，长会话先压缩旧上下文，再追加本轮完整工具往返。DeepSeek 的 Responses API 无状态。[多轮及参数兼容说明](https://api-docs.deepseek.com/guides/responses_api/)
2. 从 response.output 中读取完整 function_call，解析 arguments。网关把函数名映射到登记的能力，校验参数、当前权限、项目及业务范围后分配执行步骤。工单工具调用 Dataset 或登记的 HTTP/MCP，页面工具发动作给当前标签页，用户导出工具调用 Identity。多调用按依赖顺序执行，平台负责既定的六步预算、去重及取消。
3. 续调时在原 input 后依序附上该轮所需的模型输出项，再为每个调用补充同一 call_id 的 function_call_output。output 为序列化的安全摘要。示意值如下，生产环境由真实回执填充。平台根据 resultNId 自行渲染完整表格，模型侧只拿回答所需信息。

```json
{"type":"function_call_output","call_id":"示例调用ID","output":"{\"status\":\"ready\",\"resultNId\":\"示例结果ID\",\"count\":12}"}
```

4. 再次 POST 同一端点，传入追加后的 input、指令和本轮允许的工具。若仍有调用，继续有限执行。用户明确说“导出”可直接按确定范围办理。模型返回的“已导出”和前端真实文件状态分别处理，下载按钮由后者决定。
5. 流式模式累积文本增量与工具参数，只在模型轮正常完成且完整参数通过校验后执行。断流或不完整响应保留已知状态。429/暂时不可用时可限次退避重试模型请求，已经执行的步骤复用原业务回执。恢复聊天先展示已有结果。会话恢复时如来源已撤权，重新构造可送出的上下文。[流事件和协议](https://api-docs.deepseek.com/guides/responses_api/)

## 验收实例

- 用同一份查询处理器接入第二个数据源，验证不同说法均可识别、新旧资源权限分别生效。用独立测试处理器登记新动作，验证模型可以发起调用、页面按返回类型展示结果、停用后旧会话也无法执行该动作。

- 在固定项目时区与跨月边界的测试工单中，“本月”仅返回所选口径命中的授权记录。追问“只看未完工”继承数据源与时间。现场数据源未登记时展示接入状态。
- 同名页面只需选择一次。用户取消离开或目标页未应用筛选时，助手显示实际结果。
- 导出当前用户筛选结果，独立打开 XLSX 核对列、状态和条数。权限不足与中途断流分别显示对应原因，均无可下载文件。尝试在聊天中改租户或请求未登记列应被拒绝。
- 用记录的协议样本验证完整工具往返、重复投递、限流和多轮续问，再用获准的现场数据源、模型配置做实测。项目资料从上传到问答，以及 ZIP 合并保留本地修订，分别执行端到端验收。
