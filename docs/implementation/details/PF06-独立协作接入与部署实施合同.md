# PF06 独立协作接入与部署实施合同

日期：2026-09-14；2026-09-15 状态调整：**旧实施已停止，本文保留为既有业务需求和实现参考，不再用于自动续派。** 当前只做协作复盘、基线验证与冗余清理。平台通用单点登录和独立部署由用户分别开启新主控，最新参数含义、四阶段顺序和现有代码索引见[后续主控交接](平台单页入口与独立部署-后续主控交接.md)。不得把下文旧账户 URL、许可改动范围或待验项直接作为新阶段实现授权。

## 1. 用户可见结果

- 使用 `pnpm dev:lan:https:collaboration`，浏览器访问 `https://localhost:5173/pc/collaboration?account=xxA`，自动以演示账户 xxA 进入通讯；另一页面传 xxB/xxC 即为对应账户。无参数保留固定 A 的便捷默认，未知账户明确拒绝，不默认为 A。
- MES 以后仍可拼接同样的 account 参数。账户参数不是生产认证凭据；正式模式通过用户将要实现的服务端适配器确认该账户与 MES 当前登录一致。保留 .NET Framework 4.5.2 / .NET 6 的 HTTP 接入方式，不要求旧 MES 引用 .NET 10 程序集。
- 人员由预留 MES 数据接口提供，支持按账户取人、搜索/分页。演示预置 xxA/xxB/xxC；稳定账户标识、显示姓名分开，账户映射规则中文说明。能复用现有演示用户标识则复用，不重置已有消息。
- 文字支持离线留言：xxB 未打开页面时 xxA 仍能建聊天、发消息；xxB 下次打开加载历史、未读，既有顺序、幂等和已读同步继续有效。
- 媒体邀请要求目标具有在线通讯页面；离线拒绝语音、共享我的屏幕、请求对方共享，不能只在按钮禁用而后端仍受理。普通文字功能不受影响。
- 页面连接在线，而非 MES 登录在线：打开嵌入通讯页建立实时连接，离开/销毁页面结束本页媒体和连接，最后一条连接消失后账户离线。普通平台应用外壳长期持有连接的行为保持不变。
- 多个地方使用同一账户可并存；关闭一页不注销其他页、不退出 MES；消息只持久化一次并同步各在线页面；媒体邀请第一个接听页面获选，其他页面取消提示，信令只给选中终端。关闭媒体参与页面结束该媒体，不自动迁移终端。
- 同一浏览器同源两个标签页分别 xxA/xxB，必须互不串身份。不能用全站共享 Cookie 的最后一次登录覆盖前一页面，也不能通过删除账户全局 Cookie 实现页面关闭。
- 不能让有效通讯因旧的固定 60 秒会话寿命周期性掉线。账户认证、页面存活心跳和媒体生命周期分别负责各自状态；正常页面可连续使用，异常退出有有界清理。
- 权限由 MES 控制能否进入页面，不要求用户实现平台细分权限目录。独立宿主对已验证用户映射明确的协作基础权限（仅所需聊天/媒体能力），继续复用会话参与人/租户/选定终端校验，不给平台管理权限或全局 allow-all。

## 2. 配置与数据库标准（先落地当前宿主）

统一独立配置入口：`src/backend/appsettings.Standalone.Development.local.json`，私有忽略；配套可提交的脱敏模板。平台 `src/backend/appsettings.Development.local.json` 原样保留，独立宿主不能向上发现它当作兜底。

- 统一文件放数据库提供程序、唯一连接/物理目标、公共 Schema 及已需要的基础设施参数；各宿主保留自己的 MES 接入、页面来源、功能模式配置。
- 加载优先级必须唯一且有中文说明：宿主默认配置 → 显式独立公共配置 → 环境变量/命令行部署覆盖（如受已有基础设施实际限制需调整，必须明确写出且验证）。生产允许指定外部文件绝对路径，不依赖源码仓库，不伪装 Development。
- 尽量复用 SqlSugar、DatabaseTopology 现有契约，从唯一数据库输入派生运行目标。不要让用户同时修改两个互相可能冲突的数据库字符串；冲突时明确报错而非连错库。
- 目前默认演示 SQLite；独立模块共用一个绝对 SQLite 文件。相对路径以统一配置文件目录等固定根解析，不能随启动项目目录改变。SQLite 主命名空间 main；不新增无效 Schema 参数。
- PostgreSQL 独立部署允许一个物理库、一个公共 Schema（默认 public 可接受），沿用模块表前缀和各模块迁移账本。不在本次实施 SQL Server。
- 新的独立拓扑支持必须显式启用，保留平台现有 Shared 仅 Development 的默认限制；不全局放宽校验，不把正式环境硬改成 Development。共享 Schema 行为须核对当前初始化 SQL/元数据真实目标，不能只显示配置字段。
- 自动初始化独立于 FixedDemo，正式模式也按所装配模块依赖顺序执行必要迁移。现有 Identity → SystemData → ReferenceData → Collaboration 初始化器优先复用；不复制业务 DDL，不提前建立未来模块空项目。
- 每次启动先检查版本/结构，只执行未完成的增量；不能清空表、改写已应用迁移校验和或重置用户/消息。演示 A/B/C 配置不作为正式启动的必需条件。
- 多进程同时初始化同一物理目标必须协调，复用已有锁/账本能力并补齐必要并发保护；同进程串行不等于跨宿主安全。初始化失败不得报告就绪，释放本次锁并给出不含密码的错误。
- SQLite 自动建文件；PostgreSQL 如需先建物理库/Schema 或配置账号授权，交付必须明确命令/配置和权限要求，不擅自操作用户云数据库。
- 当前 PresenceRegistry 依赖 Redis。明确当前独立运行实际需要的缓存配置和来源，不能只验证 SQLite API 就声称跨页面在线可用。不引入不必要的新基础设施，也不假定数据库共享等于实时连接共享。

## 3. 最小代码改动边界

允许：EmbeddedHost、独立配置加载/启动编排的必要 BuildingBlocks 扩展、独立前端认证/入口/页面连接生命周期分支、独立宿主人员/权限适配，以及受影响定向测试和相关部署文档。

有条件修改：Collaboration 公共 Hub/媒体入口若缺少必要在线校验等，只补有证据的共用契约缺口，先核全部调用方，保持平台默认语义，独立特性优先通过宿主选项/适配器实现。

不允许：重写聊天存储、WebRTC 协商/编码/播放；回退原媒体修复；删除平台权限；重做 UI；开发 SQL Server/Electron/Capacitor；创建低代码等未来宿主；隐式开启新服务/端口回退；修改平台私有云配置；迁移云数据库；提交/推送/新建分支/清理 WIP。

本轮不擅自扩大为完整前端裁剪生产包；继续复用现有页面和组件，完成独立装配必要入口隔离。若尚无独立静态构建产物，保持事实说明。

## 4. 实施注意点与明确约束

1. 先确定页面会话的身份承载，再实现 account 切换。可以为独立宿主增加页面级不透明凭据，在本页内存中持有并作用于 REST/SignalR；若采用其他机制也必须满足同源多账户隔离。不要把裸 account 当作后续请求身份，也不要覆盖平台 JWT/Cookie 分支。
2. 页面结束只撤销本页凭据/连接。卸载请求是尽力而为，强关、断网由服务器失联超时清理；本地捕获和 PeerConnection 要真实停止，不能把票据过期当作停止媒体证据。
3. 原流程中页面 URL 参数须正确编码/解码，避免空值、重复/歧义账户、未知账户回退。正式模式默认拒绝未实现 MES 适配；演示白名单只在显式开发演示模式可用。
4. 服务端保留租户、会话成员和媒体终端边界。MES 页面权限由 MES 自行处理，接入接口不强迫其构造当前平台的权限目录。
5. 不删除正常平台应用级实时插件；独立入口采用自己的启动和销毁边界。iframe 销毁与仅收起视频浮窗不同，浮窗收起不等于通讯页面关闭。
6. 不通过延长一个固定短期 Cookie 到无限时长掩盖失联清理；给出页面保持、重连、退出及 MES 身份失效的实际实现说明。

## 5. 完成标准与一次定向验证

开发先完成以下有辨识力的检查，稳定后独立验收核增量和证据，不重新执行完整旧媒体测试矩阵。

- 账户参数/身份：xxA、xxB、未知账户、无参数；同源两页身份隔离；正式模式拒绝假冒参数；正常平台登录行为回归。
- 离线留言：A 发给离线 B，落库一次；B 打开后出现消息和未读；离线 B 的三类媒体邀请均拒绝。
- 页面/多端：A 两个连接关闭一个仍在线；最后一个关闭离线；另一账户页仍可用；语音邀请一端接听后其他端不再参与；关闭参与页后对应媒体结束。模拟/API 与真实浏览器证据分开标注。
- 登录保持：超过原 60 秒仍可正常通讯；页面停止心跳后凭据/在线有界失效；不循环创建登录、不无条件全局撤销。
- 配置/初始化：从两个工作目录解析到同一 SQLite 文件；重复启动保留消息；并发初始化无重复迁移；新独立正式拓扑与平台原限制分别验证。PostgreSQL 尽量定向验证目标解析/Schema/迁移，环境不具备时明确剩余项，不连接云库凑结果。
- 最终新鲜 Release 构建及受影响测试。已通过的真实 PC/手机媒体效果不扩写为本轮独立入口已测；浏览器工具不可用时不要重复尝试环境。
