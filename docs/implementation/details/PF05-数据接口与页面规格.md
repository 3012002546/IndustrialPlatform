# PF05 数据字典、接口与页面规格

版本 V1.2；2026-09-08。本文与[执行补充](PF05-前置契约与合规执行补充.md)共同定义完整输入；执行见active/PF-05。先实现明确的依赖增量并通过合同测试，再继续消费者；实际验收不得用派遣代替。


## 1. 类型、命名与基线

2026-09-11 用户调整：PDA/Mobile 必须使用已定义的会话列表路由 → `/collaboration/conversations/:conversationNId` 详情路由，列表与聊天不同时占屏；返回列表保留筛选、草稿和滚动状态，列表页不将隐藏聊天标记已读。管理员操作与导出采用主实施方案 §11.2、§11.7 的系统管理员例外：无密码弹窗、本人导出直接排队，仍保留有效会话与单次命令授权。现有 `ApprovedByUserNId == CreatedByUserNId` 且非空的受信服务端事实代表管理员本人授权，其他导出仍需独立审批；不改已应用迁移或增加前端可提交的管理员标志。

这是派遣输入的设计规格，不是已建表证据。服从[派遣前规则](../STANDARD-派遣前详细设计与页面验收.md)和[实施模板](../TEMPLATE-开发实施方案.md)。表中 `?` 表示允许 NULL；未标 `?` 均 NOT NULL。没有默认值的字段必须由经过校验的用例赋值，不由数据库猜测业务默认。

| 类型代号 | .NET / PostgreSQL / SQLite / JSON | 约束 |
| --- | --- | --- |
| id | Guid / uuid / TEXT / 不对外 | 内部主外键；应用生成；SQLite 存规范 GUID |
| key | string / varchar(128) / TEXT / string | 1～128，身份源标识保持原值；SQLite CHECK 长度 |
| nid | string / varchar(64) / TEXT / string | 本服务生成 Guid 的 N 格式32字符；不采用数据库 Id 对外 |
| str(n) | string / varchar(n) / TEXT / string | SQLite 同样限制最大 n 字符；空串是否允许见字段 |
| text | string / text / TEXT / string | 长度、敏感性在字段规则中声明 |
| i32 | int / integer / INTEGER / number | 范围逐字段指定 |
| i64 | long / bigint / INTEGER / 十进制 string | 序号/版本/字节数不经 JS number；JSON 样例 `"42"` |
| time | DateTimeOffset / timestamptz / TEXT / string | UTC RFC3339；SQLite 固定 UTC 格式比较，业务时间注入可控时钟 |
| bool | bool / boolean / INTEGER / boolean | SQLite CHECK 0/1 |
| hash | string / varchar(64) / TEXT / string | SHA-256 小写 hex，64字符；哈希不代替授权 |
| json | 已声明 DTO / jsonb / TEXT / object | schemaVersion=1，禁止任意无 schema 扩展；≤256KiB，单独注明者例外 |
| dec(p,s) | decimal / numeric(p,s) / TEXT / 十进制 string | SQLite 保存规范十进制文本，应用精度校验，不走 REAL |

逻辑字段转换为同名 snake_case：NId→n_id、TenantNId→tenant_n_id、CreatedOn→created_on。下面每行给出精确物理名。跨服务引用只是 string，不建外键；本服务自行签发的 NId 不要求外部 Identity/File 改其命名或大小写。若前置实际标识超出128，先改规格和测试再派遣，不静默截断。

**E 基组：** 领域实体表统一含下列字段，逐表不重复展开；技术表显式列字段，不套软删除/双版本。

| 逻辑字段 / 物理列 | 类型 | 默认与规则 |
| --- | --- | --- |
| Id / id | id | PK，Guid.NewGuid，无数据库业务默认 |
| IsFrozen / is_frozen | bool | false；普通修改保护 |
| IsLocked / is_locked | bool | false；锁定保护 |
| IsDeleted / is_deleted | bool | false；不等于消息撤回/打印取消 |
| EntityType / entity_type | text | 完整领域类型名，服务生成，不开放编辑 |
| CreatedOn / created_on | time | 创建时 UTC，应用赋值 |
| LastUpdatedOn / last_updated_on | time | 初始与 CreatedOn 相同；实际改变才更新 |
| OptimisticVersion / optimistic_version | i64 | 初始0，实际改变+1；API用字符串 |
| ConcurrencyVersion / concurrency_version | id | 初始非空，实际改变重新生成；API若暴露为GUID字符串 |

**B 基组：** 本文全部领域实体另含 `NId/n_id:nid` 和 `TenantNId/tenant_n_id:key`，必须 UQ(tenant_n_id,n_id)，包括已软删除行。子实体继承本地父租户，用例校验同租户，不能接受客户端提供租户。表的 E/B 组加逐表字段就是完整字段集合。可变命令使用 expectedOptimisticVersion:string + expectedConcurrencyVersion:GUID，两者匹配；幂等已完成语义先返回原结果，避免重试变409。

技术表以具体 PK/UQ 为准；领域 FK 使用普通父 Id、ON DELETE RESTRICT，不创建软删除影子列。关键冗余 NId 只读映射、同事务赋值并验证，不提供单独修改入口。所有租户查询先带 tenant_n_id，后台任务逐租户取受限上下文。状态值保存在 varchar 列并设 CHECK；未知值失败关闭，不以整数枚举顺序作持久协议。

## 2. 物理表、索引与事务

Messaging Schema=`collaboration_messaging`；SQLite前缀=`collaboration_messaging_`。同一个 Collaboration 服务级初始化单元；服务技术 Schema=`collaboration`/SQLite `collaboration_`。Presence 无SQL表，AttachmentIntegration无重复绑定表。以下2.1～2.9表都在Messaging，2.10～2.12是服务技术记录；不跨模块读写。

### 2.1 conversation

领域实体，完整字段=E+B基组+下表。

| 逻辑字段 / 物理列 | 类型 | 默认、约束与用途 |
| --- | --- | --- |
| ParticipantLowUserNId / `participant_low_user_n_id` | key | 两用户稳定标识按UTF-8字节序取小者，禁止同人；不按显示名称排序 |
| ParticipantHighUserNId / `participant_high_user_n_id` | key | 较大者；不以本地化排序生成唯一键 |
| Status / `status` | str(24) | Active / Suspended，初始Active；用户停用不物理删会话 |
| LastMessageSequence / `last_message_sequence` | i64 | 初始0，事务计数器，>=0 |
| LastMessageNId / `last_message_n_id` | nid? | 初始NULL，最后已提交消息的稳定标识 |
| LastMessageOn / `last_message_on` | time? | 初始NULL，AcceptedOn |
| RetentionFloorSequence / `retention_floor_sequence` | i64 | 初始0，已过普通保留边界的最高连续序号 |

UQ(tenant_n_id,participant_low_user_n_id,participant_high_user_n_id)全历史；CHECK(low < high)。参与人列PG用COLLATE "C"、SQLite用BINARY；应用比较UTF-8字节，确保大小写/非ASCII测试下与数据库唯一性排序一致。IX(tenant_n_id,last_message_on,n_id)支撑游标排序。发送事务锁本行、检查成员/幂等、递增计数器并插消息、更新成员未读/可见、Outbox后提交；回滚计数器一并回滚。不用数据库sequence分配聊天序号。

### 2.2 conversation_member

领域实体，完整字段=E+B基组+下表。

| 逻辑字段 / 物理列 | 类型 | 默认、约束与用途 |
| --- | --- | --- |
| ConversationId / `conversation_id` | id | FK conversation.id；同聚合唯一父关系 |
| UserNId / `user_n_id` | key | 可信身份；不得外键Identity |
| DisplayNameSnapshot / `display_name_snapshot` | str(200) | 历史最小展示，不作身份 |
| JoinedOn / `joined_on` | time | 加入UTC |
| VisibilityState / `visibility_state` | str(16) | Visible / Hidden，初始Visible |
| HiddenOn / `hidden_on` | time? | 初始NULL |
| HiddenThroughSequence / `hidden_through_sequence` | i64 | 初始0，>=0且<=会话已提交最大序号；最近成功隐藏时的高水位，不是已读游标 |
| LastReadSequence / `last_read_sequence` | i64 | 初始0，<=会话已提交最大值，原子max |
| LastReadOn / `last_read_on` | time? | 初始NULL，游标推进才更新时间 |
| UnreadCount / `unread_count` | i64 | 初始0，可重建投影；非本人且普通可见且Sequence>游标 |
| ProjectionVersion / `projection_version` | i64 | 初始0，未读/可见变化+1，防旧事件覆盖 |

UQ(conversation_id,user_n_id)；IX(tenant_n_id,user_n_id,visibility_state,conversation_id)。一个会话固定两行；事务确认成员正好对应参与人对。API ConversationNId由父映射，不再存可变重复父键。撤回/处置重算受影响未读，不推进对方已读。

隐藏按 Conversation→Member 顺序加锁，在同一事务校验成员双版本，将 HiddenThroughSequence 推进到当前 LastMessageSequence 并设置 Hidden/HiddenOn；已为 Hidden 的重复命令返回原状态，不重新采样水位。恢复只设置 Visible、清空 HiddenOn，保留隐藏水位，不推进 LastReadSequence。新对方消息 Sequence 大于隐藏水位时，同一发送事务恢复 Visible；发送造成成员投影变化时同时更新成员 E 基组双版本，旧隐藏请求返回409而不能遮住刚到的新消息。本人发送/显式恢复同样恢复显示。无需为本列单独建索引；新建库migration 002纳入此列，不声称已经迁移。

### 3.1 消息历史与补拉的唯一 JSON 契约

`MessagePageDto`固定为`{items:MessageDto[],nextCursor:string|null,nextAfterSequence:string|null,highWatermarkSequence:string,earliestAvailableSequence:string}`。全部序号为规范非负Int64十进制字符串；`earliestAvailableSequence=RetentionFloorSequence+1`，空会话为`"1"`。高水位取当前已提交LastMessageSequence，不使用数据库sequence。`retentionFloorSequence`仍是A05-04会话字段，不是A05-06响应字段。

- 历史模式：不传锚点取得最新页，`cursor`取得更早页；查询倒序、返回items升序。nextCursor为下一历史页的签名游标或null，nextAfterSequence=null。
- 补拉模式：只传afterSequence，从其后按升序读取；nextAfterSequence为最后返回序号，空页回传请求锚点，nextCursor=null。客户端将本轮首个成功响应的highWatermarkSequence冻结为本地targetHighWatermarkSequence（不是新增请求/响应字段），循环到nextAfterSequence>=该固定目标即结束本轮；后续页返回更高水位不得抬高本轮目标，新增消息由缓冲事件或下一轮同步合并。分页响应的高水位与items在同一一致性读视图内取得，items不得超过该响应水位。持续写入不能让本轮无限追赶；到达固定目标只表示该目标以内已补齐，不宣称追平不断变化的最新状态。410或订阅中断废弃本轮目标，重建后再冻结。后台补拉不更新已读。afterSequence超过已提交高水位返回400，不制造成功同步标记。
- 窗口模式：同时传fromSequence/toSequence，闭区间且1<=from<=to<=高水位，跨度最多100；按limit分段升序返回，nextAfterSequence为本段末序号，nextCursor=null；调用者下一段从末序号+1继续，保留原toSequence。空段nextAfterSequence为fromSequence-1，不能标记窗口完成，应重读摘要和保留边界。不得同时传cursor或afterSequence。
- cursor绑定租户/用户/会话/模式/锚点/投影版本/有效期，错绑定或过期为400 `COLLAB_SYNC_CURSOR_INVALID`，不得回退至其他用户的历史。
- afterSequence小于RetentionFloorSequence、窗口fromSequence小于earliestAvailableSequence或历史cursor指向已过期范围时返回410 `COLLAB_MESSAGE_HISTORY_EXPIRED`。data固定`{earliestAvailableSequence:string,highWatermarkSequence:string,retentionCutoffOn:string|null,recoveryAction:"ReloadFromEarliest"}`；retentionCutoffOn仅取可关联已生效保留检查点的CutoffOn，无法确认时null，禁止猜测清理时间。客户端清除旧普通投影，以earliestAvailableSequence-1重新补拉，显示历史过期提示。历史首页允许空items且nextCursor=null，即便全部历史已过期，也返回真实边界。

空页成功data：`{"items":[],"nextCursor":null,"nextAfterSequence":"42","highWatermarkSequence":"42","earliestAvailableSequence":"11"}`。410 data：`{"earliestAvailableSequence":"11","highWatermarkSequence":"42","retentionCutoffOn":null,"recoveryAction":"ReloadFromEarliest"}`。混用模式、非规范序号、非法窗口为400 `COLLAB_MESSAGE_QUERY_INVALID`。
