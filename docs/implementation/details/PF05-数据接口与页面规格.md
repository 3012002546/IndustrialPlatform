## 1. 类型、命名与基线

这是派遣输入的设计规格，不是已建表证据。服从[派遣前规则](../STANDARD-派遣前详细设计与页面验收.md)和[实施模板](../TEMPLATE-开发实施方案.md)。表中 `?` 表示允许 NULL；未标 `?` 均 NOT NULL。没有默认值的字段必须由经过校验的用例赋值，不由数据库猜测业务默认。

| 类型代号 | .NET / PostgreSQL / SQLite / JSON | 约束 |
| --- | --- | --- |
| id | Guid / uuid / TEXT / 不对外 | 内部主外键；应用生成；SQLite 存规范 GUID |
| key | string / varchar(128) / TEXT / string | 1～128，身份源标识保持原值；SQLite CHECK 长度 |
| nid | string / varchar(64) / TEXT / string | 本服务生成 Guid 的 N 格式32字符；不采用数据库 Id 对外 |
| str(n) | string / varchar(n) / TEXT / string | SQLite 同样限制最大 n 字符；空串是否允许见字段 |
| text | string / text / TEXT / string | 长度、敏感性在字段规则中声明 |
| i32 | int / integer / INTEGER / number | 范围逐字段指定 |
| i64 | long / bigint / INTEGER / 十进制 string | 序号/版本/字节数不经 JS number；JSON 样例 `"42"` |
| time | DateTimeOffset / timestamptz / TEXT / string | UTC RFC3339；SQLite 固定 UTC 格式比较，业务时间注入可控时钟 |
| bool | bool / boolean / INTEGER / boolean | SQLite CHECK 0/1 |
| hash | string / varchar(64) / TEXT / string | SHA-256 小写 hex，64字符；哈希不代替授权 |
| json | 已声明 DTO / jsonb / TEXT / object | schemaVersion=1，禁止任意无 schema 扩展；≤256KiB，单独注明者例外 |
| dec(p,s) | decimal / numeric(p,s) / TEXT / 十进制 string | SQLite 保存规范十进制文本，应用精度校验，不走 REAL |

逻辑字段转换为同名 snake_case：NId→n_id、TenantNId→tenant_n_id、CreatedOn→created_on。下面每行给出精确物理名。跨服务引用只是 string，不建外键；本服务自行签发的 NId 不要求外部 Identity/File 改其命名或大小写。若前置实际标识超出128，先改规格和测试再派遣，不静默截断。

**E 基组：** 领域实体表统一含下列字段，逐表不重复展开；技术表显式列字段，不套软删除/双版本。

| 逻辑字段 / 物理列 | 类型 | 默认与规则 |
| --- | --- | --- |
| Id / id | id | PK，Guid.NewGuid，无数据库业务默认 |
| IsFrozen / is_frozen | bool | false；普通修改保护 |
| IsLocked / is_locked | bool | false；锁定保护 |
| IsDeleted / is_deleted | bool | false；不等于消息撤回/打印取消 |
| EntityType / entity_type | text | 完整领域类型名，服务生成，不开放编辑 |
| CreatedOn / created_on | time | 创建时 UTC，应用赋值 |
| LastUpdatedOn / last_updated_on | time | 初始与 CreatedOn 相同；实际改变才更新 |
| OptimisticVersion / optimistic_version | i64 | 初始0，实际改变+1；API用字符串 |
| ConcurrencyVersion / concurrency_version | id | 初始非空，实际改变重新生成；API若暴露为GUID字符串 |

**B 基组：** 本文全部领域实体另含 `NId/n_id:nid` 和 `TenantNId/tenant_n_id:key`，必须 UQ(tenant_n_id,n_id)，包括已软删除行。子实体继承本地父租户，用例校验同租户，不能接受客户端提供租户。表的 E/B 组加逐表字段就是完整字段集合。可变命令使用 expectedOptimisticVersion:string + expectedConcurrencyVersion:GUID，两者匹配；幂等已完成语义先返回原结果，避免重试变409。

技术表以具体 PK/UQ 为准；领域 FK 使用普通父 Id、ON DELETE RESTRICT，不创建软删除影子列。关键冗余 NId 只读映射、同事务赋值并验证，不提供单独修改入口。所有租户查询先带 tenant_n_id，后台任务逐租户取受限上下文。状态值保存在 varchar 列并设 CHECK；未知值失败关闭，不以整数枚举顺序作持久协议。

## 2. 物理表、索引与事务

Messaging Schema=`collaboration_messaging`；SQLite前缀=`collaboration_messaging_`。同一个 Collaboration 服务级初始化单元；服务技术 Schema=`collaboration`/SQLite `collaboration_`。Presence 无SQL表，AttachmentIntegration无重复绑定表。以下2.1～2.9表都在Messaging，2.10～2.12是服务技术记录；不跨模块读写。

### 2.1 conversation

领域实体，完整字段=E+B基组+下表。

| 逻辑字段 / 物理列 | 类型 | 默认、约束与用途 |
| --- | --- | --- |
| ParticipantLowUserNId / `participant_low_user_n_id` | key | 两用户稳定标识按UTF-8字节序取小者，禁止同人；不按显示名称排序 |
| ParticipantHighUserNId / `participant_high_user_n_id` | key | 较大者；不以本地化排序生成唯一键 |
| Status / `status` | str(24) | Active / Suspended，初始Active；用户停用不物理删会话 |
| LastMessageSequence / `last_message_sequence` | i64 | 初始0，事务计数器，>=0 |
| LastMessageNId / `last_message_n_id` | nid? | 初始NULL，最后已提交消息的稳定标识 |
| LastMessageOn / `last_message_on` | time? | 初始NULL，AcceptedOn |
| RetentionFloorSequence / `retention_floor_sequence` | i64 | 初始0，已过普通保留边界的最高连续序号 |

UQ(tenant_n_id,participant_low_user_n_id,participant_high_user_n_id)全历史；CHECK(low < high)。参与人列PG用COLLATE "C"、SQLite用BINARY；应用比较UTF-8字节，确保大小写/非ASCII测试下与数据库唯一性排序一致。IX(tenant_n_id,last_message_on,n_id)支撑游标排序。发送事务锁本行、检查成员/幂等、递增计数器并插消息、更新成员未读/可见、Outbox后提交；回滚计数器一并回滚。不用数据库sequence分配聊天序号。

### 2.10 服务级技术设施

`collaboration.schema_migrations`、`seed_ledger`采用当前服务自有初始化器模式，禁止同时再创建控制面Runner的另一份业务账本。已读`ReferenceDataServiceInitializer`（实现`IServiceInitializer`）和`ReferenceDataInitializationLedger`：现有服务账本与SystemData Runner目标账本是两套不同用途的结构，不是可互换的同一类型。本服务选定服务自有账本，其完整字段见下表；控制面调用同一初始化器并保存观察，不二次apply同一业务迁移。

| 技术表 | 完整物理字段 / PostgreSQL类型（SQLite时间为TEXT） | 规则 |
| --- | --- | --- |
| schema_migrations | migration_id TEXT PK、checksum TEXT NOT NULL、target_identity TEXT NOT NULL、applied_on timestamptz NOT NULL | 新服务没有历史NULL兼容需要；checksum=产物规范SHA256；目标摘要绑定物理目标；追加账本不能改旧checksum |
| seed_ledger | seed_key TEXT、seed_version TEXT、checksum TEXT、scope TEXT、applied_on timestamptz、operation_n_id TEXT、trace_id TEXT，均NOT NULL | PK(seed_key,seed_version)；scope=System/Tenant/EnvironmentSample/SecretBootstrap；不得存Secret，租户种子键包含规范租户范围 |

预定迁移`collaboration-1.0-001`（服务设施/身份映射）、002（Messaging/附件）、003（合规/保留）；seed `collaboration.baseline`、`collaboration.permissions`、`collaboration.navigation`的首版为1.0.0。实际SQL及种子产物生成后计算真实checksum，不能在设计文档编造checksum。先核对无版本冲突再登记，升级追加版本，SQLite不靠EnsureCreated。

已读`ReferenceDataSharedMigration.cs`：它的outbox使用event_id/module_key/event_name/aggregate_id/revision/payload/status/attempt_count等列，且模块CHECK限定ReferenceData；没有本文所需通用租约列。**复用其事务/调度模式和既有公共接口，不把该服务具体表或类型当作通用现成组件**。Collaboration拥有下列服务级目标表；增加租约和安全投影是本阶段明确设计，不修改ReferenceData表。

| 技术设施 | 必须映射的字段与类型 | 约束 |
| --- | --- | --- |
| outbox_message | Id:id、EventNId:nid、TenantNId:key、ModuleKey:str(64)、EventType:str(128)、SchemaVersion:i32、AggregateNId:nid、AggregateVersion:i64、Payload:json、OccurredOn:time、PublishedOn:time?、Attempts:i32=0、NextAttemptOn:time、LeaseOwner:str(128)?、LeaseExpiresOn:time?、LastErrorCode:str(96)? | UQ(event_n_id)；IX(published_on,next_attempt_on)；普通聊天Payload只保存标识，发布前取当前安全投影；审计任务不含正文 |
| inbox_message | ConsumerName:str(128)、EventNId:key、TenantNId:key、ReceivedOn:time、ProcessedOn:time?、Attempts:i32=0、NextAttemptOn:time、LastErrorCode:str(96)? | PK(consumer_name,event_n_id)；只为真实File/Identity消费者注册；事件先持久化、幂等重查 |

上表字段名转换规则同§1；Outbox Id为PK，EventNId业务事件唯一，不把两列同时作为自增键。NextAttemptOn在未发布时必有值。重试最多10次，退避min(2^(attempt-1),300)秒加0～20%抖动；耗尽保留记录、LastErrorCode标记并进入受权人工重投，不静默丢弃。租约30秒，每10秒续租，领取按到期条件原子更新；发布确认前崩溃允许重复投递，由消费者幂等。

发布成功记录默认保留30天，失败未确认保留；Inbox保留必须不小于上游重放窗口，未取得上游窗口时不清理。Token、二进制、正文不进入通用可观测日志。G05-1仅剩目标注册/前置身份语义核验，已查清的账本和Outbox结构不能再当作未设计内容交给执行者。

### 2.11 外部身份映射（仅Embedded需要）

`collaboration.external_subject_map`是技术记录：`identity_source_n_id:key`、`external_tenant_n_id:key`、`external_subject:str(256)`、`tenant_n_id:key`、`user_n_id:key`、`display_name_snapshot:str(200)`、`security_version:str(128)`、`verified_on:time`、`valid_until:time`、`disabled_on:time?`。PK(source,externalTenant,subject)，UQ(tenant_n_id,user_n_id)。subject以来源协议大小写规则比较，默认Ordinal；不按邮箱自动关联。有效期默认最多60秒，实时停用立即作废；真实宿主要求更短时先更新规格。无单独账号门户/密码库。

### 2.12 Presence记录（Redis/内存，非SQL）

键 `collaboration:presence:v1:{tenantHash}:{userHash}:{connectionNId}`；值 `connectionNId:string, userNId:string, tenantNId:string, subjectEpoch:string, terminal:pc|pda|mobile, lastHeartbeatOn:RFC3339, expiresOn:RFC3339, stateRevision:十进制字符串`。单连接TTL60s，心跳20s，正常断开聚合去抖15s；租约自然过期不能再加15s误报在线。观察TTL与授权TTL分别维护。普通用户只得到Online/Offline/Unknown和粗粒度lastActivity，不能拿连接明细。聚合可重建；两副本键和加组均由服务端导出。

### 2.13 清理后的幂等证明与锁顺序

`collaboration_messaging.message_deduplication`是技术表：`tenant_n_id:key`、`sender_user_n_id:key`、`client_message_n_id:nid`、`request_hash:hash`、`message_n_id:nid`、`conversation_n_id:nid`、`sequence:i64`、`accepted_on:time`、`content_purged_on:time?`，全部除最后字段NOT NULL；PK(tenant_n_id,sender_user_n_id,client_message_n_id)。与消息同一发送事务插入，无正文或附件名称。业务消息物理清理后继续保存最小证明，重复意图返回410保留边界而非重发消息；首版不自动清理这张最小证明表，需后续明确重放时限后才增加清理策略。所有清理/保全事务先取租户保留互斥，再按ConversationId、MessageId稳定顺序锁定，发送/已读按Conversation→Member/Message顺序，禁止反向锁；设备/外部服务调用不在这些锁内。
