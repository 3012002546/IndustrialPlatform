# WellUnifiedReport 第二轮：预览、查询表格与高级控件

日期：2026-10-30。承接 [第一轮评估](2026-10-30-WellUnifiedReport-REA评估.md)。本轮为功能逆向与实现可行性评估，不修改产品代码、不接入原项目数据库、不执行原项目应用。

## 1. 用户需求与本轮结论

用户补充了三个明确范围：

1. 预览：单页/全部页、上下页跳转、缩放、打印/当前页打印、十类格式导出、当前页内容快速查询。
2. Spreadsheet：简版线上 Excel，在空白或预设表格模板中填充查询结果，允许用户临时操作后下载或打印。车间出入库流水仅是示例，不限定业务领域。每次查询不得自动创建持久化工作簿、副本或历史版本。第一轮指出原项目保存未完成，是对旧实现的事实判断，不应被当成该临时场景必须持久化的依据。
3. 高级报表控件：Character Comb、行、形状、条形码、图表、Gauge、Sparkline、数据透视表、子报表、PDF Content、PDF Signature、目录；另将普通 Table 一并区分。

结论：可以在现有 .NET / Studio、报表生成链和 Workbook/WOPI 基础上逐项承接。预览交互与查询表格的边界较清楚；多格式保真导出、PDF 内容与证书签名分别需要独立的导出/文档处理能力，不能靠增加菜单或画布图标完成。

### 名称校正

- 截图是 **DOCX**，不是 DOCS。
- 本地中文资源将 `XRLine` 翻译为“行”，实际是**线条**，不同于表格行。
- 本地中文资源将 `XRTableOfContents` 翻译为“表的内容”，实际是**目录**；目录基于层级与最终页码，不同于普通表格 `XRTable`。
- 用户的“图标”暂按工具箱中的 `XRChart`（图表）评估，本地名称为“图表”。若另指静态图标，则属于现有图片/图形资源能力，不能与图表的数据系列模型混同。

### 当前平台差距

`src/frontend/src/components/studio/report/ReportPreviewPanel.vue` 已有页列表、选择页码、加载单页 HTML、运行状态和取消操作；本组件尚未提供本轮完整工具栏。应在现有预览模型上补齐交互，不建立第二套报告生成算法。

当前预览 iframe 使用严格 sandbox。页内查找不能默认由父页面直接读取 iframe DOM：应设计受控的每页文本/定位信息，或经过评审的预览消息协议。不要为搜索随意取消隔离。扫描图片或无文本层 PDF 不会自动获得文本命中能力；OCR 不属于现有证据已确认功能。

## 4. 十类导出：完整需求清单

十类格式全部保留为需求范围；分批实现不等于取消剩余格式。下表为平台实现与验收要求，不宣称旧项目或平台已经通过全部格式验证。

| 格式 | 应明确的输出与选项 | 不能混淆的事项 |
| --- | --- | --- |
| PDF | 固定版式、页范围、字体/图片、目录与链接；签名单独处理 | 网页截图或打印成功不等于正式归档产物验收 |
| XLS | 真正的旧版工作簿文件；检查格式容量与兼容边界 | XLSX 改名为 .xls 无效 |
| XLSX | 区分报表版式导出与查询数据工作簿；列类型、样式、合并、Sheet 策略 | 版式切割生成的单元格不必然适合继续筛选/计算 |
| RTF | 可编辑富文本，明确分页、表格与图片处理 | 不能用 HTML 改名替代 |
| DOCX | 真正的 Word 文档；明确连续流/按页保留布局模式 | Word 重排与 PDF 固定版式目标不同，应记录允许差异 |
| MHT | 单文件网页封装，正确包含引用资源 | 与普通 HTML 文件不同 |
| HTML | 页面/连续文档策略、样式、图片和资源打包规则 | 下载后不应依赖已失效的预览会话 URL |
| 文本 | 编码、分隔符、换行及字段格式 | 不承诺保留图片、边框和全部版式 |
| CSV | 数据列、列序、引用转义、编码、日期/数字及公式样文本处理 | 不承载复杂控件、合并单元格和多 Sheet 结构 |
| 图像 | 明确 PNG/JPEG 等实际选项、分辨率、页范围；多页打包方式 | “图像”是格式族，不能只给一个未定义结果 |

平台已存在 PDF/HTML/XLSX 相关链路，但本轮没有重新执行其验收，也未证明其他七类已实现。后续须建立“控件 × 导出格式”的支持矩阵：保留可编辑结构、转静态图形、忽略不适用内容或明确不支持，逐格定义。高级控件出现在预览中，不代表跨格式等价。

## 5. Spreadsheet：查询结果工作台

后续实测：[临时查询表格 WOPI 可行性验证](2026-10-30-临时查询表格-WOPI可行性验证.md)，包含默认列头筛选、6→2→0 行刷新及两名模拟用户并行隔离。多人共用报表定义，各自持有独立临时查询会话；不得共享同一可写文档标识。

### 本轮明确用途

用户澄清：原设想是用一个空模板填充查询数据，结果仅用于本次页面中的临时操作。车间出入库流水只是这类查询的例子；该能力应供不同纯表格查询页面复用。

打开页面时加载空白或预设表格模板，查询后将数据填入指定区域；用户修改内容、整理列、排序/筛选、计算、调整格式，再下载或打印。操作对象是页面的临时表格状态，不是每次查询创建一份业务工作簿。修改结果不自动回写来源业务数据。

```text
打开页面 → 加载空白/预设表格模板 → 建立临时编辑会话
          ↓
受权查询 + 参数 + 字段类型 → 清理旧数据区域并填充本次结果
          ↓
同一页面临时编辑 → 下载 / 打印
          ↓
正常退出查询页 → 立即关闭会话并清理临时内容；异常失联 → 短租约到期兜底回收
```

这是用户明确的目标链路，不是原项目已实现功能。原项目现有 Spreadsheet 入口是读取 OP 已有文件；没有证据表明它已完成模板填充的生产流程。模板作为可复用定义保持不变，各用户的临时编辑状态隔离；不因查询创建工作簿列表项、文件业务副本或版本历史。编辑器如果需要临时文件/缓冲区，由会话管理并回收，不将其作为用户文档归档。

### 简版界面与数据约定

- 单页布局：上方业务查询条件和查询/刷新，下方表格及下载、打印、恢复查询结果入口；隐藏与该场景无关的复杂入口，具体裁剪能力按实际 Office 服务验证。
- 基础操作：选择/复制粘贴、撤销重做、单元格编辑、行列调整、排序筛选、冻结表头、格式、简单公式；保留数据类型，编码前导零不能被自动吞掉。
- 查询分页与工作簿数据范围必须区分。明确“本次全部结果”还是“当前查询页”，不能静默只导出服务端第一批行；超过限额给出可理解的处理方式。
- 重复查询在同一页面会话中重新填充数据区域，清除上次多出的行/单元格，按模板规则保留表头、样式与公式。已有编辑时提示下载当前结果、放弃修改并重新查询或取消；不自动另建副本。
- 下载和打印必须反映最近编辑结果，不能只依赖 iframe 加载完成或按钮回调。编辑器的自动保存如需启用，只更新临时会话内容，不自动产生永久文档和历史版本。
- 本场景不要求自动留存。若未来提供“另存为平台文档”，只有用户明确执行该动作才进入持久化文档流程；不是本轮新增必做功能。
- 来源、过滤条件、查询时间可作为工作簿说明；内部执行参数不堆入普通用户界面。

### 复用现有平台

`StudioEndpoints.cs` 的工作簿创建入口接受源 XLSX 文件或报告产物；`StudioWorkbooks` 已有持久化导入、工作副本和版本路径。这些是现有文档管理能力，**不能直接作为每次查询的调用路径**，否则会违背本场景不创建文档的要求。

可复用现有 Office 编辑器、身份授权及 WOPI 协议能力，但须先验证临时会话承载、模板填充、重复查询刷新和自动回收。WOPI 文件读写协议本身不等于能在当前打开的表格内直接填充数据；具体编辑器的填充接口及必要的受控重新加载尚待验证，不能宣称现有持久化 WOPI 实现可以原样满足。

填充逻辑按模板的数据区域和列 Schema 写入，覆盖不同业务查询；无预设格式时使用通用空模板。现有共享 Xlsx writer 能否保留模板样式、公式和合并区域需针对性验证；不能把重新生成一个新文件等同于已实现模板填充。内存或临时文件承载由编辑器要求决定，但对用户和业务存储始终是同一临时查询会话。

## 6. 高级控件逐项评估

REA 对 `Deploy/DevExpress.XtraReports.v21.1.dll` 精确选择下列 13 个类型，全部匹配、选定范围元数据覆盖完整。除表格、线条及程序化子报告外，第一轮本地模板统计并未证明其余高级控件已在生产模板使用。

| 控件 / 类型 | 本地成员证据与功能含义 | 平台承接与主要验收点 |
| --- | --- | --- |
| Character Comb / XRCharacterComb | CellWidth/Height、CellSizeMode、水平/垂直间距；逐字符格子文本 | 编码、批号等逐字排格；校验中文、空值、换行、溢出、字体和导出单元格语义 |
| 行 / XRLine | LineDirection、LineWidth、LineStyle | 线条、分隔线；现有 Line 基础上核对方向、粗细、虚线及缩放/打印一致性 |
| 形状 / XRShape | Shape、Angle、Stretch、FillColor、LineStyle | 基础矢量形状；现有 Box 不是完整形状库，需类型、填充、边框和旋转模型 |
| 条形码 / XRBarCode | Symbology、Module、AutoModule、ShowText、BinaryData、方向 | 明确码制、内容校验、静区、尺寸；实际打印后扫码验证，不能仅凭屏幕外观 |
| 图表 / XRChart | Series、Diagram、Legend、DataSource/DataMember、Palette、Titles | 绑定类别/数值/系列、图例、坐标轴、空值；首批图表类型须明列，静态图与可编辑 Office 原生图表分别声明 |
| Gauge / XRGauge | ActualValue、TargetValue、Minimum/Maximum、ViewType、TickmarkCount | 仪表展示实际值/目标值/范围；验证越界、空值和阈值，而非只画装饰弧线 |
| Sparkline / XRSparkline | ValueMember、DataMember、DataSource、View、ValueRange | 表格内小型趋势图；绑定有序序列，定义缺失值、范围和各行尺度是否一致 |
| 数据透视表 / XRPivotGrid | Fields、Groups、DataSource、Prefilter、OptionsPrint、行列数 | 行维度/列维度/度量/聚合/小计/总计，验证高基数与横向溢出；打印交叉表不自动等于 Excel 可交互透视表对象 |
| 子报表 / XRSubreport | ReportSourceId/Url、CanBreakPage、CanGrow；原项目有动态 ReportSource 赋值 | 复用 AssemblyPlan 和固定模板修订、参数映射、上下文、条件、顺序、空数据诊断；循环与深度受控 |
| PDF Content / XRPdfContent | Source/SourceUrl、CanBreakPage 等 | 将外部 PDF 内容加入报告；需文件版本冻结、页面尺寸/方向、页数、加密/损坏文件处理。不要承诺 PDF 内部文本可像明细带重排 |
| PDF Signature / XRPdfSignature | SignatureOptions；本地设计器含签名显示属性 | 可视签名信息/签名区域与最终 PDF 密码学签名分层；签字图片不等于有效证书签名。最终验收应验证签名与文件完整性 |
| 目录 / XRTableOfContents | Levels、LevelTitle、LevelDefault、MaxNestingLevel | 从稳定标题/书签层级生成目录与链接，使用最终页码；目录增加页数后须有界重新计算，不能在未分页前填猜测页码 |
| 普通表格 / XRTable | Rows、KeepTogether、ProcessHiddenCellMode | 延续现有 Table；单元格边框/合并/类型/重复行、长单元格续排，与目录及透视表分别建模 |

以上成员仅证明类型提供这些接口，部分还包含继承隐藏/设计器不适用属性；并非所有成员都应直接暴露给平台用户。

### PDF Content 与电子记录规则

现有电子记录内容流继续按母版分页。外部 PDF 是独立附件页面/固定内容类型，不能以引入 PDF Content 为由把原本可连续排版的工序子报告改成整页 PDF 拼接。默认行为、是否独立成页、是否计入全局页码须写入契约并用真实样本验证。

当前官方 PDF Content 文档还描述内嵌模式等新能力；本轮 21.1 类型检查没有证明其全部存在，不将新文档能力回填为旧项目事实。

### PDF Signature 与业务签名

业务审批身份、签名图像、PDF 签名字段、证书签名是不同对象。应先完成内容、分页、目录与最终 PDF，再按指定签名策略处理；签名后再次修改文件内容的影响需验证。复用平台密钥/证书管理与授权能力，不把私钥直接写入模板 JSON。

## 7. 实现难度与建议顺序

这是评估顺序，不是已派发的新开发工作包；用户要求的全部功能仍在范围内。

| 顺序 | 内容 | 判断 |
| --- | --- | --- |
| 1 | 完整预览工具栏、当前页搜索、PDF 打印；空模板填充查询结果并临时编辑、下载/打印 | 复用编辑器与协议能力，先验证临时会话和重复填充；不得每次查询创建持久化副本 |
| 2 | 表格/线条完善、Character Comb、基础形状、条形码、子报告 | 前三类偏布局；条码需要编码器与实物扫码；子报告复用现有组装规则 |
