## 2. G05-1 Identity、外部参考宿主、权限与菜单

### 2.1 真实依赖已存在

Identity 当前有管理用户摘要 `UserSummary`，实际字段包括 `UserNId`、`LoginName`、`Name`、`Email`、`Phone`、`Status`、`TenantNId`、`CreatedOn`、`LastLoginOn`、`MustChangePassword`、直接/组/有效角色列表、`OptimisticVersion`、`ConcurrencyVersion`、`IsDeleted`、`IsSystemAdmin`（`src/backend/src/Services/Identity/IndustrialPlatform.Identity.Contracts/Management/UserManagementContracts.cs:85-107`）。管理 `GET /api/v1/users/{id}` 受 `identity.user.view` 保护，并在控制器注释和代码中声明不存在或跨租户返回 404（`src/backend/src/Services/Identity/IndustrialPlatform.Identity.Api/Controllers/UsersController.cs:27-84,216-239`）。

SystemData 已有一个应用端口 `IIdentityUserDirectory.GetAsync(tenantNId,userNId)`，以及 `IdentityUserDirectoryEntryV1` 投影，字段为 `TenantNId`、`UserNId`、`LoginName`、`Name`、`Status`、可空 `AuthVersion`、`IsSystemAdmin`（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Application/IdentityDirectory/IIdentityUserDirectory.cs:5-20`；`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Contracts/Administration/IdentityUserDirectoryContracts.cs:11-35`）。通知业务已有按租户和 `Status=Active` 再校验的调用模式，并在目录不可用时返回稳定 503（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Application/Notifications/NotificationService.cs:242-254`）。

Identity 的认证基础能力也真实存在：Access Token 当前签发 `sub/user_name/tenant_id/role/sid/ver/jti`，认证校验 issuer、audience、签名、有效期和会话撤销（`src/backend/src/Services/Identity/IndustrialPlatform.Identity.Infrastructure/Security/AccessTokenFactory.cs:7-56`；`src/backend/src/BuildingBlocks/IndustrialPlatform.Security/ClaimConstants.cs:5-35`；`src/backend/src/Services/Identity/IndustrialPlatform.Identity.Api/Extensions/AuthenticationServiceCollectionExtensions.cs:20-119`）。已有权限测试覆盖持有权限 200、缺权限 403 `ID_PERMISSION_DENIED`、安全版本不匹配/撤销会话 401、禁用账号 403、认证安全存储不可用 503（`tests/Identity/IndustrialPlatform.Identity.Tests/Api_PermissionAuthorizationTests.cs:35-200`）。

### 2.2 设计/契约缺口

1. **没有 PF05 所需的搜索契约。** `IIdentityUserDirectory` 只有按 `(tenantNId,userNId)` 查询，没有关键字、游标、限流或 `canStart` 投影；PF05 A05-01 明确要求最小 `items[{userNId,displayName,canStart}]`，并要求同租户有效人员可搜索。当前 Identity `UserSummary` 是管理员摘要，不能全量下发给普通聊天用户。

2. **现有 HTTP 目录适配未形成可证明的受信用户上下文。** `HttpIdentityDirectoryClient.GetAsync` 仅创建 named client 并调用 `GET api/v1/users/{id}`，代码没有给该请求设置或转发用户 Bearer，也没有 service identity、actor context 或外部宿主票据参数（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Infrastructure/Identity/HttpIdentityDirectoryClient.cs:61-90`）。它还在响应缺少租户字段时回退到调用参数 `tenantNId`，但没有对响应租户做显式相等校验。现有单测只证明 `EvaluateAsync` 会把 Bearer 转发到 `POST /api/v1/authorization/evaluate`，没有覆盖 `GetAsync` 的认证、租户不匹配或最小目录字段（`tests/SystemData/IndustrialPlatform.SystemData.Tests/Infrastructure_HttpIdentityDirectoryClientAuthorizationTests.cs:10-69`）。这不能被描述为真实 PF05 目录调用已通过。

3. **权限目录和导航当前没有 Collaboration 注册，但这属于 PF05 待实现项，不单独算作外部依赖缺口。** Identity `PermissionCatalog.FirstBatchNIds` 及其 121 项契约测试目前只包含 Identity/SystemData/ReferenceData/Platform 权限，没有任何 `collaboration.*`（`src/backend/src/Services/Identity/IndustrialPlatform.Identity.Domain/Permissions/PermissionCatalog.cs:198-320`；`tests/Identity/IndustrialPlatform.Identity.Tests/Domain_PermissionCatalogTests.cs:137-158`）。SystemData baseline 的权限清单同样只到 systemdata/reference/identity，默认资源只有现有首页、Identity、SystemData 和 ReferenceData 页面（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Infrastructure/Reliability/SystemDataBaselineSeedRunner.cs:19-65`）。其初始化器调用 `VerifyAsync` 只验证 Identity 中已经存在的权限，不能创建缺失权限（同文件 `:167-218`；`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Infrastructure/Identity/HttpIdentityDirectoryClient.cs:34-58`）。前端现有测试明确阻止尚未实现的聊天假入口（`src/frontend/src/components/navigation/navigation.ts:1-8`；`src/frontend/tests/unit/navigation.spec.ts:166-177`）。这些是 PF05-001/005/006 后续需要按已冻结契约增量注册的实现工作；在本门禁核验中保留为“待实现/待验证”，不把它们误报成 Identity 外部服务已经缺少的能力。另一个独立的设计缺口是 Collaboration manifest 的完整父子权限、资源类型、ResourceNId、RouteName、NavigationNodeNId、标题 key、终端和排序尚未冻结；实现任务不能自行发明这些注册字段。

4. **Platform/Embedded Collaboration 宿主尚未实现；外部身份交接契约仍需核验。** 源码下没有 Collaboration 后端宿主、聊天 API、Hub 或协作前端页面（`rg --files src/backend/src | rg -i 'collab|messag|presence|conversation|chat|hubs'` 得到 `NO_COLLABORATION_BACKEND_FILES`；生产源码检索 `collaboration|messaging|presence|conversation|chat_attachment` 无命中）。前一部分是 PF05-001/005/006 的待实现工作，不应当作为“外部依赖不存在”的证据；真正需要总控确认的外部契约是 Platform Identity 最小目录/受信调用语义，以及 Embedded 参考身份的 issuer/audience/nonce、防重放、停用传播和受信有效期。后者目前没有可验证实现或运行证据。

### 2.3 成功/拒绝样例与结论

可观察的既有成功/拒绝语义：

- **既有 Identity 管理成功**：认证主体持有 `identity.user.view` 时，`GET /api/v1/users` 的测试返回包含 `userNId` 的分页；`UsersController.Get` 对同租户有效用户调用管理服务返回 `UserSummary`（`tests/Identity/IndustrialPlatform.Identity.Tests/Api_ManagementEndpointTests.cs:43-60,327-338`）。这是管理接口成功，不是 PF05 最小搜索成功。
- **既有安全拒绝**：无认证 401；缺少策略权限 403 `ID_PERMISSION_DENIED`；身份安全版本不匹配或会话撤销 401；禁用主体 403；目录适配不可用按应用端口约定 503 `SD_IDENTITY_DIRECTORY_UNAVAILABLE`（上述认证测试和 `AdministrationErrors.cs:117-123`）。
- **PF05 必须补齐但当前没有的成功**：同租户有效搜索只返回 `UserNId/DisplayName/canStart`，服务端固定主体并取得 `conversation.start`，Platform/Embedded 目录映射和 Collaboration 权限/资源/导航得到真实注册回执。
- **PF05 必须补齐但当前没有的拒绝**：跨租户/不可见/不存在统一 `COLLAB_USER_NOT_FOUND` 404，停用目标 `COLLAB_USER_INACTIVE` 409，目录无法安全确认 `COLLAB_IDENTITY_DIRECTORY_UNAVAILABLE` 503，浏览器自报主体或重放/过期外部票据失败关闭。

结论：**G05-1 = BLOCKED（真实 Identity 管理依赖部分存在；PF05 最小目录/调用鉴权与 Platform/Embedded 受信身份语义仍未关闭）。** Collaboration 权限、资源、路由和菜单属于待实现项，不单独构成外部缺口；但实现后必须按真实注册回执和实际菜单再验收。在总控冻结公开契约并取得真实目录/受信身份证据前，不派遣或实现 TASK-PF05-001。

## 3. G05-2 File 授权、引用与多 Case 保全

### 3.1 真实依赖已存在

当前 `FileObjectV1` 字段为 `TenantNId`、`FileNId`、`FileName`、`ContentType`、`Length`、`Sha256`、`ScanStatus`、`Restricted`、可选 `Purpose`/`OwnerUserNId`、引用数量/摘要、`DeletionStatus`、`CreatedOn`、`RetentionUntil`（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Contracts/Files/FileContracts.cs:77-103`）。应用记录 `FileObjectRecord` 和 `FileReferenceRecord` 分别保存文件状态和 `(TenantNId,ReferenceNId,FileNId,OwnerUserNId,Purpose,CreatedOn,DeletedOn)`；`IFileService.OpenFileContentAsync` 只接收租户、用户、文件和可选引用（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Application/Files/FilePorts.cs:26-58,145-159`）。

真实下载逻辑位于 `FileService.OpenFileContentAsync`：先按租户查文件；`ScanStatus` 非 Clean 时 Pending/Unknown 返回 `FILE_SCAN_PENDING` 409，Malicious 返回 `FILE_MALICIOUS` 422；Restricted 或非 Active 返回 `FILE_ACCESS_RESTRICTED` 403；非文件 Owner 时必须存在同租户、同文件、且 `Reference.OwnerUserNId == caller` 的用途引用，否则 `FILE_ACCESS_DENIED` 403（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Application/Files/FileService.cs:251-265`）。HTTP `/api/v1/files/{fileNId}/content` 由 `systemdata.file.download` 策略保护，并把当前 Bearer 主体直接传给 File 服务；引用新增/删除由 `systemdata.file.manage` 保护（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Api/Controllers/FilesController.cs:194-223`）。

已有测试真实表达了两组拒绝语义：PendingScan/Unknown 不能下载、Malicious 返回相应错误；文件删除在 RetentionUntil 有效时返回 `FILE_RETENTION_ACTIVE` 409，保留期解除但仍有活动引用时返回 `FILE_REFERENCED` 409（`tests/SystemData/IndustrialPlatform.SystemData.Tests/Application_FileServiceTests.cs:102-134`）。这些测试没有覆盖成员用途引用下载成功、非 Owner 成员下载拒绝或真实跨服务调用。

### 3.2 设计/契约缺口

1. `FileObjectV1`、`FileObjectRecord` 和 `system_file_object` 没有 `FileStateVersion`/源版本，也没有条件授权 token、CaseNId 或多 Case 保全引用；数据库字段当前只有文件级 `RetentionUntil`、`Restricted`、`DeletionStatus`。物理实体定义可见 `src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Infrastructure/Persistence/Entities/Pf04Tables.cs:30-75`。其中 FileStateVersion 缺失已被 PF05 规格明确允许：以受权即时查询、记录 `FileObservedOn`、单飞重查和安全降级为准，**不要求为了关闭 G05-2 临时新增或伪造源版本**。

2. 当前 File 下载授权模型只有“文件 Owner 或 FileReference Owner”，同租户的 ConversationMember 不自动获得下载权；`AddReferenceAsync` 把引用 Owner 固定为当前用户（`FileService.cs:275-285`）。没有受信 Collaboration 服务身份、签名 actor/member scope、消息撤回/处置状态、用途/会话绑定或授权撤销后的重新授权契约。不能让 PF05 以上传者身份代理另一成员下载。

3. 当前删除保护只检查单个文件的 RetentionUntil 或任一活动普通引用（`FileService.cs:319-327`），没有 `CaseNId` 级幂等创建/释放、多个 Case 并存、释放 Case A 后 Case B 仍阻止清理的真实契约。PF05 规格要求 File 保全引用优先于普通引用释放，并以 Case 范围和版本二次检查；这一能力不能由当前 File API 推导。

4. PF05 细化规格明确要求 `FileStateVersion` 缺失时只能做受权即时查询并记录观察时间，禁止伪造源版本；附件绑定与下载还要有单飞重查、失效降级、撤回/处置后再次授权失败的语义。当前没有 Collaboration adapter、ChatAttachment 表或真实 File Gateway；这些是 PF05-004 的待实现工作，不能提前假造上传 URL。FileStateVersion 本身不是本门禁要求 PF-04 新增字段的理由。

### 3.3 成功/拒绝样例与结论

- **既有逻辑允许的下载成功（尚无独立成功测试）**：File 为 `Clean` 且 `DeletionStatus=Active`，调用人等于 `OwnerUserNId`；或 FileReference 为活动引用、其 `FileNId` 匹配且 `OwnerUserNId` 等于调用人，服务随后打开物理内容。
- **既有拒绝**：不存在/跨租户按 `FILE_NOT_FOUND` 404；扫描中/未知 `FILE_SCAN_PENDING` 409；恶意 `FILE_MALICIOUS` 422；受限/删除态 `FILE_ACCESS_RESTRICTED` 403；同租户另一会话成员没有匹配用途引用 `FILE_ACCESS_DENIED` 403；保留期/普通引用阻止删除分别为 `FILE_RETENTION_ACTIVE`/`FILE_REFERENCED` 409。
- **PF05 必须补齐但当前没有的成功**：受信 Collaboration 校验成员和消息普通投影后，按 `FileNId + Conversation/Message/Attachment + actor` 建立业务引用；两个独立 Case 同时保全同一附件，释放一个 Case 后另一个仍能阻止清理；每次下载重新取得 File 最终授权。
- **PF05 必须补齐但当前没有的拒绝**：非成员、跨租户、用途/消息不匹配、撤回/处置、陈旧授权、File 状态变化、保全登记失败和伪造服务身份均安全拒绝或失败关闭，且不返回未扫描文件或长期 URL。

结论：**G05-2 = BLOCKED（File 基础扫描/Owner/引用/保留拒绝语义真实存在；File 侧受信业务授权与多 Case 保全/解除契约未关闭）。** `IChatFileGateway`、ChatAttachment 和本地单飞重查适配属于 PF05-004 待实现项，不单独作为前置循环门禁；FileStateVersion 缺失按既定安全即时重查方案处理，也不是额外阻塞项。TASK-PF05-004、依赖其真实 File 契约的 007/008 不得生产准入。

## 4. G05-3 Audit、短时提权与独立审批

### 4.1 真实依赖已存在

当前 Audit 入站请求实际字段为 `ProducerServiceKey`、`AuditEventNId`、`OccurredOn`、`ActorUserNId`、`Action`、`ObjectType`、`ObjectNId`、`PayloadJson`、`TraceId`、`Severity`、`SourceIp`、`UserAgent`；对外 `AuditFactV1` 返回租户、生产者、事件、发生/接收时间、主体、动作、对象、受控 payload、trace 和 severity（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Contracts/Auditing/AuditContracts.cs:3-32`）。持久 `AuditFactTable` 还存 PayloadHash、SourceIp、UserAgent；另有生命周期、入站失败和 Outbox 表（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Infrastructure/Persistence/Entities/Pf04Tables.cs:133-193`）。

`AuditService.IngestAsync` 会要求 producer/event/action/object，清洗 payload，按 `(tenant,producer,event)` 查重；同 hash 重放返回既有事实，不同 payload 返回 `AUDIT_FACT_CONFLICT` 409；数据库失败写独立 failure sink 并返回 `AUDIT_WRITE_UNAVAILABLE` 503（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Application/Auditing/AuditService.cs:33-70`）。当前 Audit resilience 测试覆盖主存储/事务失败落盘与恢复、`AUDIT_WRITE_UNAVAILABLE`、法律保全删除拒绝 `AUDIT_LEGAL_HOLD_ACTIVE`、删除缺保留期 `AUDIT_RETENTION_REQUIRED` 以及清理策略（`tests/SystemData/IndustrialPlatform.SystemData.Tests/Application_AuditResilienceTests.cs:13-145`）。

### 4.2 设计/契约缺口

1. 真实 HTTP 入站 `/api/v1/audits/facts:ingest` 只接受 `ClaimConstants.ServiceKey == "systemdata"`，否则 403 `AUDIT_TRUSTED_CHANNEL_REQUIRED`；请求中的 producer 只要不是 `systemdata` 就 403 `AUDIT_PRODUCER_UNTRUSTED`，通过后由控制器强制覆盖为 `ProducerServiceKey=systemdata` 并把 Actor 覆盖为当前用户（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Api/Controllers/AuditsController.cs:21-32`）。因此 `ProducerServiceKey=collaboration` 当前一定不能落真实 Audit，不能把现有 SystemData 入口当作 PF05 已接入。

2. PF05 要求 Collaboration 以受信服务身份映射 `producer=collaboration`，payload 只含受控元数据，不传原始 SourceIp/UserAgent，并保留受签名 actor context；当前入站契约允许 SourceIp/UserAgent，且没有 Collaboration service identity 或 actor context 适配。现有测试只证明 SystemData 的 Bearer evaluation 转发，不证明 Collaboration producer 或受控 actor 成功。

3. Identity 的当前 Access Token/claims 没有 assurance、step-up、最近认证时间、动作/范围绑定或审批主体字段；针对 `step.?up|assurance|elevat|recent.?auth|reauth|second.?factor|mfa|read.?original` 对 Identity/SystemData 生产源码检索没有命中。Identity bootstrap 的 `recoveryReference/approvalReference` 只属于一次性管理员恢复，不是可供合规查看、导出和解除保全复用的高风险提权/独立审批契约。这里的 Identity step-up/assurance 是 G05-3 需要确认的外部安全依赖；Collaboration 自身的导出/解除保全审批状态机属于 PF05-007 待实现项，不把“当前没有自身审批代码”误报成外部服务缺口。

4. 当前 Audit lifecycle 只有事实级 `Active/Archived/Deleted`、一个 `LegalHold`/`LegalHoldReason` 和 RetentionUntil；没有 PF05 `compliance_view`、异步 `ExportRequest`、checksum 绑定批准者、申请者禁止自批、Case 版本和双人解除保全状态机。前半部分（Collaboration 的合规查看/异步导出/自身审批/Case 业务状态机）是 PF05-007 待实现项；现有同步 `ExportCsvAsync` 是 SystemData 审计导出，不得作为 PF05 合规原文导出流程（`src/backend/src/Services/SystemData/IndustrialPlatform.SystemData.Application/Auditing/AuditService.cs:90-113`）。

### 4.3 成功/拒绝样例与结论

- **既有 SystemData 成功**：带 `service_key=systemdata`、`systemdata.audit.write` 且请求字段完整时，控制器固定 producer/actor 后进入 `AuditService`；同一 producer/event/payload hash 可幂等重放，数据库故障则进入失败落盘而不是伪造成功。
- **既有拒绝**：缺失或非 `systemdata` 服务声明 403 `AUDIT_TRUSTED_CHANNEL_REQUIRED`；请求 producer 非 `systemdata` 403 `AUDIT_PRODUCER_UNTRUSTED`；同一事件不同 payload 409 `AUDIT_FACT_CONFLICT`；主存储不可用 503 `AUDIT_WRITE_UNAVAILABLE`；法律保全事实删除 409 `AUDIT_LEGAL_HOLD_ACTIVE`；删除没有 RetentionUntil 422 `AUDIT_RETENTION_REQUIRED`。
- **PF05 必须补齐但当前没有的成功**：受信 `collaboration` 服务主体被服务端固定映射，受控 actor/租户/动作/对象/结果/版本写入持久 Audit；五分钟内、动作和范围匹配的短时提权允许一次原文查看；非请求者对未变 checksum 的导出或解除保全完成独立审批。
