## 已从代码确认的缺口

1. **可靠消息投递缺执行链（002/005）。** `SqlCollaborationRepository.cs:204` 事务写入 CollaborationOutboxTable；全后端/参考宿主查找该表及表名，仅有迁移、初始化读取及这处写入。DI 仅注册 CollaborationExportWorker，未找到该 Outbox 的扫描、发布确认、published_on 更新或死信重试执行器。Controller/Hub 当前直接 SendAsync，无法补偿“数据库提交后进程退出、推送失败”等窗口。
2. **普通保留清理未实现完整闭环（007）。** 消息/附件保留天数有 DTO、校验和持久化；RetentionFloorSequence 有读取和历史过期判断，但未找到按策略推进边界、清理正文/附件引用、保全跳过及故障续跑的后台执行路径。已有导出产物过期清理不等于普通聊天历史清理。
3. **应用级聊天连接和提醒未接入（003/006）。** createCollaborationRealtime 只在 CollaborationChat.onMounted 创建，onBeforeUnmount 停止；20 秒续期存在，但只随聊天组件运行。未找到平台顶栏聊天抽屉、登录态级连接/未读 Store。订阅仅在选择会话时加入对应组，不能据此宣称未打开聊天或未选中会话也能持续收提醒。
4. **多实例实时分发未接入（003/005）。** Presence 使用 Redis 不代表 Hub 已有跨实例背板；模块仅 AddSignalR，未找到背板注册。实际两实例一致性仍未验收。
5. **发送失败重试存在重复消息风险（002/006）。** CollaborationChat.sendMessage 每次调用重新生成 clientMessageNId。若服务端已接受但响应丢失，再点击发送会使用新 ID；当前未接入按原 ID 查回执/重试、pending/failed 项或消息 ACK 合并。后端幂等已实现不能弥补前端丢弃幂等标识。
6. **实时状态校正不足（002/006）。** 前端主要监听 message.accepted/presence/typing，消息处理只做 messageNId 去重追加；未找到撤回、处置、已读等状态事件的版本合并。重连仅重载当前一页历史，未证明完整旧窗口校正；会话列表固定取 100 条，未继续消费列表游标。
7. **四个合规菜单缺后端接入（006/007）。** `SystemDataBaselineSeedRunner.CollaborationResources/CollaborationNavigation` 仅列三端聊天，未列受控查看、保全案件、导出记录、保留策略。前端 navigation.ts 和 routes.ts 声明不能替代已配置租户的资源/菜单增量发布。
8. **合规页面仍有功能和交互缺口（007）。** CompliancePage 将 readOriginal 固定为 false，未提供显式原文查看；导出列表只有审批，没有后端已有的授权下载动作；保全页面只调用 review/release-request，没有 release-approve 操作。保全/导出采用原生 table 和常驻表单，未完整遵循用户管理黄金样板的 AppDataTable、业务弹窗和“更多”动作组织。单纯补菜单后仍不能标记页面完成。
9. **附件事件与故障处理未闭环（004）。** 上传、下载重新授权、File 保全同步已有代码，但未找到 Collaboration 对 File 状态变化的实际事件消费注册/Inbox。不能将请求时授权重查或保全同步 Worker 等同于全部扫描、删除、隔离、引用对账流程完成。
10. **运行可观测性不足（001/007）。** AddCollaborationHealthChecks 直接返回固定 Healthy，未实际检查数据库/积压/后台任务状态；未找到方案要求的 Collaboration 专项 Meter/Counter/Histogram、积压/清理/故障告警实现。

以上是可追踪的实现/接入缺口；未将接口中的有意不支持流写入、默认接口方法抛异常或 HTML placeholder 误计为未实现业务。
