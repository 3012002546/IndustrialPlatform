# 开源 Spreadsheet 独立验证

日期：2026-10-30。范围：PF09 临时查询表格的开源实现可行性；不修改产品代码。

**最新结论：浏览器临时查询表格方向可行，仍不作为生产方案验收通过。** 第二轮已补齐受支持的筛选条件导出，定位并修复重复刷新保留旧画布的引用链，完成现有 CMP 台账 XLSX 的受限导入、填充、公式重算及输出。真实平台登录和已发布报表读取已成功，但当前可选报表分别存在字段不匹配、固定版式类型不适用，尚未完成真实 Query 结果填入 CMP 的成功链路。第 3～4 节保留首轮测量记录，第二轮结果及限制见第 7 节。

## 1. 实验位置与依赖

样例位于仓库忽略目录 `.run/oss-spreadsheet-poc`，页面为 `http://127.0.0.1:19382/`。基础填充使用合成数据；另设正常登录的本地平台查询验证入口，两者独立。启动命令为在该目录执行 `npm.cmd run dev`；关闭服务后链接不可用。实验依赖及构建产物不纳入产品依赖或提交。

| 部分 | 本次版本及用途 |
| --- | --- |
| Univer | `@univerjs/presets`、core/filter/sort presets 均为 1.3.1 |
| Vue | 3.5.22，Composition API；SDK 实例不放入深层响应式对象 |
| XLSX | ExcelJS 4.4.0，独立编写受限的快照转换适配 |
| 打印 | 当前编辑快照转 HTML 表格，再调用浏览器打印；测试使用 Edge PDF 输出 |
| 构建 | Vite 7.1.7、Vue 插件 6.0.1、Node 24.18.0 |
| 验证 | Edge headless、Playwright；openpyxl 独立读取 XLSX；pypdf/pdfplumber 读取及渲染 PDF |

当前平台前端的 Vue/Vite 版本与样例不同；独立构建成功不等于已完成平台版本组合验证。

锁文件中未发现 `@univerjs-pro`；所检查的 28 个 `@univerjs` 包声明 Apache-2.0，ExcelJS 声明 MIT。这是指定包版本的许可证据，未代替完整传递依赖、NOTICE 和目标发布协议的审核。本次没有复制 DevExpress 代码、资源或协议实现。

官方现有[导入导出入口](https://docs.univer.ai/zh-CN/guides/sheets/features/import-export)使用 Pro 交换能力，[打印入口](https://docs.univer.ai/guides/sheets/features/print)也属于 Pro 扩展。因此样例仅复用开源编辑内核，下载和打印采用本次受限适配；这不代表复制或替代了完整商业能力。

## 2. 生命周期及服务器负担

共享模板描述工作表、字段、类型、样式及填充区。每个页面独立持有当前工作簿内存；点击样例填充把合成结果填入模板。刷新前提交编辑状态，确认替换后释放整个编辑器及其服务作用域，再创建当前代次的内存模型，避免只删除工作簿而残留旧画布。它没有业务文件身份、版本历史，也不调用 WOPI。

普通查询和编辑不生成服务器结果文件，不使用 localStorage/IndexedDB 保存查询数据。下载时才在当前浏览器生成 XLSX Blob，触发下载后撤销对象 URL；打印时生成页面内的打印文档。测试目录中的 XLSX/PDF/截图是自动化主动保存的证据，不是运行页面每次查询自动产生的副本。

用户选择下载后形成的本机文件属于用户输出，不应随查询页退出删除。正常关闭组件执行 SDK dispose，页面重载重新显示空模板。异常退出无需依赖一次“删除服务器工作簿”请求来防止服务器文件累积；浏览器缓存、后台页和内存回收仍需要实际集成时验证，不能承诺关闭瞬间操作系统占用归零。

真实平台接入仍需对查询行数、单元格数、响应字节数、并发请求和超时设上限；取消与代次检查防止旧响应覆盖新查询。大导出若改为服务端任务，必须单独设计任务配额、超时与清理机制，不能把“浏览器编辑不落文件”扩展成“所有输出都没有服务端成本”。

表头：工单、工序、批次、产品、计划量 L、实际量 L、质量状态、复核人。六条合成记录包含放行、待检、复核等状态。

| 真实键盘编辑 | 名称框定位 F2，输入 399.5；提交后的工作簿快照为数值类型，XLSX 解析也为数值 |

格式、筛选和排序测试验证的是 SDK 功能路径；未把它们描述为全部菜单点击交互已验收。多报表入口是建议复用方式，本样例只实现一个固定的八列模板。自定义列、跨区域填充、合并、图片、图表、公式兼容和任意 XLSX 模板导入需另行覆盖。

### 实际输出文件

下载文件经 openpyxl 读取：F2=399.5、类型 `n`、加粗、底色 `FFFFF2CC`、数值格式 `0.0`；第 5、6 行隐藏；AutoFilter=`A1:H7`；冻结位置 A2。

**导出缺口：筛选条件数量为零。** 目前只保存了筛选区域和隐藏行，未保存“质量状态=放行”条件。正式实现必须保存支持的条件，或明确提供“仅导出可见行”的语义；不能把隐藏行当作完整筛选状态。当前 XLSX 包含全部六条记录，打印只包含筛选后的四条，两者的范围选择也需在产品中明确。

打印 PDF 为一页 A4 横向，包含修改后的 399.5、加粗和底色，不包含被筛掉的两条记录。已渲染查看中文及列布局；未实测物理打印机、多页重复表头和超宽列打印。当前打印对齐和样式转换是受限实现，不保证与编辑器像素一致。

## 4. 首轮资源与构建结果（保留问题发现过程）

连续刷新测试执行 120 次，SDK 对最近 30 个退役 ID 的查询均为空，当前已知活动工作簿计数为 1。该计数是应用跟踪口径，不是全堆存活对象扫描。

第一轮后台多页测试出现堆增长，因此增加单页专用测试，每次替换等待两个动画帧，在每个采样点执行两次强制 GC。结果如下，单位为十进制 MB：

| 采样点 | JS 已用堆 | DOM 节点 | JS 事件监听器 |
| --- | ---: | ---: | ---: |
| 刷新 20 次 | 43.09 | 815 | 529 |
| 刷新 70 次 | 45.23 | 816 | 530 |
| 刷新 120 次 | 46.78 | 816 | 530 |
| 显式关闭编辑器 | 38.36 | 740 | 251 |
| 页面重载 | 34.09 | 755 | 507 |

DOM 和监听器没有随刷新次数持续增加，但 JS 堆仍增长约 3.69 MB。证据尚不能区分模块缓存、延迟资源与真实泄漏，因此“长期重复刷新资源稳定”未通过最终判定。需捕获堆快照及保留链，或比较原位填充和重建实例策略；不能只依赖 dispose 返回成功。

合成数据单次测量：1,000 行约 1.56 秒、10,000 行约 2.01 秒，包含模型替换并等待两个动画帧。开发模式、同机负载和浏览器状态会影响结果；这些数字不是性能 SLA、生产并发容量或完整首屏绘制基准。

`npm.cmd run build` 退出码 0。主 JS 约 8,020 kB、gzip 约 2,185 kB，CSS 约 125 kB；另有动态语言资源。构建包含 React 依赖的 `use client` 忽略提示及大 chunk 警告。产品接入应按路由加载并测量实际网络请求、解析时间和导出适配拆包效果。

## 7. 第二轮修复与真实模板验证

### 7.1 筛选条件导出

ExcelJS 默认仅写 AutoFilter 范围。样例新增 OOXML 适配，在工作表或 Excel Table 的 AutoFilter 中写入 `filterColumn`，同时保留隐藏行。

已验证：多列组合、值集合、空白、含 XML 特殊字符的文本、数值比较及 AND/OR、通配符。三份导出文件均由 openpyxl 独立解析核对条件和隐藏行。颜色筛选明确拒绝导出，未假装完整支持所有 Excel 筛选类型。XLSX 保存全部当前结果和筛选条件，打印仅输出当前可见行。

证据：`verify-filters.mjs`、`verify_filter_files.py`、`evidence/filter-cases/`。新增直接依赖 JSZip 3.10.2，仅用于实验的 XLSX ZIP 读写；包声明 `MIT OR GPL-3.0-or-later`，本实验按 MIT 选项评估，不推导平台必须采用 GPL。

### 7.2 连续刷新内存

堆快照定位到 Univer 1.3.1 的 `SheetSkeletonService._sceneMap`：只执行 `disposeUnit/createWorkbook` 后，旧 Scene、Canvas、Engine 和 ResizeObserver 仍可从长期存活的注入器到达；额外 100 次刷新增加约 100 组相关对象。根引用链经过 `FUniver._injector → SheetSkeletonService._sceneMap → Scene._beforeRender$ → Canvas`。这证明原先不能仅凭活动工作簿 ID 已删除来判断释放完成。

样例改为每次替换结果都释放 Facade、Univer 实例及其完整作用域，再建立当前实例；没有修改 node_modules、使用私有缓存清理或刷新整个网页。固定构建下第 100 与第 500 次刷新堆快照比较，Canvas、Scene、Workbook、EventSubject 的数量不再随刷新累积。

| 测量方式 | 采样点 | JS 已用堆，十进制 MB | DOM / 监听器 |
| --- | --- | --- | --- |
| 正常 JIT | 100 / 500 / 1000 次 | 35.03 / 38.71 / 41.54 | 均为 807 / 527 |
| 禁用 JIT 的诊断进程 | 100 / 300 / 500 次 | 25.92 / 25.99 / 26.05 | 均为 806 / 526 |

正常模式总堆仍有增长；快照增长主要落在编译代码，禁用 JIT 诊断的后 200 次仅增加约 57 KB。**结论限于已确认的旧编辑器对象泄漏已修复；不能承诺所有负载下总堆恒定或无限次刷新已验证。** 禁用 JIT 只用于独立诊断进程，不作为产品配置。测试使用固定构建、等待渲染和强制 GC；现场浏览器的自然 GC、长会话、大数据及多页并发仍需容量验证。

证据：`heap-investigate.mjs`、`heap-diff.mjs`、`heap-paths.mjs`、`memory-soak.mjs`；`evidence/heap/` 为原保留链，`evidence/heap-fixed-stable/` 为修复后快照，`evidence/memory-soak.json` 与 `memory-soak-jitless.json` 为测量。`heap-fixed/` 的中断尝试不作结论依据。

### 7.3 现有 CMP 台账 XLSX

使用用户选定的 `outputs/01a18156-03aa-7d41-8a25-4788bc456eff/样例-CMP批次产量台账.xlsx`。这是现有真实 XLSX 文件，文件中的业务记录仍为样例数据；原文件不修改。原 SHA-256：`B57C521F7F81A98B600BBA7E7456FC8A1C2C912D0C9BA21E3413521BF6B3A677`。

文件具有标题、汇总公式、十列 Table `A7:J13`、六条数据、冻结位置 D8、数值及百分比格式、质量状态验证和条件格式。导入适配处理 SpreadsheetML 的 `x:` 前缀及 OPC 绝对关系路径，解决本文件在 ExcelJS 4.4.0 中的读取失败；只在内存中规范化 XML。前缀兼容问题亦有 [ExcelJS 官方仓库问题记录](https://github.com/exceljs/exceljs/issues/1437)。这不是任意 XLSX 的完整转换器。

已通过：

- 空模板加载后填入六行，十列表头默认提供筛选；汇总计划量 2490、实际量 2480。
- 修改 F8 为 399，汇总实际量变为 2481；导出同时保留公式和当前缓存结果。
- 质量状态筛选为“放行”，Table 筛选条件写入列 8，Excel 行 11、12 隐藏，打印仅显示四条明细。
- 6→2→0 刷新，实际合计分别为 2480（原样例）、800、0；旧尾行及筛选状态被清除。
- openpyxl 独立确认数值、公式、D8 冻结、筛选范围和条件、有效数据验证规则及条件格式范围保留。ExcelJS 会把原验证范围写成两个重叠的相同规则，验证按各单元格有效规则比较，未以记录条数冒充语义差异。

限制：当前仅针对这份六行模板，超过容量明确拒绝，不截断；尚未实现行扩展和公式引用重定位。验证规则和条件格式保留在下载文件，未完整映射为浏览器交互。打印是受限 HTML 表格，标题/说明文字的跨空单元格显示不与原 Excel 完全一致，未承诺打印版式保真。

证据：`verify-cmp.mjs`、`verify_cmp_file.py`、`evidence/cmp/results.json`、`outputs.json`、`edited.xlsx`、`filled.png`、`print.png`。

### 7.4 平台接入实际结果

样例通过仅本机的 Vite 代理调用现有标准接口，用户手动正常登录；密码与令牌仅驻留页面内存，不保存到文件或浏览器存储。不创建、修改或发布平台资源，不改产品代码。

2026-10-30 用户登录后，样例成功显示已发布报表，并针对选择的单个报表读取其修订：

- `PF09-本轮回归-默认排序-20261030`：Query 报表，但未满足 CMP 的八字段映射，被校验拒绝。
- `样例-CMP批次生产汇总报表`：固定版式报表，被 Query 模式校验拒绝。

因此，**真实平台仅验证到登录、元数据读取、单个修订读取和不匹配拦截；未实际完成发布查询接口返回结果后的 CMP 填充。** 当前目录只加载前 20 项中的已发布报表，不能据此声称平台没有其他合适报表。下一步应提供或选择匹配八字段的已发布 Query 报表，明确字段映射；无需为验证修改现有固定版式报表。

另用完全虚构的 API 响应验证接口契约：两行映射后合计 298；总数超六行拒绝且保留当前结果；取消请求后旧响应不覆盖当前编辑。`verify-platform-contract.mjs` 和 `evidence/platform-contract.json` 属于模拟契约证据，不等同真实授权查询、多账号隔离或数据库连接验证。

此前自动审批拒绝过“从 E2E 文件提取管理员凭据并导出全部报表文档”的脚本，未执行；本轮改为用户正常登录和单个选定修订读取，没有绕过该限制。
