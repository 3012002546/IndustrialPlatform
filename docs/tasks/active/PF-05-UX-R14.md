- 消息同时提供右键和可见“更多”按钮；用户本轮明确要求移除可见“更多”。

## 1. 顶栏顺序

聊天按钮紧邻“消息通知”的左侧，不只是在其左边某处。将入口插入真实通知按钮前的布局位置，必要时用最小插槽扩展 PlatformSessionControls；不要复制通知逻辑、重排无关控件或改变通知权限。键盘顺序应与视觉顺序一致。无聊天权限仍隐藏聊天入口，通知正常。

## 2. 左侧会话列表

```text
会话筛选 / 发起入口
┌ 头像  姓名（单行…）               时间 ┐
│       最后一条消息预览（单行…）   未读 │ 固定 72px/行
└───────────────────────────────────────┘
后续会话同样紧凑排列，列表独立滚动，余下空间留空而不拉伸单行。
```

默认固定行高 72px，头像占位约 40px；姓名/预览 min-width:0、单行 text-overflow:ellipsis，时间与 badge 不被挤掉。图片参照信息结构，沿平台主题，不复制绿色背景和服务号业务。在线点可叠在头像旁，保留文字/可访问说明。会话为 1、10、100 条时行高一致；仅列表滚动，不撑高完整页或弹窗。

预览显示本人或对方最新一条可见消息，不依赖打开会话才获得。文本压缩换行为一行；图片/文件用本地化类型摘要；撤回显示墓碑提示，不泄露正文；个人隐藏/合规限制不在预览重新泄露。无消息为空态摘要。重登、重连、ACK、对方推送、撤回、个人隐藏后应一致更新摘要与顺序。

接口最小增量：复用已有等价字段，否则在 ConversationSummaryDto/前端对应模型添加可空 `lastMessagePreview`：`{messageNId,sequence:string,acceptedOn:RFC3339,messageType,state,text?:string}`。正文最多 160 个字符，仅返回当前成员有权查看的最新消息摘要，绝不返回合规原文/附件敏感元数据；无可见消息为 null。文本由后端安全投影产生，前端本地化类型/墓碑，不渲染 HTML。沿既有租户/成员/个人可见性规则按当前分页批量查询，不为每条会话在浏览器额外请求消息历史，也不引入每行独立后端查询。增量查询不应需要修改既有迁移；如发现必须新增结构，先沿现有版本化规则明确增量再做，禁止重写已应用账本。

## 3. 本人消息右键菜单

PC 消息上不显示“更多”按钮；右键打开复制/撤回/仅为我删除。鼠标在菜单外任意位置按下即关闭；Escape、切换会话、关闭弹窗时关闭；点菜单项必须先执行一次动作再关闭，避免 document 事件抢先清空目标。菜单限于视口内。保留无可见按钮的键盘 ContextMenu/Shift+F10 入口；不影响已有移动端必要触控能力。保留现有权限、撤回窗口、墓碑无正文操作与个人隐藏隔离。

## 4. 发送后焦点

按钮发送与 Enter 发送后，当前活动输入框立即保持/恢复焦点，可直接连续输入下一条。不必等 ACK 或额外刷新才允许继续编辑；IME composition 不误发送，失败可重试且不丢新草稿。网络返回后不得清空发送期间新输入的文本，也不得跨会话/跨弹窗抢焦点；用户主动切换到别处时不强制拉回。

## 5. 收发自动滚到底

本轮新要求覆盖 R13“新消息进入仍保留消息区滚动位置”的旧验收断言。当前可见的会话，在本人发送待发送项、ACK合并或收到对方新消息后，DOM更新完成时滚到最新消息底部；图片等异步内容改变高度时也应保持底部。只作用于当前活动会话/聊天表面，不滚动整个页面或左列表。

只有实际新消息/发送才触发滚底；Presence/未读后台刷新不拉动列表。用户主动加载更早历史时保持锚点，不立刻跳回底部。两个聊天表面共用业务状态，各自管理 DOM 引用与可见性，不使用已卸载表面的闭包操作滚动或焦点。

## 6. 自动已读与顶栏即时同步

当前会话在可见、活动的聊天表面内且浏览器文档有焦点时，收到对方消息自动提交已读；右侧聊天区域任意位置点击/聚焦也将当前已展示最高已提交序号标已读。不能以仅 mounted、隐藏抽屉、后台标签或其他当前会话的消息作为已读依据。焦点恢复时检查当前已展示新消息；不能把未加载的历史/未显示会话一并读掉。

复用一个会话/未读状态来源，页面、顶部按钮badge、顶部聊天窗及同用户其他设备从该来源收敛。markRead成功回执直接合并游标/未读/投影版本，同时更新顶栏，不等待再打开窗或下一轮整表刷新。总未读覆盖未加载分页/未打开聊天表面，不能只对筛选后的可见列表求和。晚到旧列表/旧事件不能复活已确认的未读；跨账号/租户切换全部清理。

已读写入按会话合并最高序号，防止点击区域、focus、实时事件、多表面叠加产生重复风暴；请求进行时有更高序号则完成后继续推进。失败保留可重试状态，不永久伪清零。后端权威序号/权限保持不变，对方已读指示继续正常，不能为清badge直接写0或 bypass API。
