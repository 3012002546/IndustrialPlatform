## 修改决定及线框

### 1. 顶部弹窗和完整聊天页

```text
顶部弹窗：固定 960 × 680（视口不足时限制在视口内，边距至少 16）
┌ 协作消息                                  打开完整聊天  × ┐
├ 会话筛选/人员入口（左 280） ┬ 对方姓名 ● 在线/离线           ┤
│ 会话列表，独立滚动          │ 消息历史，独立滚动             │
│ 保持选中与滚动位置          │ 本人消息：状态/右键操作         │
│                            ├ 输入区、附件、发送（固定）      │
└────────────────────────────┴───────────────────────────────┘
完整页：同一聊天内容填满 shell 可用宽高；无外层表单 footer 或嵌套大空白。
```

- 宽高不随消息和会话数量变化；整窗不产生内容滚动，左侧会话、右侧消息区域各自滚动。滚动条鼠标进入所属区域时显示；focus-within/触屏仍可操作，避免出现/隐藏时布局跳动。
- 完整页与弹窗复用业务状态和实时连接；切换保持草稿/会话，不建立重复 Hub、计时器或事件订阅。消息列表布局 min-height:0，输入区不被推出视口。
- 静默刷新仅更新数据，不清空列表、不闪 loading、不重置选中和滚动；首次加载与用户显式筛选仍有适当反馈，失败保留数据，乱序响应不能覆盖新状态。
- Presence 用绿色圆点在线、灰色圆点离线并配文字/可访问名称；未知/断线状态保持独立，不能伪装离线。
- 本人已发送消息以 peerMember.lastReadSequence ≥ message.sequence 判定已读；初始化读取详情，后续按对方 read-cursor 事件单调推进，重连补齐，不以本人 unreadCount 判断。页面和弹窗一致。

### 2. 消息操作和发送响应

- 本人消息右键菜单：复制、撤回、删除（仅自己）。提供键盘/更多入口；复制仅复制可见正文，撤回复用权限/时间窗口及墓碑逻辑，失败有明确反馈。撤回后的内容不可复制。
- 删除只影响当前租户当前用户视图，刷新/重登后保留；不得删除对方内容、全局消息、附件引用、已读序号、合规原文或保全事实。
- 如没有可复用的个人消息隐藏能力，限定增加技术投影 `collaboration_message_personal_visibility`：tenant_n_id/user_n_id/conversation_n_id/message_n_id 沿用规格 nid/key 长度，hidden_on 为 UTC 时间；PK(tenant_n_id,user_n_id,message_n_id)，索引(tenant_n_id,user_n_id,conversation_n_id,message_n_id)。新迁移编号，不改旧迁移与 checksum。
- API `PUT /collaboration/api/v1/conversations/{conversationNId}/messages/{messageNId}/personal-visibility`，请求 `{hidden:true}`，响应 `{messageNId,hidden:true}`；幂等同请求，复用 messaging.write 且校验成员身份、同租户及本人发送者。拒绝 hidden:false（本轮不扩展恢复 UI）。历史/补拉/实时投影对当前用户一致过滤；同用户其他设备需要收敛，事件只通知本人。DTO/规格增量由开发记入交付说明，主控据证据收敛。
- 点击发送立即显示待发送条目；服务端 ACK 后合并正式消息，及时释放输入区，不等待全量消息/会话重载。clientMessageNId 在失败重试中稳定，ACK/Hub 事件去重及乱序合并；不允许乐观 UI 把失败标为成功。后台刷新合并会话摘要，尽量减少全量往返。
- 同环境记录改前/改后至少 20 次文本发送的点击→本地反馈、请求 ACK、对方可见耗时及请求数（中位数/P95）；本地待发送反馈目标 ≤100ms，ACK 后 UI 合并不再等待额外列表请求。隔离账号/租户验证，不向真实联系人发送测试消息。

### 3. 四个管理页面统一黄金样板

- 采用现有“四个页面、四个导航”：受控查看、保全案件、导出记录、保留策略各有独立路由标题/内容，去掉页内重复导航 Tab。保留现有 routeName、权限和已发布导航；内部可复用组件，避免四份复制业务逻辑。
- 参照 IdentityUsersPage：AppPage 标题/操作，AppQueryPanel 查询，AppDataTable 表格及业务 toolbar-actions，操作列更多，AppFormDrawer 业务表单。不可只套外壳而仍使用未样式化原生按钮/输入。
- 深色主按钮使用 on-primary 浅色文字，所有明暗主题的普通/危险/禁用/选中状态可辨。修复作用于协作或确有缺陷的共享插槽契约；不得全局覆盖按钮导致用户管理回归。

### 4. 受控查看再认证

- 打开页面仅显示查询条件和待查询提示，不自动拉取敏感内容/弹出密码框。用户明确点击查询、查看原文或其他受控业务操作后才验证范围并发起再认证；保留原权限、短时 proof、动作/操作者/会话/范围绑定及一次性消费。
- 使用黄金表单控件、footer 操作和 busy/防重入契约；展示“受控查看”等本地化动作名、人类可读的范围摘要，不把协议代码/原始 JSON 放在主要业务界面。
- 精确定位 createStepUpContext、Identity createStepUp、proof consume 中失败的一段：HTTP 状态、业务错误码、脱敏日志及生效配置来源。检查签发私钥/受信公钥匹配、路由、Audience、时钟和数据库账本，不以猜测设置默认密钥或绕过安全验证。
- 对确认为本地缺失的配置，沿既有私有配置/密钥管理机制补全必要的本地开发接入，私钥不得硬编码、输出或提交；不改远端 Docker 生命周期、不扩大权限、不停用户调试。若需重新加载进程，明确区分代码已修与现场未加载。
- 取消/失败不丢查询条件，密码不持久化；错误区分凭据错误、上下文失效、服务未配置/不可用，业务页面保持可继续操作。
