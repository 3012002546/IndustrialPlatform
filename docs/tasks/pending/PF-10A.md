# PF-10A KnowledgeHub 知识中心待派遣工作包

## 状态、负责人和目标

**派遣状态为待派遣，设计就绪度为待细化。** Codex 主控维护设计、代码边界与集成。项目负责人参与开发，具体认领范围和编码执行者在实际启动时登记。本包优先于 PF-10。

以同一份项目资料贯穿交付。用户从平台上传后能搜到原件、问到有出处的答案，再从当前会话查询获准数据、导航、导出或创建问题草稿。独立安装复用同一套知识和助手代码，通过项目适配接入现有 MES。问题整理与资料包迁移按辅助流程交付。

## 开发顺序与本人参与

| 顺序 | 可见结果 | 可亲自实现或跟代码的位置 |
| --- | --- | --- |
| 001～002 | 从平台菜单上传资料，原件可读，索引状态可见 | 菜单 → 上传 API → 文件扫描与绑定 → 有效修订/作业。可拿一份文件跟到业务记录。 |
| 003～005 | PDF、Word、Excel 能检索原文，助手给出可点击的依据 | 解析器 → 带定位的文本块 → 索引 → 授权检索 → DeepSeek 工具结果 → 原文阅读。可认领一种解析器及其回归样本。 |
| 006～007 | 处理问题、转为经验，并以对话执行平台行为 | 业务处理器 → 执行记录 → 结果卡。导航由页面回报到达和筛选结果。可认领一个页面行为或一个受控查询。 |
| 008～009 | 独立安装后使用相同功能，旧项目资料可选择合并 | 独立 Host → 本地或 MES 提供方；资料包 → 来源比较 → 新项目修订。可亲自实现一个 MES 字段/权限映射。 |
| 010～011 | 管理员可排查失败，发行包可初始化、升级和恢复 | 配置/诊断入口、辅助工具、发行脚本及双模式验收。按实际环境核对结果。 |

开工时先列当前步骤拟改的文件和第一条调试路径。项目负责人可直接认领业务代码，或跟着请求/结果走读；谁认领，谁写该文件，范围在本卡登记。切换用户流程时用实际改动清单更新负责人。涉及业务字段含义、返回数据范围、页面完成条件的变更由主控同步主规格，常规实现细节随开发推进。

## 前置条件、工程范围与验证

- **合同就绪度。** 数据、接口、页面按主规格 §13 的 D01～D08 和 §13.3 核对到各自使用时点。普通导入已定批次/逐项接口和数据合同。最先核验模块开关与真实迁移、File 与 Jobs 生产者授权；模型/连接配置、跨业务引用复制和资料包合并按对应步骤细化。解析效果、模型实连、MES 账号范围和独立发行在对应步骤验证。
- **工程范围。** 业务代码限于拟新增 KnowledgeHub 服务、独立 Host、前端模块及其测试/发行物，具体见每项卡。共享接入点包括解决方案、中央包版本、UnifiedHost 模块目录与迁移协调器、Gateway 注册、RuntimeSupport File/Jobs 生产者和资源/处理器登记及回归测试、权限与菜单种子、前端外壳和路由、两语言资源及独立构建入口。主控开工前核对当前差异，安排唯一写入人。PF-10 监控、ServerOpsCenter、其他 PF 的业务实现和用户私有配置均在本包之外。
- **页面与环境。** 平台沿真实菜单进入，PC 完整管理，Mobile/PDA 验证已承诺的阅读、本人问题与助手范围；独立包从空目录冷安装。用隔离账号、脱敏资料和测试项目，保留用户已有工作树改动、服务及正常调试数据库。
- **完成条件。** KH-01～08、A01～A23、K01～K06 和 §12.1 六个现场场景能对应到实现、实际环境和结果。执行者随功能编写并运行后端、前端及关键端到端测试。先新鲜 Release 构建，再执行相同配置的测试；记录退出码、失败数和未测项。缺真实 MES 时可交付经验证的独立功能，现场接通仍待验收。
- **交付与证据。** 一个工作包连续执行，按 §13.2 共用的提交策略整包交接。实施时写入 `docs/evidence/PF-10A.md`，列出实际文件、可重跑命令、结果和剩余环境依赖。主控负责最终集成；拟用提交说明为 `feat(knowledgehub): implement PF-10A knowledge center`。
