# 1. 文档定位

本文把已确认的平台基础功能、视觉体系、工业合规协作和独立产品路线纳入 `docs/blueprint` 正式维护源。

Identity 完成后暂缓 MasterData、OperationalData 和 MES 生产业务扩张，优先形成可日常使用、可运维、可扩展的平台基础。每个 PF 阶段（含 PF-10A）各使用一个阶段管理会话，根据实施母版、项目记忆和当前代码完成详细设计、任务派遣、跟踪与验收；本文只固定跨阶段边界和不可反向修改的总体决策。

# 2. 建设目标

- 建立可日常管理的平台内置功能，而不只提供登录鉴权。
- 建立适合工业高信息密度场景的 PC、PDA、Mobile 视觉体系。
- 当前默认租户完整可用，同时保留多租户数据和基础设施边界。
- 提供登录用户之间的一对一工业合规聊天、图片和文件传输。
- 提供从聊天发起的合规屏幕共享和现场远程指导。
- 将 Platform Studio、Operations Center、IoT Collector 保持为可独立演进产品，并保持其内部模块边界。
- 初期允许模块合并部署，但领域、契约和数据归属必须可拆分。

# 3. 总体模块边界

## 3.1 平台基础

| 模块 | 权威职责 | 明确不负责 |
| --- | --- | --- |
| Identity | 用户、角色、权限、登录、令牌、会话、SSO | 组织、菜单、聊天内容 |
| SystemData | 行政组织、岗位、菜单导航、功能开关、服务目录、主题默认值 | 制造组织、字典、业务主数据 |
| ReferenceData | 字典、系统参数、元数据、动态属性、编码规则 | 物料、设备、工厂、库存 |
| Audit | 统一接收、追加存储和查询审计事件 | 覆盖或修改业务历史 |
| Workspace Query | 聚合个人工作台只读数据 | 业务写操作和来源数据所有权 |
| Platform Health | 汇总平台服务和依赖健康摘要 | 主机级完整运维监控 |

正式模块名固定为 `SystemData`，不得再使用 `Platform Administration`。

## 3.2 可独立提取的平台模块

| 模块 | 职责 |
| --- | --- |
| File | 上传、隔离、扫描、存储、授权下载、保留和清理 |
| Notification | 公告、系统通知、个人收件箱、已读状态和投递策略 |
| Collaboration | 登录用户一对一聊天、离线补拉和消息状态 |
| RemoteAssistance | 屏幕共享会话、邀请、参与人授权、审计和 WebRTC 引擎适配 |
| Scheduler | 任务定义、执行、互斥、重试、历史和人工触发 |
| Realtime | SignalR 连接治理、用户连接映射、推送和多实例背板 |

## 3.3 独立产品与 Service Host

- Low Code：数据模型、表单、列表、页面编排和发布治理。
- Dashboard & Report：数据源、数据集、指标、看板、报表和导出。
- Operations Center：实施项目工作区、知识库、问题跟踪、知识/数据助手、模型网关和 ServerMonitor；ServerMonitor 只是其内部模块。
- IoT Collector：协议驱动、点位、采集任务、边缘缓存和断线续传。
- MasterData 与 MES：平台基础稳定后恢复开发。

# 4. 租户与组织模型

## 4.1 单租户可用、多租户预留

- 当前只启用一个默认租户，不提供租户选择和运营页面。
- 所有租户数据携带 `TenantNId`。
- 唯一索引、缓存键、对象存储路径、消息主题和审计查询包含租户维度。
- 租户来自可信身份上下文，客户端不得任意覆盖。
- 后续启用多租户时补充生命周期、配额和隔离策略，不修改既有领域主键。

## 4.2 行政组织与制造组织分开

- SystemData 管理公司、部门、科室、班组、岗位和用户任职关系。
- MasterData 管理工厂、车间、产线、工作中心和生产资源位置。
- 两者使用显式关联对象映射，不共用同一棵树，不按名称隐式匹配。
- 行政组织调整不得自动改变制造结构。

# 5. 信息架构

## 5.1 PC

一级导航按下列分组组织：

- 平台治理：Identity 入口、SystemData、ReferenceData。
- 平台服务：File、Notification、Collaboration、RemoteAssistance、Scheduler。
- 运行治理：Audit、错误日志、在线会话、服务目录、Platform Health。

全局顶部区域包含搜索、主题、通知、聊天和用户入口。工作台固定，PC 最多打开 12 个业务标签。

## 5.2 PDA 与 Mobile

PDA/Mobile 不复制完整后台，只提供工作台、通知、聊天、个人中心、被授权现场入口和远程协助观看。PC 是远程协助主要共享端。

## 5.3 工作台

Workspace Query 聚合待办与通知、未读聊天、最近访问、快捷入口、平台健康摘要和用户可见告警。工作台只显示真实数据或明确空状态，不使用装饰性假 KPI。

# 6. 视觉与主题体系

视觉方向为“明亮管理界面 + 工业控制强调”：

- 全宽青蓝品牌顶栏；
- 窄图标工具轨和浅色功能树；
- 平整白色内容画布；
- 低圆角、细分隔线和高信息密度；
- 管理页面优先树、表格、表单和抽屉，减少大面积互联网卡片。

首期内置工业青、科技蓝、中性灰，每套支持明亮、暗色、跟随系统。工业青固定为：

```text
渐变起点  #55a0b9
主色      #0077a1
悬停      #006b91
激活      #006487
```

渐变只用于 Logo、顶栏、选中导航、登录品牌区、工作台主视觉和大屏标题。状态色独立于品牌主题。

- PC 支持舒适和紧凑密度。
- PDA 触控目标不小于 48px，Mobile 不小于 44px。
- Vue 挂载前恢复主题，组件只使用语义令牌。
- 支持焦点、键盘操作、对比度和减少动态效果偏好。

# 7. 平台内置能力

## 7.1 SystemData

- 行政组织和岗位；
- 用户任职关系；
- 菜单、路由、按钮资源和终端可见性；
- 功能开关；
- 服务目录；
- 租户默认主题和用户可选范围。

菜单控制导航，权限控制资源访问，两者通过稳定资源标识关联。

## 7.2 ReferenceData

- 字典类型和字典项；
- 系统参数及作用域；
- 元数据和动态属性；
- 编码规则和取号策略。

ReferenceData 继续使用现有服务骨架和重编号后的实施文档 06，但进入开发前必须在 PF-03 阶段管理会话复核其与本蓝图、SystemData 和主题体系的契约。

## 7.3 File、Notification、Audit

- File：上传后先隔离、校验和扫描，业务模块只保存 `FileNId`。
- Notification：系统到用户的单向公告、提醒和收件箱，不承担用户对话。
- Audit：追加型合规事实源，高风险查看行为本身也产生审计。

文件扫描不可用时文件留在隔离区，文字聊天和其他业务不得因此整体不可用。

## 7.4 Scheduler 与 Platform Health

Scheduler 管理任务运行，不包含任务所属模块的业务规则。Platform Health 只汇总平台服务和依赖状态，主机、进程、磁盘和日志告警进入 Operations Center 的 ServerMonitor 模块。

# 8. 工业合规协作

## 8.1 Collaboration

首期只提供登录用户一对一聊天：文本、图片、文件、在线状态、未读、已读游标、离线补拉、撤回墓碑和个人隐藏。

- REST 负责命令和查询，SignalR 负责实时推送。
- `ClientMessageNId` 保证发送幂等。
- 消息和 Outbox 同事务提交。
- 多实例部署时才启用 Redis 背板。
- 图片和文件必须通过 File 隔离和扫描。
- 默认单文件上限 50MB。
- 首期允许 PNG、JPEG、WebP、PDF、TXT、CSV、DOCX、XLSX。
- 阻止脚本、可执行文件、宏文档和压缩包。
- 消息和附件默认保留 365 天，合规访问审计保留 3 年，法律保全优先。

首期不做群聊、语音、视频会议、外部联系人、机器人、链接预览和任意 HTML。

## 8.2 RemoteAssistance

RemoteAssistance 从一对一聊天发起，但拥有独立会话、权限和审计边界。

- 一名共享者，一至三名观看者。
- 平台邀请、参与人白名单、一次性短期凭证和超时关闭。
- 浏览器原生授权后共享屏幕、窗口或标签页。
- PC 主要共享，PDA/Mobile 主要观看。
- 不录屏、不保存画面、不做远程鼠标键盘控制。
- 审计只记录人员、原因、时间、终端、IP、范围、中继和异常等元数据。

Screego 只作为独立验证底座或可替换 WebRTC 引擎，不把源码合并到平台闭源模块。生产接入必须补充平台 Identity、一次性凭证和参与人授权，并单独完成 GPL-3.0 许可评审。

首期采用“流程嵌入、页面独立”：聊天显示邀请卡片，接受后打开平台独立路由或安全新窗口，不把跨域 iframe 作为唯一实现。

# 9. 后续独立模块边界

## 9.1 Low Code

首期包括数据模型、表单、列表、页面编排、字典和编码规则绑定、权限绑定、三端适配、草稿、发布、版本和回滚。设计态、发布快照和运行数据分开；禁止任意 SQL、任意脚本和绕过应用权限。

复杂工作流、规则引擎和插件市场后移。

## 9.2 Dashboard & Report

- Low Code 负责业务录入和管理页面。
- Dashboard 负责交互指标和大屏。
- Report 负责固定版式、参数、导出和定时生成。

三者可共享数据源和数据集契约，但分别建模。长时间报表进入后台任务，结果交给 File，完成后由 Notification 通知。

## 9.3 Operations Center 与 IoT Collector

Operations Center 的 ServerMonitor 模块观察平台和 IT 运行状态，由 PF-10 单独处理；IoT Collector 获取工业设备数据。两者可以共享日志、指标和告警基础设施，但不共享领域模型。Operations Center 的 ProjectWorkspace、KnowledgeBase、IssueTracking、KnowledgeAssistant、DataAssistant 与 ModelGateway 进入 PF-10A，其边界以蓝图 32 为准；IssueTracking 与 KnowledgeBase 完整数据闭环仍为设计待确认，不得按既有原则摘要直接开发。

# 10. 跨模块约束

当前七个核心 Service Host 及其内部模块清单以蓝图 32 为准。阶段不等于微服务，共用宿主只代表部署合并。

- 模块拥有自己的领域对象、应用用例、公开契约、数据表和迁移。
- 同宿主模块使用独立 Schema 或表前缀、独立权限资源和独立测试。
- 模块不得直接读取或写入其他模块数据表。
- 跨模块状态使用公开 API、事件和 Outbox/Inbox。
- API、SignalR 和后台任务都从可信身份上下文获取租户和主体。
- 权限使用稳定资源标识，不以菜单文字判断。
- HTTP、SignalR、任务和消息消费使用统一错误分类和 TraceId。
- 健康检查区分存活、就绪和依赖降级。
- 每个模块提供请求量、错误率、延迟、积压和关键资源指标。

# 11. 开发治理

正式执行顺序不再由实施文档文件编号决定，统一由 `09-Industrial Platform开发总TodoList.md` 的 PF/MES 阶段编号决定。

每个阶段必须在唯一的阶段管理会话中完成：

```text
现状核对
→ 需求讨论与方案比较
→ 按 TEMPLATE-开发实施方案.md 编写详细设计
→ 用户确认设计
→ 生成九字段任务卡
→ 派遣实际开发任务
→ 跟踪、验收和回写
```

阶段管理会话不直接开发业务代码；实际编码由它派遣的执行任务完成。未经该会话确认，不得从本文摘要推断字段、API、事件、路由或数据库设计。

# 12. 阶段完成共性标准

- 默认租户可运行且 `TenantNId` 边界完整。
- 权限资源、菜单和功能开关完成注册。
- 关键写操作产生审计事件。
- API/事件契约有版本和契约测试。
- 数据迁移、健康检查、指标和 TraceId 可用。
- 适用页面完成 PC 和对应 PDA/Mobile 路径。
- 三套主题和明暗模式通过视觉检查。
- 单元、集成、契约和关键流程 E2E 通过。
- 部署、运维和结果回写与实现一致。
