# PF-05 R14 Chat Experience Implementation Plan

> **For agentic workers:** Execute inline with test-first cycles. Do not commit, restart the user's services, or send test messages to normal contacts.

**Goal:** Deliver compact, safe conversation summaries and deterministic chat focus, scrolling, menus, and unread convergence across the PC page and quick drawer.

**Architecture:** The Collaboration service returns one batch-projected `lastMessagePreview` per paged summary, filtered by the existing member and personal-visibility rules. The Pinia chat store owns conversation projections and monotonic read cursors; chat surfaces only own DOM focus/scroll state. The PC top bar consumes that shared projection rather than independently paging unread results.

**Spec:** `docs/tasks/active/PF-05-UX-R14.md`

## Global Constraints

- Preserve R13, notifications, user management, and compliance behavior.
- Keep the summary query batch-based; never fetch per-row message history in the browser.
- Never expose hidden, retracted, disposed, compliance, or attachment-sensitive body content in a preview.
- Keep UI changes scoped to Collaboration; do not modify shared `AppDataTable`.

### Task 1: Safe batch conversation previews

**Files:** Contracts, `CollaborationPorts.cs`, `SqlCollaborationRepository.cs`, `CollaborationService.cs`, Collaboration tests.

- [ ] Add a nullable preview DTO containing message identity, sequence, accepted timestamp, type, state, and at most 160 safe text characters.
- [ ] Add one repository batch projection for the current page's conversation IDs and current member. Filter personal visibility in SQL; select only the latest visible message for each conversation.
- [ ] Build previews from that projection: text only when accepted and undisposed; otherwise type/state only. Do not call the per-message compliance projection or return attachment metadata.
- [ ] Write a failing service/repository test proving a hidden latest message falls back to the latest visible message and a retracted message has no text; run it red, then implement and rerun green.
