# PF-05 R6 Reliability and UI Contract Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the nine R6 acceptance findings with durable file events, recoverable inbox consumption, safe RabbitMQ failure handling, authoritative file reconciliation, shared step-up UX, reconnect recovery, localized copy, and scrapeable observability.

**Architecture:** SystemData persists file state transitions and their serialized integration events in one SQL transaction. A dedicated outbox dispatcher publishes only confirmed messages and records retry/dead-letter state; Collaboration claims inbox rows with leases and reconciles from the SystemData authority through the existing embedded or trusted HTTP file port. Frontend high-risk actions use one shared AppFormDrawer promise flow, while the application realtime manager owns cancellable initial retries.

**Tech Stack:** .NET 10, SqlSugar, RabbitMQ.Client 7, ASP.NET Core SignalR, System.Diagnostics.Metrics/ActivitySource, Vue 3, TypeScript, Vitest.

**Spec:** `docs/implementation/details/PF05-前置契约与合规执行补充.md` and R6 acceptance feedback.
