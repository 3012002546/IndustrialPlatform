# Industrial Platform 平台基础功能与独立模块设计

## 1. 背景

Industrial Platform 的系统架构与工程骨架已经建立，Identity 正在实现。Identity 完成后暂缓 MES 业务功能扩张，优先解决两个问题：

1. 基础鉴权完成后，平台仍缺少可供日常管理和协作使用的内置功能。
2. 当前页面视觉、布局和交互不足以支撑工业现场的高密度管理场景。

本设计在现有蓝图和已实现边界基础上，参考以下开源项目的可取之处，但不复制其领域模型或代码结构：

- [tmom](https://gitee.com/thgao/tmom)：参考低代码元数据、表单和页面编排思路。
- [MalusAdmin](https://gitee.com/Pridejoy/MalusAdmin)：参考 PC、PDA、Mobile 多终端视觉和布局。
- [Admin.NET](https://gitee.com/zuohuaijun/Admin.NET)：参考后台系统内置功能覆盖范围。
- [Screego](https://github.com/screego/server)：参考浏览器 WebRTC 屏幕共享和 TURN 部署方式。

参考项目只作为能力与交互样本。Industrial Platform 继续遵循既有 Clean Architecture、DDD、模块边界和可独立提取方向。

## 2. 目标与范围

### 2.1 目标

- Identity 完成后尽快形成可日常使用的平台基础。
- 建立适合工业管理界面的内置主题、布局和组件规范。
- 提供组织、岗位、菜单、字典、参数、文件、通知、审计、调度和平台健康等内置能力。
- 提供受平台身份体系约束的一对一聊天和工业合规远程协助。
- 为低代码、看板、报表、运维监控和 IoT Collector 建立清晰的独立边界与开发顺序。
- 当前单租户可完整运行，同时为后续多租户保留数据、缓存、消息和权限边界。
- 初期允许多个模块合并部署，但代码、契约和数据归属不得形成不可拆分耦合。

### 2.2 不包含

- 本阶段不开发物料、工单、库存、称量、批记录等 MES 业务功能。
- 不在首期建设完整主题设计器。
- 聊天首期不包含群聊、外部联系人、机器人、语音和视频会议。
- 远程协助首期不包含远程鼠标键盘控制、录屏和无人值守接管。
- 低代码首期不建设任意代码执行、万能流程引擎或绕过权限的数据访问。
- Platform Health 不替代完整 Server Monitor。
- IoT Collector 不承担主数据、报表或 MES 业务规则。

## 3. 总体原则

### 3.1 单租户可用，多租户预留

- 系统只启用一个默认租户，用户不需要执行租户选择或租户管理。
- 所有归属于租户的业务数据携带 `TenantNId`。
- 唯一索引、缓存键、对象存储路径、消息主题和审计查询均包含租户维度。
- 服务之间通过身份上下文或公开契约传递租户，不允许由客户端任意指定有效租户。
- 后续开启多租户时补充租户生命周期、配额、隔离策略和平台运营面，不反向修改领域主键。

### 3.2 边界先行、部署可合并

- 每个模块拥有自己的领域对象、应用用例、公开契约和数据表归属。
- 模块之间不得直接读取对方数据表。
- 同步查询使用公开 API 或查询契约，状态传播优先使用领域事件和 Outbox。
- 初期可运行在同一进程、数据库实例、Redis 和消息基础设施中；未来可独立部署而不重写领域逻辑。

### 3.3 真实数据优先

- 工作台和健康摘要只展示已接入的真实数据。
- 尚未实现的数据明确显示空状态或“未配置”，不使用装饰性假 KPI。
- Mock 仅用于开发和自动化测试，并在界面中显式标识。

## 4. 模块架构

### 4.1 平台基础层

| 模块 | 主要职责 | 关键边界 |
| --- | --- | --- |
| Identity | 用户、角色、权限、登录、令牌、会话、SSO | 不承担组织、菜单、聊天内容 |
| SystemData | 行政组织、岗位、菜单导航、功能开关、服务目录、主题默认值 | 正式名称固定为 `SystemData`，不使用 `Platform Administration` |
| ReferenceData | 字典、系统参数、元数据、动态属性、编码规则 | 不等同于 MasterData |
| Audit | 统一接收、追加存储和查询审计事件 | 只追加，不允许业务模块覆盖历史 |
| Workspace Query | 聚合个人工作台所需的只读数据 | 不拥有来源数据，不承载写操作 |
| Platform Health | 汇总平台服务健康和依赖摘要 | 不建设主机级完整监控 |

### 4.2 可独立提取的平台服务

| 模块 | 主要职责 |
| --- | --- |
| File | 文件上传、隔离、扫描、存储、授权下载、保留和清理 |
| Notification | 公告、系统通知、个人收件箱、已读状态和投递策略 |
| Collaboration | 登录用户之间的一对一聊天、消息状态、离线补拉 |
| RemoteAssistance | 屏幕共享会话、邀请、参与人授权、审计和 WebRTC 引擎适配 |
| Scheduler | 定时任务定义、执行记录、重试、互斥和人工触发 |
| Realtime | SignalR 连接治理、用户连接映射、推送和多实例背板 |

### 4.3 后续独立产品

- Low Code：数据模型、表单、列表、页面编排和发布治理。
- Dashboard & Report：数据源、数据集、指标、看板、报表和导出。
- Server Monitor：主机、进程、服务、端口、日志、告警和运维看板。
- IoT Collector：协议驱动、点位、采集任务、边缘缓存和断线续传。
- MasterData 与 MES 业务域：在平台基础稳定后按原蓝图继续实施。

## 5. 组织模型

行政管理组织与制造执行组织分开建模。

### 5.1 SystemData 行政组织

- 行政组织：公司、部门、科室、班组等管理关系。
- 岗位：职位和职责定义，可与用户建立任职关系。
- 用途：身份管理、审批归属、数据权限和通知范围。

### 5.2 MasterData 制造组织

- 工厂、车间、产线、工作中心和资源位置。
- 用途：生产执行、设备归属、工单调度和现场数据范围。

二者通过显式关联对象建立映射，不共享同一棵树，也不通过名称隐式匹配。行政组织调整不得自动改变生产结构。

## 6. 信息架构与终端策略

### 6.1 PC 管理门户

一级导航按“平台治理、平台服务、运行治理”组织：

- 平台治理：用户与权限入口、SystemData、ReferenceData。
- 平台服务：文件、通知、聊天、远程协助、调度。
- 运行治理：审计、错误日志、在线会话、服务目录、平台健康。

全局顶部区域包含搜索、主题、通知、聊天和用户入口。PC 使用受控多标签页：工作台固定，最多打开 12 个业务标签，超限时要求关闭或替换旧标签。

### 6.2 PDA 与 Mobile

PDA 和 Mobile 不复制完整后台，只提供：

- 工作台；
- 通知；
- 聊天；
- 个人中心；
- 被授权的现场业务入口；
- 远程协助观看入口。

PC 是远程协助主要共享端，PDA/Mobile 首期以观看为主。终端路由可由自动识别给出默认值，同时保留调试和人工覆盖入口。

### 6.3 工作台

工作台通过 Workspace Query 聚合：

- 待办与通知；
- 未读聊天；
- 最近访问；
- 已授权快捷入口；
- 平台健康摘要；
- 用户可见的调度异常或服务告警。

工作台不直接修改来源数据，卡片点击后进入所属模块完成操作。

## 7. 视觉与主题系统

### 7.1 视觉方向

采用“明亮管理界面 + 工业控制强调”的方向：

- 全宽青蓝品牌顶栏；
- 窄图标工具轨与浅色功能树；
- 平整白色内容画布；
- 低圆角、细分隔线和较高信息密度；
- 管理页面优先使用树、表格、表单和抽屉，减少互联网仪表盘式大卡片。

### 7.2 内置主题

首期提供工业青、科技蓝、中性灰三套内置主题，每套支持明亮、暗色、跟随系统。

工业青色板固定为：

```text
渐变起点  #55a0b9
主色      #0077a1
悬停      #006b91
激活      #006487
```

渐变只用于 Logo、顶栏、选中导航、登录品牌区、工作台主视觉和大屏标题。普通按钮、表格和表单使用单色语义令牌。

成功、警告、危险、信息等状态颜色独立于品牌主题，不能被品牌色替代。

### 7.3 密度和可访问性

- PC 支持舒适、紧凑两种密度。
- PDA 触控目标不小于 48px，Mobile 不小于 44px，不随紧凑模式继续缩小。
- Vue 挂载前恢复主题，避免首屏闪烁。
- 所有组件只引用语义令牌，不直接散落品牌色值。
- 支持清晰焦点、键盘操作、对比度检查和减少动态效果偏好。

## 8. 平台内置功能设计

### 8.1 SystemData

- 行政组织及层级维护；
- 岗位及用户任职关系；
- 菜单、路由、按钮资源和终端可见性；
- 功能开关及环境覆盖；
- 服务目录、所有者、入口和健康地址；
- 租户默认主题与用户可选范围。

菜单不直接等同于权限。菜单控制导航展示，权限控制资源访问，两者通过资源标识关联。

### 8.2 ReferenceData

- 字典类型与字典项；
- 系统参数及作用域；
- 元数据与动态属性；
- 编码规则和取号策略。

敏感参数只保存密钥引用或加密值，普通查询 API 不返回明文。

### 8.3 File

文件生命周期为：上传会话、隔离、校验、扫描、可用、冻结、过期、清理。

- 客户端不直接声明文件可信。
- 文件扩展名、MIME、魔数和大小必须一致校验。
- 扫描服务不可用时，文件停留在隔离区；文字聊天和其他业务不因此中断。
- 所有下载都经过业务授权或短期签名，不公开永久对象地址。
- 文件元数据归 File，业务模块只保存 `FileNId` 和用途关系。

### 8.4 Notification

Notification 负责系统到用户的单向信息：公告、任务提醒、服务异常和业务通知。支持目标范围、发布时间、失效时间、优先级、已读状态和跳转目标。

Notification 不承担用户对话，用户回复必须进入 Collaboration 或所属业务模块。

### 8.5 Audit

审计事件至少包含租户、操作者、主体类型、主体标识、动作、时间、来源终端、IP、TraceId、结果和必要的差异摘要。

- 审计写入失败不得静默忽略。
- 合规型操作采用可靠事件或 Outbox，允许业务事务后补投，但必须可监控。
- 审计查询权限独立于普通日志查询权限。
- 查看聊天合规副本必须填写原因并产生新的审计事件。

### 8.6 Scheduler 与 Platform Health

Scheduler 管理任务定义、Cron、启停、互斥、超时、重试、执行历史和人工触发。任务处理器由所属模块实现，Scheduler 不包含业务规则。

Platform Health 汇总 API、数据库、缓存、消息、文件扫描和实时连接等平台依赖状态，只提供服务级摘要。主机、进程、磁盘和日志告警进入 Server Monitor。

## 9. 工业合规聊天

### 9.1 首期范围

- 登录用户之间一对一聊天；
- 在线状态与最后活动提示；
- 文本、图片和文件；
- 未读计数、已读游标、离线补拉；
- 发送中、已发送、失败和重试状态；
- 撤回墓碑和个人隐藏；
- PC 快捷抽屉与完整页；
- PDA/Mobile 全屏聊天页。

首期不包含群聊、语音、视频、外部联系人、机器人、链接预览、任意 HTML 和端到端加密密钥托管。

### 9.2 消息与实时传输

- REST API 负责发送命令、历史查询和状态变更。
- SignalR 只负责实时推送，不作为唯一事实来源。
- 每次发送包含 `ClientMessageNId`，服务端通过租户、发送人和客户端标识保证幂等。
- 消息持久化和 Outbox 在同一事务完成，SignalR 推送失败可重投。
- 离线恢复使用单调游标，不依赖客户端时间戳判断遗漏。
- 多实例部署时才启用 Redis 背板。

### 9.3 附件和合规策略

- 首期允许 PNG、JPEG、WebP、PDF、TXT、CSV、DOCX、XLSX。
- 默认单文件上限 50MB，可由租户策略收紧。
- 阻止脚本、可执行文件、宏文档和压缩包。
- 附件先进入 File 隔离区，通过扫描后才能绑定到可下载消息。
- 外部图片不自动加载，外部 URL 点击前提示。
- 消息和附件默认保留 365 天，合规访问审计保留 3 年；法律保全覆盖自动清理。
- 用户删除只对本人隐藏；撤回保留墓碑；合规副本按权限继续保留。

## 10. 远程协助

### 10.1 定位

远程协助用于现场终端通信受限时，在平台聊天基础上进行实时屏幕指导。产品能力是屏幕共享和协同说明，不是无人值守远程控制。

RemoteAssistance 是独立模块，依赖 Identity、Collaboration、Audit 和 Realtime 的公开契约。聊天只提供发起入口和会话卡片，不拥有 WebRTC 房间。

### 10.2 用户流程

1. 用户在一对一聊天中选择“发起屏幕协助”。
2. 选择共享人、观看人、协助原因、有效时间和是否允许增加观看人。
3. 对方收到平台邀请并显式接受。
4. RemoteAssistance 创建会话、参与人白名单和一次性短期凭证。
5. 用户进入平台远程协助页，由浏览器原生界面选择屏幕、窗口或标签页。
6. 共享期间继续使用聊天发送文字、截图和文件。
7. 用户结束、所有参与人离开、房主离开、超时或管理员终止时关闭会话。

### 10.3 首期约束

- 一名共享者，一至三名观看者。
- PC 为主要共享端，PDA/Mobile 主要观看。
- 不自动开始捕获，必须由用户触发浏览器授权。
- 不录屏，不保存画面内容，只记录会话元数据。
- 不做远程鼠标键盘控制。
- 不允许裸房间链接绕过平台身份和参与人校验。
- 房间标识不可枚举，一次性凭证短期有效。
- 管理员可按专用权限立即终止会话。

会话审计记录发起人、共享人、观看人、原因、开始结束时间、终端、IP、工厂或车间范围、加入退出事件、中继方式和异常结果。

### 10.4 Screego 使用策略

Screego 只作为独立部署的验证底座或可替换 WebRTC 引擎，不把其源码合并到平台闭源模块。

推荐顺序：

1. 独立部署原版 Screego，验证网络、画质、延迟和浏览器兼容性。
2. 通过反向代理接入试点环境，由平台管理入口、邀请和审计。
3. 根据试点结果选择维护独立 GPL 适配版本，或自研轻量信令服务并使用成熟 TURN。

Screego 当前用户文件和 Cookie 登录不能直接满足平台 Identity、一次性凭证和参与人白名单要求，生产接入必须增加网关或受控适配层。其 GPL-3.0 许可要求修改和交付时单独完成许可证评审和源码义务。

### 10.5 页面和网络部署

第一阶段采用“流程嵌入、页面独立”：聊天中显示邀请卡片，接受后打开平台独立路由或安全新窗口。暂不以跨域 iframe 作为唯一实现，避免屏幕捕获权限、全屏、焦点、Cookie、WebSocket 和兼容性风险。

部署关系：

```text
浏览器
  │ HTTPS / WebSocket
  ▼
平台反向代理
  ├─ Platform API
  └─ Remote Assistance Gateway
       ├─ Screego 或自研信令
       └─ 内置或独立 TURN
```

纯内网部署需要内部 DNS、受信任 HTTPS 证书、WebSocket 和 TURN 网络策略。验证必须覆盖同网段、跨 VLAN、无互联网、UDP 受限、强制 TURN、VPN、双网卡和代理环境。

## 11. 低代码设计边界

Low Code 首期只建设可治理的页面生产能力：

- 数据模型设计器；
- 表单设计器；
- 列表设计器；
- 页面编排；
- 字典、编码规则和动态属性绑定；
- 权限资源和数据范围绑定；
- PC、PDA、Mobile 适配；
- 草稿、校验、发布、版本、回滚和停用；
- 发布后生成菜单和权限资源。

设计态模型、发布态快照和运行数据分开存储。运行时只读取不可变发布快照，不直接执行设计器草稿。

低代码不得直接修改正式领域模型和数据库表，不允许任意 SQL、脚本或绕过应用权限。需要访问既有模块数据时使用注册的数据服务契约。

工作流设计器、复杂规则引擎和插件市场放到后续阶段。

## 12. 看板与报表

Dashboard & Report 与 Low Code 可以共享数据源和数据集契约，但分别建模：

- Low Code 负责业务录入和管理页面。
- Dashboard 负责交互式指标展示和大屏运行。
- Report 负责固定版式、参数查询、导出和定时生成。

主要能力包括数据源、查询模型、数据集、指标、维度、图表、看板编排、报表模板、Excel/PDF 导出、定时生成和通知。

数据访问必须经过已注册连接和权限检查，禁止前端提交任意查询直接访问生产数据库。长时间报表进入后台任务，结果交由 File 保存并由 Notification 通知用户。

## 13. Server Monitor 与 IoT Collector

### 13.1 Server Monitor

- 主机、CPU、内存、磁盘和网络；
- 进程、服务和端口；
- 日志采集、告警规则和通知；
- 平台服务与基础设施监控；
- 运维看板和处置记录。

### 13.2 IoT Collector

- 驱动和协议适配；
- 设备连接与点位建模；
- 采集任务和调度；
- 边缘缓存、断线续传和幂等写入；
- 数据质量、连接状态和采集监控。

Server Monitor 观察系统运行，IoT Collector 获取工业设备数据。两者可共享日志、指标和告警基础设施，但不共享领域模型。

## 14. 跨模块技术约束

### 14.1 身份与授权

- API 和实时连接都必须从 Identity 验证身份和租户。
- 权限采用稳定资源标识，不以菜单名称作为权限判断。
- 后台作业使用服务身份，保留原始请求人和触发来源。
- 合规查看、强制下线、终止远程协助等高风险动作使用专用权限。

### 14.2 数据与事件

- 每个模块拥有自己的表和迁移。
- 跨模块写入通过应用命令或事件，不使用共享仓储。
- 可靠异步通知采用 Outbox/Inbox 和幂等消费者。
- 公共事件包含版本号，新增字段保持向后兼容。
- Workspace Query 和 Platform Health 是只读聚合，不成为事实来源。

### 14.3 错误和可观测性

- HTTP、SignalR、后台任务和消息消费使用统一错误分类与 TraceId。
- 健康检查区分存活、就绪和依赖降级。
- 每个模块提供请求量、错误率、延迟、积压量和关键资源使用指标。
- 文件扫描不可用、SignalR 推送失败、TURN 不可达等可降级场景必须明确展示状态，不得伪装成功。

## 15. 开发分期

### Phase 0：Identity 完成

完成用户、角色、权限、登录、令牌、会话和现有前端登录闭环。Identity 未达到既定验收前，不并行扩张 MES 业务功能。

### Phase 1：平台外壳与视觉体系

- 三套内置主题和明暗模式；
- PC/PDA/Mobile 布局；
- 顶栏、工具轨、功能树、内容区和受控多标签；
- 统一表格、树、表单、抽屉和状态组件；
- Identity 页面接入新外壳；
- 工作台真实数据骨架。

### Phase 2：平台内置功能

- SystemData；
- ReferenceData；
- File；
- Notification；
- Audit；
- 在线会话和错误日志。

### Phase 3：工业合规协作

- 一对一聊天；
- 图片和文件；
- 离线补拉和实时推送；
- 保留、撤回、隐藏和合规查看；
- Screego 网络与终端验证；
- 验证通过后接入 RemoteAssistance 试点。

远程协助验证失败不阻塞文字聊天上线，功能开关保持关闭。

### Phase 4：运行治理

- Scheduler；
- 服务目录；
- Platform Health；
- 平台级任务异常和服务状态通知。

### Phase 5：Low Code

交付模型、表单、列表、页面、权限、发布和版本治理，不包含复杂工作流。

### Phase 6：Dashboard & Report

交付数据集、看板、报表、导出和定时生成。

### Phase 7：Server Monitor 与 IoT Collector

分别实施运维监控和工业采集，完成后再按蓝图恢复 MasterData 和 MES 业务域开发。

总体顺序：

```text
Identity
→ 视觉外壳
→ SystemData / ReferenceData
→ File / Notification / Audit
→ Collaboration
→ RemoteAssistance 验证与试点
→ Scheduler / Platform Health
→ Low Code
→ Dashboard & Report
→ Server Monitor
→ IoT Collector
```

## 16. 阶段完成标准

每个正式模块交付必须同时满足：

- 默认租户可运行且 `TenantNId` 边界完整；
- 权限资源和菜单注册完成；
- 关键写操作产生审计事件；
- API 或事件契约有版本和契约测试；
- 数据迁移可重复执行并可在测试环境回滚；
- 健康检查和基础监控指标可用；
- 错误返回 TraceId，降级状态可见；
- PC 页面完成，适用能力提供 PDA/Mobile 页面；
- 工业青、科技蓝、中性灰及明暗模式通过视觉检查；
- 单元、集成和关键流程 E2E 测试通过；
- 功能开关支持安全关闭未完成或现场不适用能力；
- 文档、部署配置和运维说明与实际实现一致。

RemoteAssistance 进入生产前还必须完成：

- 同网段、跨 VLAN、无互联网和强制 TURN 验证；
- Edge、Chrome 和现场浏览器验证；
- 1080p 文字可读性、连续 30 分钟共享和断线恢复验证；
- CPU、内存、带宽和并发上限记录；
- 一次性凭证、参与人白名单和终止权限安全测试；
- Screego 或其他引擎的许可证评审。

## 17. 已确认决策

- 优先建设可日常使用的平台基础，不继续抢跑 MES 业务功能。
- 当前单租户可用，多租户预留。
- 行政组织与制造组织分开建模。
- 模块采用分层平台基础和可提取独立服务。
- `Platform Administration` 正式更名为 `SystemData`。
- 视觉采用明亮管理界面与工业控制强调，内置主题可选。
- 工业青使用 `#55a0b9 → #0077a1 → #006b91 → #006487`。
- 聊天采用工业合规模式，支持图片和文件。
- 通知与聊天分离。
- 远程协助纳入方案，从聊天发起；首期只做屏幕共享，不做远程控制和录屏。
- Screego 用于独立验证或可替换引擎，不直接复制合并到平台源码。
- Low Code、Dashboard & Report、Server Monitor、IoT Collector 分别保持独立边界。
