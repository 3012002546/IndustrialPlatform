# 文档治理与开发任务派遣设计

## 目标

将 `IndustrialPlatform/docs` 确立为 Industrial Platform 蓝图、实施方案与开发 TODO 的唯一维护源，统一时间类型规范，并明确当前协作任务只负责设计和任务派遣，不直接承担代码开发。

## 文档边界

- `docs/blueprint`：维护架构、领域、数据库、API、协作规范和阶段路线。
- `docs/implementation`：把已确认的蓝图拆成可派遣、可验收的开发 TODO，并回写任务状态。
- 外层 `个人MES平台开发设计` 与 `开发实施` 不再维护，确认仓库副本存在后删除。
- `CLAUDE.md` 属于其他开发任务的独立记忆，本次不读取其约定、不修改其内容，也不以其作为当前协作任务的范围依据。

## 时间类型规范

- .NET 领域模型、DTO、事件、命令和查询中的时间值统一使用 `DateTimeOffset`；可空时间使用 `DateTimeOffset?`。
- 获取 UTC 当前时间统一使用 `DateTimeOffset.UtcNow`。
- API 使用包含 `Z` 或明确偏移量的 ISO 8601 / RFC 3339 时间字符串。
- PostgreSQL 持久化统一使用 `timestamp with time zone`（`timestamptz`），保存 UTC 瞬时时间；展示时再按用户、工厂或设备时区转换。
- 禁止在新增设计和 TODO 中把 `DateTime` 用作业务时间类型。

## 当前协作模式

当前任务只执行以下工作：

1. 维护和校验蓝图设计。
2. 将蓝图拆成开发 TODO，明确输入、修改范围、输出、验证方式和依赖。
3. 选择可执行任务并派遣到其他开发任务，或由用户在其他任务中执行。
4. 接收开发任务返回的实现结果、验证证据和决策，再更新 TODO 状态与必要的蓝图记录。

当前任务默认不修改业务代码、不运行具体功能开发流程，也不把实施方案中的代码示例视为已授权执行。只有用户明确改变当前任务范围时，才进入实际开发。

## TODO 生命周期

开发 TODO 使用以下状态：`待细化 → 可派遣 → 已派遣 → 开发中 → 待验收 → 已完成`。如果实现发现设计冲突，则标记为 `设计待确认`，先回到当前任务修订蓝图，再重新派遣。

每个可派遣 TODO 至少包含：任务编号、目标、输入文档、依赖、允许修改范围、预期输出、验证命令或验收证据，以及结果回写位置。

## 一致性验收

- `docs` 中除“禁止使用 `DateTime`”等规范性说明外，不再出现将 `DateTime` 声明为类型的 C# 示例。
- 蓝图索引与实施索引都声明唯一维护源、时间规范和协作边界。
- Codex 协作规范与 MVP TodoList 使用同一派遣流程和 TODO 字段。
- 外层两份重复资料目录已删除，仓库内文档保留。
