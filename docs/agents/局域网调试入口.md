# 局域网访问本机调试

本机VS继续启动现有UnifiedHost（默认localhost:5041，仍使用唯一Development local配置和云Docker依赖）。媒体调试使用下文的HTTPS入口。仅需HTTP页面联调时，前端启动命令为（即使已有证书配置也保持HTTP）：

```powershell
Set-Location -LiteralPath 'D:\Code\Industrial Platform\IndustrialPlatform\src\frontend'
pnpm dev:lan
```

其他电脑打开 `http://<调试机局域网IPv4>:5173`。Vite启动时会打印Network地址；不是对端自己的localhost，也不是云Docker数据库地址。现有5173被占用时命令会明确失败，不自动漂移端口；由调试者切换自己的前端启动方式，本功能不会结束正在运行的VS/Vite。

LAN模式使用 `.env.lan` 的 `VITE_API_BASE_URL=/_backend`，浏览器按当前页面Origin解析；HTTP与SignalR（含WebSocket升级）经同一前端代理转发至本机后端，再去掉 `/_backend`。UnifiedHost无需向网卡开放5041或放宽CORS。普通 `pnpm dev` 和生产构建保持原有入口配置。

如本地后端不是5041，在忽略版本控制的 `.env.lan.local` 设置 `DEV_API_PROXY_TARGET`，值是Vite所在调试机可访问的后端入口。不要把VITE_API_BASE_URL改回localhost或远端访问者无法连接的地址。生产部署不能依赖Vite开发代理。

## 已提供的HTTPS调试入口

下面命令可从任意工作目录执行，路径包含空格，复制时保留引号。使用PowerShell 7.5及以上（`pwsh`）。本机当前证书已生成并迁移到新目录，日常调试直接执行后面的“启动前端”，无需每次生成。首次配置、证书续期或更换IP时才运行（本次IP为10.13.49.141，更换地址时替换参数）：

```powershell
pwsh -NoProfile -File 'D:\Code\Industrial Platform\IndustrialPlatform\tools\setup-lan-https.ps1' -IpAddress '10.13.49.141'
```

脚本使用.NET证书API，无需安装openssl或mkcert；生成90天服务器证书，SAN包含指定IP、localhost和回环地址。重复运行复用原开发CA，更新服务器证书；已有其他证书配置时停止，避免覆盖。证书集中存放在源码仓库旁的 `D:\Code\Industrial Platform\开发辅助文件\HTTPS证书\`：`导出`只放可复制到手机的CA公钥；`私钥`存放服务器与CA文件，访问限制为当前Windows用户和SYSTEM。两者均在源码仓库和前端root之外；只更新 `.env.lan.local` 的两个证书路径，保留原代理配置。CA到期前需显式安排更换和设备重新信任。

首次使用还需信任证书：

- Windows：明确允许安装开发CA后，使用下面带 `-TrustCurrentUser` 的完整命令。它会复用已有CA、更新服务器证书，并把专用CA公钥加入**当前用户**的受信根证书库，不修改机器级信任；上面不带参数的命令不会安装。两条生成命令按需选择，不必连续执行。调试结束不再需要时，可在当前用户证书管理器按脚本输出的指纹移除对应CA。
- 手机：仅复制 `D:\Code\Industrial Platform\开发辅助文件\HTTPS证书\导出\industrial-platform-lan-ca.cer` 到手机。在系统设置中搜索“安装证书”或“CA证书”，选择该文件并核对脚本输出的SHA256指纹；具体菜单随Android/厂商版本不同。不要复制 `私钥`目录。安装会让该手机信任此开发CA，结束调试后可以移除。
- 仅跳过浏览器证书警告不算完成信任；Windows与手机必须分别信任。真实设备信任尚未安装或验证时，不宣称媒体可用。

允许安装当前Windows用户信任后执行（此处是命令说明，不代表已经安装）：

```powershell
pwsh -NoProfile -File 'D:\Code\Industrial Platform\IndustrialPlatform\tools\setup-lan-https.ps1' -IpAddress '10.13.49.141' -TrustCurrentUser
```

打开手机证书导出目录：

```powershell
Invoke-Item -LiteralPath 'D:\Code\Industrial Platform\开发辅助文件\HTTPS证书\导出'
```

### 启动前端（日常调试）

先在VS启动现有UnifiedHost后端，然后在VS Code终端执行：

```powershell
Set-Location -LiteralPath 'D:\Code\Industrial Platform\IndustrialPlatform\src\frontend'
pnpm dev:lan:https
```

此命令复用LAN同源代理和 `.env.lan.local`，证书缺失时明确失败，不退回HTTP。本机打开 `https://localhost:5173`，手机打开 `https://10.13.49.141:5173/mobile`。已有前端占用5173时，由调试者停止自己的旧前端并重新选择HTTPS入口；脚本不会停止进程或换端口。后端仍用现有VS/云Docker配置。

配置已同时对齐Vite代理和浏览器环境变量。登录请求应为 `https://<前端地址>:5173/_backend/identity/api/v1/auth/login`；如果仍显示 `http://localhost:5041/identity/api/v1/auth/login`，说明页面尚未加载当前LAN配置。更新vite.config.ts后，在前端终端停止旧进程、重新执行上述HTTPS命令，再刷新页面；后端可继续运行。

### VS Code操作

用VS Code打开前端文件夹（`code`命令已安装时可直接运行）：

```powershell
code 'D:\Code\Industrial Platform\IndustrialPlatform\src\frontend'
```

在“运行和调试”选择 **局域网 HTTPS：启动 Vite**，按F5；需要浏览器断点时，再启动 **局域网 HTTPS：Chrome 页面调试**。配置位于该前端文件夹的 `.vscode/launch.json`。前者只启动Vite，后者只连接页面；不会启动或停止后端。命令行启动和F5启动Vite二选一；未配置证书信任时，F5不会替用户跳过安全检查。

局域网命令按调试对象选择，均监听0.0.0.0并使用同源API/SignalR代理：

| 命令 | 前端协议 | 后端与认证 |
| --- | --- | --- |
| `pnpm dev:lan` | HTTP | 平台后端，默认5041，沿用平台认证配置 |
| `pnpm dev:lan:https` | HTTPS | 平台后端，默认5041，沿用平台认证配置 |
| `pnpm dev:lan:https:collaboration` | HTTPS | 独立协作宿主，默认56365，自动选择embedded认证 |

独立协作的F5配置为“独立协作 HTTPS：启动 Vite”，同样复用LAN证书。后端启动和固定A演示会话步骤见 `src/frontend/DEPLOYMENT.md`；独立端口可通过 `.env.lan.local` 的 `DEV_COLLABORATION_API_PROXY_TARGET` 覆盖，不影响平台的 `DEV_API_PROXY_TARGET`。专用命令只是调试入口，不代表已有独立裁剪生产包。`pnpm dev`普通开发和生产构建保持原行为。手机语音和观看继续选HTTPS入口，不要同时启动多个5173前端。

## 使用现有企业或域名证书

局域网IP的普通HTTP可用于页面访问，但不能作为麦克风/屏幕捕获验收入口。要测试媒体，在 `.env.lan.local` 设置：

```dotenv
DEV_HTTPS_CERT=C:/path/to/lan-server-cert.pem
DEV_HTTPS_KEY=C:/path/to/lan-server-key.pem
```

证书必须包含实际访问的DNS名称或IP（SAN），并由所有测试电脑及手机信任；已有企业CA或受信域名证书也可直接使用，无需运行生成脚本。私钥仅留调试机，不发给测试电脑或手机、不提交。仅点击跳过证书告警不作为受信媒体测试完成。配置后用 `https://<证书对应名称或IP>:5173`；API/SignalR仍同源，HTTPS由Vite终结后转现有本机HTTP后端。不会自动修改信任库或浏览器安全设置。

### 手机浏览器的能力边界

手机通过 `http://10.13.49.141:5173/mobile` 访问时，调试机的局域网IP不属于浏览器对 `localhost` 的安全上下文例外；换用Chrome也不会解除麦克风的HTTPS要求。该IP仅是本次截图中的调试地址，后续以实际地址和证书SAN为准。

| 功能 | 访问和能力要求 |
| --- | --- |
| 文字聊天 | 不依赖麦克风或屏幕捕获；HTTP开发入口也应能发送。请求标识生成不能无条件调用仅安全上下文支持的 `crypto.randomUUID()` |
| 双向语音 | 手机信任的HTTPS、可用的 `getUserMedia()`、本次麦克风授权及媒体连接 |
| 观看电脑共享 | 接收远端媒体，不要求手机具备本机屏幕捕获API；按HTTPS入口验证实际播放和连接 |
| 共享手机自己的屏幕 | 除HTTPS外还要求本机屏幕捕获支持。MDN兼容数据当前将Chrome Android的 `getDisplayMedia()` 标为不支持；HTTPS不能补齐缺失API，原生容器采集适配属于后续终端阶段 |

先完成可信HTTPS入口再验证语音和观看；不要把“不支持共享手机屏幕”扩大为不支持聊天或语音，也不要用修改路由、换浏览器或禁用浏览器安全限制代替配置HTTPS。

依据：[randomUUID安全上下文要求](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)、[getRandomValues兼容入口](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues)、[安全上下文](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)、[媒体API兼容数据](https://github.com/mdn/browser-compat-data/blob/main/api/MediaDevices.json)。

## 一次性访问检查

1. 本机已登录页面、后端调试正常后，对端打开Network地址；确认API地址以该前端地址加 `/_backend` 开头。
2. 对端若TCP连接失败，检查调试机当前网卡IP、局域网隔离及Windows防火墙。按组织策略只允许测试网段访问5173；不关闭防火墙、不开放数据库或全局所有端口。本次未修改防火墙。
3. 媒体测试确认地址受信且 `window.isSecureContext` 为true，再使用原邀请链；不要因HTTP媒体权限不可用反复返工业务代码。

参考：[Vite监听、代理与HTTPS](https://vite.dev/config/server-options)、[屏幕捕获规范](https://www.w3.org/TR/screen-capture/)。页面可达、媒体可用及跨网TURN分别记录，不互相替代。
