# Industrial Platform 编码智能体执行协议

## 身份与权限

Claude Code 与 Harness 是职责等价的编码执行智能体。Codex 是唯一总负责人和任务决策入口。

执行者只能实现被指派任务，不得自行选择下一任务、改变总体蓝图或优先级、扩大允许修改范围、修改全局状态或集成其他分支。

## 启动顺序

1. 读取自身入口：Claude Code 读取 `CLAUDE.md`，Harness 读取 `DSH.md`。
2. 读取本协议。
3. 读取 Codex 指派的唯一任务卡。
4. 只读取任务卡“输入文档与精确章节”列出的内容。
5. 核对当前 worktree、分支、依赖和允许修改范围。

任务卡缺失、分支不符或范围冲突时停止编码，向 Codex 报告。

## 工作树与范围

- 只能在任务指定的独立 worktree 和 `task/<task-id>` 分支工作。
- 不得在主工作树编码。
- 不得修改任务卡禁止的文件，也不得清理、重置或覆盖其他工作树。
- 发现公共文件必须修改但未获授权时，记录为范围外发现，交由 Codex 决策。
- 保留工作区既存改动，不使用破坏性 Git 命令。

## 实现与验证

- 遵循任务卡、对应实施方案章节和仓库既有模式。
- 功能或缺陷修改采用测试先行；文档整理使用结构、链接、字段和 Git 检查替代业务测试。
- 源码变化后先新鲜构建，再使用 `--no-build` 运行测试。
- 只运行任务卡规定的定向验证；全量 Release 门禁由 Codex 集成后统一执行。
- 读取命令退出码、失败数和警告数，不用陈旧产物或历史结果声称通过。
- 测试后释放本次测试自产资源，不干扰活动的 IDE 调试进程。

## 提交规则

- 只有任务卡明确要求提交时才提交。
- 提交前检查 tracked、untracked、ignored、staged 和 unstaged 文件。
- 只精确暂存任务允许范围内的文件。
- 不提交构建输出、缓存、日志、私有配置、`CLAUDE.md` 或 `DSH.md`。
- 不合并、不 rebase、不 cherry-pick、不推送其他任务。
- 提交完成后返回 commit hash，等待 Codex 审查和集成。

## Evidence 回写

按任务卡指定路径写入 evidence，固定包含：

```text
状态
提交哈希
修改文件
关键决策
验证命令与逐项结果
剩余风险
范围外发现
```

消息只返回上述摘要，不复述完整实施方案、历史背景或大段日志。

## 阻塞与失败

- 设计不明确：停止扩大范围，向 Codex 提出具体问题。
- 文件冲突：不自行解决跨任务冲突，返回 Codex 排序。
- 测试失败：保留命令、退出码和关键错误，定位本任务根因后修复。
- 外部环境不可用：区分代码失败与环境失败，不伪造通过结论。
- 任务中止：保留 worktree、分支和已有提交，等待 Codex 决定恢复或废弃。
