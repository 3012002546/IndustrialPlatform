# Industrial Platform 编码智能体执行协议

## 身份与权限

Claude Code 与 Harness 是职责等价的编码执行智能体。Codex 是唯一总负责人和任务决策入口。

执行者负责被指派的整个 PF 工作包，可按实施方案依赖顺序自行连续执行其中的 `TASK-*`；不得改变总体蓝图、PF 边界、修改全局状态或集成其他分支。

## 启动顺序

1. 读取自身入口：Claude Code 读取 `CLAUDE.md`，Harness 读取 `DSH.md`。
2. 读取本协议。
3. 读取 Codex 指派的唯一 PF 工作包。
4. 按工作包入口读取本 PF 实施方案和当前所需内部任务章节。
5. 核对当前 PF 工作线、worktree、分支、依赖和允许修改范围。

PF 工作包缺失、工作线不符或跨 PF 范围冲突时停止编码，向 Codex 报告。

## 工作树与范围

- 默认只能在 Codex 分配的长期 PF worktree 和分支工作；连续任务复用该工作线，不自行创建任务分支。
- 默认不得在主工作树编码。PF-02 自 2026-09-02 起按用户授权例外使用主工作区 `D:\Code\Industrial Platform\IndustrialPlatform` 的 `develop`，开发与独立验收顺序交接；旧 PF-02 工作树已移除，不重建或重新启用旧工作线，具体边界见当前 PF 工作包。
- 不自行拉取、合并或 rebase `develop`；整个 PF 开始或恢复前由 Codex 负责同步工作线。
- 不得修改 PF 工作包禁止的文件，也不得清理、重置或覆盖其他工作树。
- 发现公共文件必须修改但未获授权时，记录为范围外发现，交由 Codex 决策。
- 保留工作区既存改动，不使用破坏性 Git 命令。

## 实现与内部验证

- 遵循 PF 工作包、对应实施方案和仓库既有模式。
- 按依赖顺序连续完成本 PF 内部任务；内部 `TASK-*` 完成后直接继续下一项，不等待 Codex 派遣、验收或提交。
- 自行完成编码、测试、修复和内部验证，不把常规实现决策逐项退回 Codex。
- 源码变化后自行运行相关构建和测试，确保整个 PF 交付时通过。
- Codex 不重复运行这些测试，只执行最终 Release 编译门禁。
- 读取命令退出码、失败数和警告数，不用陈旧产物或历史结果声称通过。
- 测试后释放本次测试自产资源，不干扰活动的 IDE 调试进程。

## 交付与提交规则

- 执行智能体默认不提交、不暂存；整个 PF 当前范围完成后保留完整未提交改动，交由 Codex 编译和提交。
- 交付前自行检查 tracked、untracked、ignored、staged 和 unstaged 文件，确保改动只在 PF 允许范围。
- 不提交构建输出、缓存、日志、私有配置、`CLAUDE.md` 或 `DSH.md`。
- 不合并、不 rebase、不 cherry-pick、不推送其他任务。
- Codex Release 编译成功后统一暂存、提交并集成；失败则退回本执行智能体继续修复。

## Evidence 回写

整个 PF 使用一份精简 evidence；内部任务只更新进度，不创建新的派遣/验收文档。最终包含：

```text
状态
主要修改范围
验证命令与逐项结果
剩余风险
范围外发现
```

只记录足以交接和定位失败的信息，不复述完整实施方案、历史背景、逐文件清单或大段日志。

## 阻塞与失败

- PF 蓝图不明确：停止扩大范围，向 Codex 提出具体问题。
- 文件冲突：不自行解决跨 PF 冲突，返回 Codex 排序。
- 测试失败：保留命令、退出码和关键错误，定位本任务根因后修复。
- 外部环境不可用：区分代码失败与环境失败，不伪造通过结论。
- PF 工作中止：保留 worktree、分支和已有改动，等待 Codex 决定恢复；不得废弃整条工作线。
