主控应承担本次目标表达、替代方案清理和交接范围收敛责任，不能只要求执行模型“仔细理解”。已有开发/验收任务和模型设置保持，单一生产源码写入者；完成后的直接交接只触发一次验收。

后续部署建议（尚未执行）：云部署稳定后，用两台设备在同网与不同网各跑短链，确认实际候选路径，再集中进行一次30分钟语音＋屏幕测试。同一共享素材包含中文表格/代码、滚动拖动和动态画面，Screego对照保持采集尺寸、浏览器、设备及网络路径一致。必要时每2～5秒采样RTT、丢包、抖动、分辨率/帧率、发送码率及解码帧变化，缺字段记不可用；RTT不冒充端到端画面延迟。先定位网络/CPU/采集约束，再单项调参数，不一开始堆60fps或固定高码率。复用[WebRTC标准统计](https://www.w3.org/TR/webrtc-stats/)与[coturn已有能力](https://github.com/coturn/coturn)，不新增媒体平台或全量录屏。Electron/Capacitor就绪后按实际支持能力补权限、生命周期、设备与三端场景，不能默认容器和浏览器支持一致。

## 1. PF05 的实际教训

| 已发生问题 | 为何到验收才发现 | PF06 对应预防措施 |
| --- | --- | --- |
| 附件授权要求已绑定消息，发消息又要求先授权 | 分别测试方法，没有从真实初始状态走完流程 | 开发自己执行邀请→应用接听→绑定/持续确认→采集授权及轨道接入→协商→实际媒体→分项停止；检查每个前置条件的产生者和时机，不能由fixture提前塞入 |
| 导出bind/release签名action与接收端不一致 | mock只验证调用端自己的预期，没经过实际接收端校验 | 真实HTTP/Hub调用双方一起验证路径、action、字段、身份、requestNId；不得另写一份宽松接收handler充当最终契约证据 |
| 保全释放把状态乐观版本当成冻结案件版本 | 同一“版本”名称下混用了不同含义 | 会话ID、业务并发版本、端点绑定、媒体操作代次、协商代次按现有规格逐个定义用途；旧请求不得作用于新会话 |
| SQLite时间读回成+08，立即批准被判过期 | 内存测试保留正确offset，没有实际落库读回 | 截止时间、租约、邀请超时实际写入/重新读取再比较；SQLite和PostgreSQL分别证明，不以延长期限补偿偏移错误 |
| 导出先Succeeded再审计；重投的occurredOn变化导致冲突 | 只验成功返回，没有验失败/重试后的持久事实 | 按业务分别定义何时可提交终态；PF06停止媒体不能等待中央Audit，先执行停止并持久可靠本地事实，再可靠投递；事实ID和原发生时间重投稳定 |
| 页面、菜单、普通查询反复回归 | 新模块改公共路由/权限/初始化后只验新功能 | 每次公共入口改变执行受影响旧功能回归，尤其用户查询、登录/权限、菜单、文字聊天与未读同步 |
| 扫描最后才发现只有协议替身 | 测试环境与“真实通过”口径未提前登记 | 开工前登记真实浏览器、设备、HTTPS、TURN和网络路径；fake media、协议替身、localhost直连分别标注，不能代表真实媒体/跨网中继 |

PF05最后一轮代码与隔离HTTP业务链已通过，实际ClamAV仍缺环境。PF06没有文件扫描需求时不把该缺项扩张为整个PF06停工，也不能因此把PF05整包标PASS。

用户后续明确：日常开发上传附件也不受ClamAV环境阻塞，真实扫描在合入main前统一验收。仅Development可用的 `SystemData:ClamAv:DevelopmentBypass` 只在统一 `src/backend/appsettings.Development.local.json` 配置一次，当前开启；各宿主不重复配置。扫描明细记录DEVELOPMENT_BYPASS，不作为真实杀毒通过。main前补验必须在同一入口关闭开关并用新上传文件连接真实扫描器；这不推迟PF06现有001/009真实媒体技术验证。具体配置见 `src/开发注意事项-数据库拓扑与本地配置.md` §9。

## 3. 把真实验证前移到开发阶段

本节保留早期验证前移原则。实际已从002连续完成正式实现，不再执行001/009独立PoC前置或扩建样本；后续仅在用户指定部署/终端阶段补验，不改变最终三表、15个Hub方法和共用连接设计。

1. **001＋009先验证技术风险。** 真实两端屏幕/语音、两种加入顺序、权限拒绝、分项停止、TURN路径按现有规格取证；同一个最终三槽/协商样本复用到后续实现。缺少真实设备或TURN，只能确认已测路径，不提前宣称可交付。
2. **生产接入后尽早跑最小纵向链。** 接通已有权限/真实适配器后，开发自己从实际账号/聊天入口执行一条屏幕链；语音接入后立即验证一条语音链和两种能力组合，不能等全部UI完成或独立验收才首次调用真实接收端。
3. **小范围修复立即验证同一失败步骤及上下游。** 例如授权修复后继续到Ready和实际媒体；停止修复后验证资源释放及另一能力仍可用。不要只验证“原错误消失”，然后把下一步留给验收发现。
4. **实现所有可测必需场景后才正式交验。** 环境阻塞场景显式列缺项，开发可交部分结果，但状态必须是部分完成，不能写“全功能完成”。

## 4. PF06 特别容易返工的边界

- **同一媒体宿主。** App级宿主持有媒体生命周期；聊天页/顶栏弹窗只呈现。切路由、收起、切会话不能误断当前通话，不停止文字聊天Hub。
- **共享与语音分别授权和结束。** SYSTEM_ADMIN的PF05免重复密码规则不能扩成自动接听、跳过对方同意或浏览器采集授权。新增能力失败保留已有能力；结束语音保留屏幕，停止屏幕保留语音。
- **实际停止，不只改状态。** 先证实轨道在传输，再按规格观察该音频/视频轨道停止，保留能力继续。UI黑屏、按钮消失、SignalR断线或PeerConnection总字节变化都不能独立证明停止。沿规格既有时限测量，不新增另一套SLA。
- **最少但关键的竞态。** 双方同时发起/协商、多设备抢接、迟到采集成功、旧邀请/旧结束重试、停止时新增能力；使用真实身份与当前授权，不能拿调用者的HttpContext代替对方权限。
- **可靠事实与安全动作分开。** 结束操作不等待中央Audit恢复；停止事实可靠保存与重投稳定。PF05导出“审计后才成功”是敏感下载门禁，不能机械复制为“审计失败不允许停媒体”。
- **UTC与迁移。** 追加Collaboration迁移，不重写PF05已应用checksum。实际provider验证全新库、已有库升级、二次启动和相关旧数据；不删除账本/表或延长租约来消除报错。数据库约定见 `src/开发注意事项-数据库拓扑与本地配置.md`。
- **页面直接复用已验成果。** PDA/Mobile列表→详情、桌面固定聊天弹窗、右键菜单、焦点/滚底/未读同步均为已确认基线，媒体按钮按现有布局增量加入，不重新设计聊天壳。管理页才用用户管理黄金模板，不机械套到通话画面。

## 5. 开发与验收怎样少重复

| 时机 | 谁做什么 | 不重复什么 |
| --- | --- | --- |
| 实现中 | 开发做定向测试与真实最小链；有证据的缺陷自行修正 | 不把独立验收当日常调试器，不逐步要求用户确认 |
| 首次稳定交验 | 开发交稳定manifest、变更摘要和一张实测矩阵；验收独立检查完整约定范围 | 不接受只给“多少测试通过”的交接，也不另建第二套规格 |
| 首轮发现问题 | 验收先汇总可独立检查的阻断并一次交开发；能继续的只读/独立场景继续 | 前置失败导致无法到达的后续步骤记未到达，不能断言没有问题；不能为了找后续问题绕过前置安全校验 |
| 返修 | 开发复现并修根因，跑失败点及影响范围；新快照交验收定向复验 | 无公共契约/权限/数据一致性或新证据风险时，不每轮重跑所有无关项目 |
| 最终 | 验收给有限/整体结论；主控核对范围、证据与限制，更新一个当前状态 | 不再第三次运行相同全套测试，不反复读整份diff |

源码变化必须先fresh Release再使用--no-build测试。模块/公共变更按仓库门禁执行全量；隔离小修先定向，最终稳定交付汇总。构建/测试共用目录顺序执行，不能开发与验收同时写bin/obj或同一测试库。保留隔离样本脚本供接续复验，不保留秘密；优先一个可参数化执行全链的既有harness，避免每修一步另造脚本和测试替身。

同一问题两轮没有新证据才由主控定点介入；发现新的根因不自动换模型。主控只处理范围冲突、真实阻塞和最终结论，开发/验收的常规交接不再经过主控重复转发，避免每个状态通知都启动新一轮任务。

## 6. 一份交付记录就够

复用PF06工作包现有evidence格式，每次稳定交付只维护：

- 快照：HEAD、WIP范围、manifest文件数/逐项hash/aggregate与计算方法；验收期间开发不改该范围。
- 结果：代码已实现 / 开发自测 / 独立验收分别标注；场景期望、实际、环境及证据位置。
- 统计：passed、failed、skipped分别相加；项目复跑/组合汇总与单次solution结果区分，首次失败不擦除。
- 限制：FAIL为已证实缺陷，BLOCKED为无法执行的依赖/权限阻碍，用户明确暂缓另列；修复后的旧失败移到历史，不继续堆在CURRENT。

正常环境只在用户允许的方式下加载新代码；测试实例通过不等于当前调试已加载。保留源码WIP和既有调试，模型设置、部署、提交及PF05暂缓项均不自动扩张。
