# PF-04 再决策门禁

本文件只定义 PF-04 的实施前边界。当前阶段不实现 Audit、File 或 Notification，不安装对应依赖，不创建生产接口，不承诺未来采用某个具体 provider。

## 暂定边界

| 能力 | 暂定责任边界 | 当前阶段允许的输入 |
| --- | --- | --- |
| Audit | 记录谁在什么租户、以什么授权、对哪个资源执行了什么结果；不替业务服务拥有领域状态 | 现有 traceId、用户/租户标识和服务自有业务事件的候选字段 |
| File | 文件元数据、访问授权和生命周期边界；文件内容的存储、扫描和传输策略另行决策 | 现有 API 边界、权限和数据归属约束 |
| Notification | 通知意图、收件人解析、投递结果和重试边界；不把通知当作同步业务成功的替代品 | 现有服务操作结果和用户偏好候选字段 |

这些是待验证的责任边界，不是接口、数据库表或消息主题设计。PF-04 之前的平台工作只保证不会让 Shell、Identity 或 SystemData 偷先拥有这些能力。

## 实施前决策步骤

每一项能力进入实现任务前，按以下顺序完成决策记录：

1. **Build**：只有现有平台 BuildingBlock 无法满足稳定的协议、隔离或生命周期要求时，才设计平台自有最小能力；先写所有权、失败语义和独立验收。
2. **Adopt**：检索成熟方案的协议、升级、许可证、运维和数据边界，确认它能被平台 adapter 包裹；不得因功能列表丰富就整体迁移平台架构。
3. **Wrap**：选定外部能力后，平台只暴露稳定、受控的适配接口，领域服务不依赖 provider 类型；定义替换点、超时、重试、降级和审计责任。
4. **Skip**：若当前真实需求、数据所有权或验收边界不足，明确跳过并保留重新评估条件；不创建空服务、假 API、占位健康状态或未来承诺。

## 决策门禁输出

实施任务必须附带：需求和数据所有权、Build/Adopt/Wrap/Skip 结论、许可证与升级风险、真实依赖可达性、失败与恢复语义、独立启动/健康检查、最小真实路径及回退方案。未完成这些证据时，PF-04 只能保持边界文档，不得进入代码或生产配置。
