# 可部署宿主

`Hosts` 存放可启动、调试和发布的应用入口。业务实现继续放在 `Services`，公共能力放在 `BuildingBlocks`；宿主负责组合模块、选择身份/文件等适配器和装配配置，不复制业务实现。

## 统一约定

- 宿主目录、项目与专用解决方案统一命名为 `IndustrialPlatform.<能力>.<宿主类型>`。例如 `IndustrialPlatform.Collaboration.EmbeddedHost` 表示面向外部系统嵌入的协作宿主；现有平台统一入口 `IndustrialPlatform.UnifiedHost` 保留。
- 每个新增独立宿主目录提供同名 `.csproj`、可直接打开的 `.slnx`、`README.md`、不含秘密的配置模板和调试入口；同时加入后端总解决方案。解决方案不是独立复制的代码包，构建仍引用本仓库的 Services/BuildingBlocks 与根目录公共构建配置。
- 后续低代码、采集、标签等能力需要独立部署时，按同一规则新增宿主；能力尚未实施时不提前创建空项目或复制样板。
- README 说明最短启动方式、固定演示数据与真实接入的区别、用户需替换的适配入口、依赖和发布方式。测试按改动范围执行，目录调整不能改动已通过的业务行为。
- 固定用户演示与 SQLite 数据仅用于明确标识的演示配置；生产身份接线复用现有适配入口。当前数据库范围 PostgreSQL/SQLite；其他数据库按后续工作包接入。

协作宿主已从原 `src/samples/Collaboration.EmbeddedHost` 迁入本目录。历史 evidence 保留当时路径，当前文档和项目引用使用新路径。2026-09-14按用户要求确认旧目录只剩bin/obj/.vs缓存后，已移除整个src/samples目录，不再保留第二入口。

## 前端发布边界

后端宿主独立部署，不代表前端已经独立打包。各能力采用同一代码仓库、共享业务组件，分别提供平台入口和独立入口，不复制前端业务代码。具体的协作发布边界及当前实现状态见[前端发布说明](../../../frontend/DEPLOYMENT.md)。
